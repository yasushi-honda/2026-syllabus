# 学校フォーム作成（GAS + Playwright）の手順と落とし穴

ITパスポート テクノロジー系のGoogleフォーム・回答スプレッドシート・成績ページを、Apps Script（GAS）で作る手順と、実授業で見つかった落とし穴の記録（第1〜4回分）。コード本体は公開リポジトリの外（`~/Projects/学校/forms-gas/`）にある。ここには手順と知見だけを置く。

> 2026-10-28: ハーネス側（`~/.claude/memory/projects/school-forms/gas-workflow.md`）から、案件側へ移した。以降の更新はこのファイルで行う。第5回の知見は `docs/handoff/GOAL.md`（ITパスポート第5回の項）にある。

学校のITパスポート等で使うGoogleフォームは、GASで一括生成し、設定確認だけPlaywright MCPで行う。実績: 2026-09-29「ITパスポート 第1回 診断テスト」(20問・3セクション)。

**手順**
- コードは `~/Projects/学校/forms-gas/code.gs`(+`spec_w01.json`)。**公開サイトになる `2026_syllabus` リポジトリには置かない**(正答が公開されるため)。
- 問題データは元資料(md)から機械的にJSON化し、公式解答例PDFと機械照合してからGASに埋め込む(転記ミス防止)。
- script.google.com/home/projects/create で新規プロジェクト → Monaco に `monaco.editor.getModels()[0].setValue(...)` でコード投入 → SHA-256でローカルと一致確認 → 保存 → 実行。
- **2026-10-14 ユーザー指示「今後はplaywrightやclaspでAIが対応する」**: 学校のGAS作業では、デプロイ（ウェブアプリの公開）・権限承認の画面も AI が Playwright で操作してよい（以前の「権限承認はユーザー本人が押す」を置き換え）。clasp は下記の別組織認証の衝突があるため、使うなら学校用に認証を分けてから。公開範囲は「学校法人 清風明育社 内の全員」（＝i-seifu.jp）を既定にし、それより広げる場合は先に確認する。
- 回答先スプレッドシートは**コース単位で1つ**(`ITパスポート_後期_回答`)。フォームごとにタブが増える。GASは同名ファイルがあれば再利用、無ければ作成。タブ名は英語(Form Responses N)なので「第N回_○○」に改名する。

- 分野別の自動集計: 回答シートに「第N回_正答」「第N回_分野別集計」タブをGASで追加(`addition_section_scores.gs`)。**本番作成の前に `testSectionScoreTabsW01` のダミー3パターン検証(PASS確認)を必ず先に実行**。関数の実行は、ドロップダウンで選択した関数名をスクリーンショットで確認してから押す(誤実行防止)。

- 集計タブの数式は**直接参照（B2など）にしない**。フォームの回答は回答タブに「行の挿入」で追加されるため、回答0件の時に作った `=…!B2` の参照が、回答が増えるたびに下へずれて集計が空になる（2026-09-30の実授業で発生、9件入った時点で `B11` を指していた）。`INDIRECT("'タブ名'!B"&ROW())` で組み立てる。検証テストも「見出しだけで集計を作り、あとから `insertRowsBefore(2, n)` で回答を入れる」形にする（回答を先に入れた状態で作るテストでは検出できない）。
- 質問の追加は既存列を動かさず、回答タブの右端に列が増える。集計側は `Q1.` の列位置が想定どおりか確認してから作る。
- 「1人1回まで」の制限を外す場合、GASの `setLimitOneResponsePerUser(false)` が授業中（回答受付中）に「Failed to edit the form」で失敗することがある。設定画面（回答→回答を1回に制限する）の状態を再読み込みして確認する。

**落とし穴**
- `clasp` は別組織のアカウントでログイン済み。`clasp login` で上書きすると他案件の認証が消えるため、学校用には使わない。
- FormApp では「成績の発表(送信直後)」「不正解だった質問/正解/点数の表示」を設定できない。作成後にフォーム設定画面で手動設定する(既定は「確認後に手動で表示」)。
- メール収集の既定が「回答者からの入力」(手入力)になる。「確認済み」に変える(Googleログインから自動取得)。
- 「確認済み」だと、生徒は最初に「メールアドレスを記録する」チェックを入れる必要がある(授業で案内)。
- `fetch('http://127.0.0.1:...')` をPlaywrightブラウザ上のGoogleページから呼ぶとハングする。コードはインラインで渡す。
- WebFetch は公開問題PDFの全文書き出しを断ることがある。PDFをRead(pages指定)で目視するか、解答例のようにテキスト層があるものは pdftotext を使う。

**毎回の確認テスト（2回方式、2026-10-07〜）**: 同じ問題のフォームを「1回目」「2回目」の2つ作る。コードは `forms-gas/code_full.gs` の `buildReviewQuizForm_` / `createW02ReviewTests`（問題はサイト内クイズのHTMLから機械抽出→`SPEC_W02`）。Apps Script には必要部分だけ貼って実行でき、`require`はPlaywright側で使えないためコードはインラインで渡す。作成後に設定画面で手動設定: 成績の発表=送信直後／不正解の質問・正解・点数=オン／メール収集=確認済み（「回答」セクションは「回答の設定を表示」を押すと出る。トグルはrole=checkboxでaria-labelの前方一致で操作）。Playwrightのスクリーンショットは filename を相対指定するとリポジトリ直下に出ることがあるので、絶対パスで`.playwright-mcp/`へ出す。

**確認テストの分析タブ**（`forms-gas/addition_review_analysis.gs`、2026-10-07）: `renameReviewTabsW02`（シートの`getFormUrl()`でフォームと回答タブの対応を確認してから「第N回_確認テスト1回目/2回目」へ改名）→`addReviewAnalysisW02`で「第N回_確認テスト分析」（上=問別の正答率・1回目/2回目/差、中=全体の受験者数・平均、下=個人別の1回目・2回目・差・受験状況）。点数はGoogleの点数列に頼らず、正答と照合して自前で採点。参照は列全体（`B:B`）で、始点固定の範囲(`B2:B`)は行挿入でずれるので使わない。**`setFormulas`に数式でない文字列（ラベル・選択肢の文字）を混ぜると`#ERROR!`になる**ので、文字は`setValues`、数式は`setFormulas`に分ける（検証テスト`testReviewAnalysis`で初回FAILして発見）。回を増やすときは `buildReviewAnalysis_(ss, spec, label, tab1, tab2, analysisName, maxRows)` を呼ぶだけ（設問列がQ1.から連続していることを自動確認する）。

**学生向けGASウェブアプリ「ITパスポート_自分の成績」（2026-10-14公開）の前提と確認点**: 実行=先生の権限／アクセス=学校法人 清風明育社 内の全員。本人確認は `Session.getActiveUser().getEmail()`（公式: 同じWorkspaceドメインなら制限は一般にかからないが、先生本人は例外なので先生のアカウントでは判定にならない）。**学生の組織部門で Apps Script がオフだと、ウェブアプリの実行も止まる**（管理者ヘルプ原文: "Script and trigger executions are blocked. Blocked scripts include web apps…"。管理コンソール > アプリ > Google Workspace > ドライブとドキュメント > Google Apps Script。グループ設定が組織部門設定より優先）。学生が開けないときは、画面のメッセージで原因を切り分ける（Apps Scriptオフ／別アカウントでログイン中／メールが取れない）。取れない場合の代案は、本人の確認済みメールへ本人の分だけを `MailApp` で送る方式。

**自分の成績ページの新しい回の登録は自動（2026-10-14、本番バージョン4）**: 回答スプレッドシートの「成績ページ設定」タブ（列: id/week/kind/label/formId/key/topics/sections/recapOf/keyOf/link）を、ページが開くたびに読み、コード内の組み込み7テスト（第3回まで）に足す。行を足すのは、フォームを作るコード側から `forms-gas/mypage_register.gs` の `registerMyPageTest_` を呼ぶ（正答 `key` はフォームのクイズ設定の正解の選択肢から自動取得、2回目は `keyOf`）。壊れた行（id/formId重複・不正JSON・topics数違い・公開サイト以外のlink・kind不正）は無視して実行ログに理由を出し、全員の画面は止めない。設定タブが読めなくても組み込み分は必ず出る。前回の問との照合（recapOf）は、フォームが半角スペースで保存する正答に合わせて空白をそろえて比べる。仕組みを直すときは `node test_mypage.js`（45件）と `node test_register.js`（5件）。登録後はエディタで `checkMyPageStructure`。なお `registerMyPageTest_` を呼ぶのは「フォーム作成コードのApps Scriptプロジェクト」側なので、第4回のフォームを作るときに `mypage_register.gs` をそのプロジェクトへ貼る（まだ貼っていない）。

**自分の成績ページの高速化（2026-10-14、本番バージョン5）**: 遅さの原因は「Googleへの呼び出し回数」（計算は1ms）。計測（`profileMyPage`、キャッシュを消した状態）で、探す処理（Drive検索3秒・全タブの getFormUrl 1.6秒）と、回答タブ1枚ごとの読み込み（約0.4〜0.5秒/枚、行数に関係なく一定）が主だった。対策: ①スプレッドシートIDと「テスト→タブ(gid)の対応」を6時間キャッシュ（成績・メールは入れない。対応が決まった回は探し直さない／未作成の回だけ毎回探す／分析タブなど対応しないタブは次から調べない。登録テストが変わったら見直す）②回答タブを Sheets API（高度なサービス「Sheets」v4）の `batchGet` で1回にまとめて読む（使えなければ1枚ずつ読む。日時はシリアル値になるが、新しい行を選ぶ並べ替えにしか使わないので問題なし）。結果: 初回 14.8秒→3.6秒、キャッシュあり 1.5秒→0.33秒。ブラウザで開いた体感は初回約4秒・2回目以降約2秒（残りは Apps Script ウェブアプリ自体の固定の待ち時間で、コードでは縮まらない）。テストは `node test_mypage.js`（52件）と `node test_register.js`（5件）。Sheets API の高度なサービスをプロジェクトに追加済み（外すと一括読み込みが1枚ずつに戻り遅くなるだけで、表示は壊れない）。タブを手で削除・改名しても、フォームIDで探し直すので壊れない。キャッシュを手で消したいときは `profileMyPage` を実行する（先頭でキャッシュを消す）。

**名前欄が末尾に回る不具合（2026-10-14）**: 確認テスト2回目（問題の順番をシャッフルする設定）で、シャッフルが「名前」欄も混ぜて、名前が最後に出ていた（第2・3回）。1回目・復習・用語・診断はシャッフルなしなので無事。対策: シャッフルする回は、名前を1ページ目に分けて（名前→ページ区切り→問題）、シャッフルが効くのを2ページ目の問題だけにする。`code_full.gs` の `buildReviewQuizForm_` が自動でページ区切りを入れ、作成後に `assertNameFirst_`（`addition_name_first.gs`）が「名前が先頭か／シャッフルする回は次がページ区切りか」を検査して、違えば作成を止める。作成済みのフォームは `fixNameFirst_(formId)`（名前を先頭へ移動し、必要ならページ区切りを足す。何度実行しても同じ。回答・回答タブの列は変わらない）で直せる。テストは `node test_namefirst.js`（8件）。**フォーム作成後は、公開URLをPlaywrightで開いて目で確認する**（メール記録のチェックを入れてから「次へ」を押せば、送信せずに2ページ目の問題順を見られる。`aria-checked` は取れないので `click({force:true})`）。同じ人が開くと問題の並びは毎回同じ（Googleの仕様）。ほかのフォームでも「シャッフル」「ページ区切り」を使うときは、名前欄の位置を必ず確認する。

**先生用の「個人別一覧」タブ（2026-10-14作成、回ごとには作らない）**: 回答スプレッドシートの1枚のタブ「個人別一覧」に、学生1人=1行で、診断（合計＋分野別%）・各回の復習・確認1回目・確認2回目の点数と、確認1回目の通算正答率を並べる。上に「最終更新」、受験者数、クラス平均の行。6割未満は色つき。**列は `loadTests_()`（組み込み＋設定タブ）から作るので、第4回以降は成績ページへの登録だけで列が自動で増える**（個別の作成作業なし）。コードは `forms-gas/mypage.gs` の `buildOverviewMatrix_`（計算。Nodeで検証）・`updateOverview`（書き込み）・`installOverviewTrigger`（10分ごとの自動更新、設置済み）。成績ページのApps Scriptプロジェクト（「ITパスポート_自分の成績」）で動く。メール・名前・点数が入るので**先生だけが見るタブ。AIは中身の行を開かない**（確認は「学生N行・列M」のログと偽データのテストで行う）。承認した権限: drive読み取り・script.scriptapp（トリガー）・spreadsheets・メール確認（2026-10-14、先生アカウントで承認）。以前計画していた「第N回_確認テスト分析」タブ（`buildReviewAnalysis_`、回ごとに作る方式）は、一覧タブで代替するので、第3回以降は作らない。テストは `node test_mypage.js`（60件）。

**フォームの「回答→要約」画面は個人情報を含む（2026-10-14）**: 確認テストなどのクイズフォームの要約画面には、集計のほかに「スコアの通知」（メール・点数・日時の一覧）と、名前の欄の回答一覧が出る。`document.body.innerText` 全体を取ると、これらがそのまま入ってしまう。集計の数字（選択肢別の件数、平均、得点分布）だけが必要なときは、要素を絞って取るか、成績ページのApps Scriptの `classStatsMyPage`（受験者数・平均・問別正答率のみ）を使う。報告書シート（水_本田_HITパス）の「気づき」「学生の状況」には、個人名・メール・個人別の点数を書かない（クラス全体の数字だけ）。報告書の各回タブの記入手順（セルはF2→insertText→Enter、授業内容詳細は1セルずつ、行12は1行・行14/15は2行まで、学生の到達度は`86%`の形）は、GOAL.mdの第2・3回の記録を参照。


**第4回で確認した本番の実地手順（2026-10-21）**: フォーム作成用のApps Scriptプロジェクト（`script.google.com/home` の「無題のプロジェクト」で、`createW03Forms` を含む1ファイルのもの）に、`addition_wNN.gs` の中身を `monaco.editor.getModels()[0].setValue(旧+新)` で足して保存→関数名を `role=listbox[name="実行する関数を選択"]` で選ぶ→**選択名を読み戻して一致を確認してから**「選択した関数を実行」を押す（`[aria-label*="関数"]` のような広いセレクタでクリックすると、前回選んだ関数が実行される。第4回では `createW02ReviewTests` が誤って動き、同名フォームの重複防止ガードで止まった）。フォームの手動設定（Playwright）: 設定タブ→「送信直後」ラジオと「不正解だった質問/正解./点数.」を `click({force:true})`、メール収集は `aria-label="回答の設定を表示"` を押して `aria-label="回答者のメールアドレスの収集方法を選択します"` のリストボックスを開き `[role="option"]:visible:has-text("確認済み")` を押す。用語フォームはクイズではないのでメール収集だけ。成績ページへの登録は、同じプロジェクトに `mypage_register.gs` を足し `registerMyPageTest_` を呼び、成績ページ側で `checkMyPageStructure`（`script.google.com/home` から「ITパスポート_自分の成績」を開く）。**復習テストの `recapOf.n` は、参照先の確認テストと「正答の文字列と用語（topics）が同じ問」だけ**（別の聞き方の問を含めると「recapOf が参照先と合いません」で行ごと無視される。その場合は設定タブの `recapOf` セルだけ直す）。

**成績ページの全学生検証（2026-10-21、学生から「ちゃんと反映されているか」の声があって実施）**: `forms-gas/verify_mypage.gs` の `verifyMyPageAll` を成績ページのApps Scriptのエディタで実行する（読み取り専用・ウェブアプリのデプロイに影響なし・氏名/メール/個人の点数はログに出さず件数だけ）。やること: ①全回答行の自前採点とフォームの点数列の突き合わせ ②全学生分を `buildReportFromTables_`＋`renderHtml_` で生成し、回答タブにある人が画面で「受けた」になっているか ③学校以外のドメイン・同じ人の重複行・空欄・同名で別メールの有無。結果（第4回後、学生39人・全10テスト）: 点数の不一致0、画面の食い違い0/390、生成失敗0、別ドメイン0、同名別メール0。診断テストだけ再受験の重複行31（画面は新しい行を採る設計）。学生に見える不具合の声があったら、まずこれを回し、次に学生本人の画面のメッセージ（「メールが取れない」「別アカウント」「準備中」など）を聞く。

**成績ページ 本体 v6（2026-10-21）**: 画面に「最終確認：M月d日 H:mm（日本時間）」と「受けたテスト」一覧（回ごとに 復習／確認1回目／確認2回目（任意）が 受けた／まだ）を追加（学生の「反映されているか」の声への対応）。`mypage.gs` の `stampJst_`・`doGet`・`renderHtml_`、テストは `node test_mypage.js` 61件（時刻と一覧の確認を追加。doGet のテストには `ctx.Utilities` の模擬が要る）。**更新手順（実績）**: ①ローカルで変更→`node test_mypage.js`/`test_register.js` ②エディタのコードへ同じ置換（`monaco...setValue`）→保存→該当部分のSHA-256をローカルと照合 ③`verifyMyPageAll` で全学生の画面生成に不備なしを確認 ④「デプロイ」→「デプロイを管理」→鉛筆（右上、aria-label=編集）→バージョンで「新バージョン」→説明は `fill()` で入れる（Metaキーの全選択は効かず追記されてしまう）→「デプロイ」。URL・デプロイIDは変わらない。⑤本番URLを開いて表示を確認。タブ名は `renameTabsW03W04`（フォーム作成用プロジェクト）で整理済み。フォームのタイトルは空なので、照合は `DriveApp.getFileById(form.getId()).getName()` で行う。

## 成績ページ 本体v7（2026-10-21）: 用語カードの提出状況を追加
- 設定タブに kind='terms' の行（w01〜w04_terms。`registerTermForm_` / `registerAllTermForms`）を足し、`loadTests_` はそれを除外、`loadTermForms_` で別に読む。画面は「受けたテスト・用語カード」に「用語カード 提出済み/まだ」を出す。第5回以降は、その回のフォーム作成コードの最後で `registerTermForm_` を呼ぶ。
- 反映手順: ローカル `mypage.gs` の SHA-256（末尾空白除去）とエディタの検証関数より前の部分を照合→`verifyMyPageAll`（用語カード対応版）を実行し「食い違い0」を確認→デプロイ（新バージョン）。全学生39人で0/546、v7を本番に反映済み。
- 先生アカウントで開くと全部「まだ」になるのは正常（受講者ではない）。本番確認は見出し・欄の有無だけを見る。
