セキュリティとデータガバナンスを学ぶ

Week 5 木曜 3・4限
テーマ
自分が使っているAIエージェントに「何が送られ、どう扱われるのか」を公式資料で確認し、進級制作で何を入力してよい・よくないかを自分たちで判断できるようになる
キーワード
データガバナンス / 学習への利用 / 保存期間 / 個人契約と商用契約 / 入力してよいデータ
必要な準備
自分が使うAIエージェント（Claude Code／Codex CLI／Antigravity CLI）の契約・ログイン状態がわかること。ノートPCで公式ページを開ける状態にしておく。

この回のゴール

  • AIエージェントを使うとき、プロンプトやコードがネットワーク経由で送られていることを説明できる
  • 「学習に使われるか」「どれくらい保存されるか」は、サービスや契約の種類で違うことを、公式資料で確認できる
  • クラウドAIサービスの「個人情報を扱えるレベルの安全設計」が、どのような要素の組み合わせで成り立っているかを理解する
  • 「学習に使われない」＝「何を入力してもよい」ではないことを理解する
  • 自分が使っているエージェントの設定画面を実際に開いて、現在の状態を確認する
  • 進級制作で何を入力してよい・よくないかを、自分の言葉でルール化する
今日の進め方: 正解を暗記する回ではありません。サービスの規約や設定は変わることがあるため、公式資料を自分で読んで確認する習慣を身につけることが目的です。表現は公式の言い回しに合わせて確認しましょう。

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

AIエージェントを使うと、何が送られているのか

前回の振り返りから入る

  • 前回は、Codespacesのポート転送を「パブリック」にすると認証なしで世界中からアクセスできることを学んだ。今日は視点を変えて、自分が入力した情報の行き先を確認する

Claude Codeを例に、データの流れを読む

  • 公式ドキュメントには次のように書かれている（公式: Data usage）:「Claude Code runs locally. To interact with the LLM, Claude Code sends data over the network. This data includes all user prompts and model outputs, encrypted in transit via TLS 1.2+.」
  • つまり、手元のPC（またはCodespace）で動いていても、指示文とモデルの出力はネットワーク越しにモデルの提供元へ送られる。Codex CLI・Antigravity CLIも、モデルを呼び出す仕組みである以上、入力が提供元のサービスに渡る点は同じ
  • 手元にも記録が残る。Claude Codeは、セッションの記録を手元の~/.claude/projects/に平文で、既定で30日間保存する（同じ「Data usage」ページ）

今日の問い

  • ①送った内容はモデルの学習に使われるのか　②どれくらいの期間保存されるのか　③誰がそれを見られるのか——これらは別々の論点であり、サービスや契約の種類によって答えが違う。この回では、①②③を公式資料で確認していく
1限 後半 約50分

公式資料で、自分のエージェントの扱いを調べる

自分が使うエージェントの資料を読む（同じエージェントの人同士でグループになる）

各自、自分が使っているエージェントの行を担当し、①学習への利用　②保存期間　③その他の注意点を、公式ページから探して書き出す。以下は、教員が事前に公式ページで確認した内容（確認日: 2026-09-30）で、答え合わせ用として使う。

  • Claude Code（個人のFree／Pro／Maxプランで使う場合）: 公式は「We will train new models using data from Free, Pro, and Max accounts when this setting is on (including when you use Claude Code from these accounts).」と書く（Data usage）。つまり設定がオンのときは学習に使われる。保存期間は、設定がオンなら5年、オフなら30日（確認日時点）。設定はいつでも変更できる
  • Claude Code（API・Amazon Bedrockなど商用の経路で使う場合）: 公式は「Anthropic does not train generative models using code or prompts sent to Claude Code under commercial terms, unless the customer has chosen to provide their data to us for model improvement」と書く（同上）。既定では学習に使われない。なお、Amazon Bedrockについて、AWSの公式ドキュメントは「Because the model providers don't have access to those accounts, they don't have access to Amazon Bedrock logs or to customer prompts and completions.」と書く（Data protection（Amazon Bedrock））
  • Antigravity CLI: 公式の追加利用規約は「We use Interactions to evaluate, develop, and improve Google and Alphabet research, products, services and machine learning technologies.」と書き、設定でデータの使われ方の選択を変えられるとする。一方、冒頭でGemini Enterprise（Google Cloud）・Google Workspaceなどの契約で使う場合はこの規約は適用されないと書く（Google Antigravity Additional Terms of Service）。どのアカウントでログインしているかで適用される規約が変わる
  • Codex CLI: OpenAIのヘルプセンターによると、個人のChatGPTプランでCodexを使う場合は「Improve the model for everyone」の設定がCodexにも適用される。加えて、Codexには別の設定「Include environments」があり、ChatGPT側の設定を変えても連動しない、とされている。ヘルプ記事は授業中に各自が公式ページで実際に読んで確認する（How your data is used to improve model performance（OpenAI Help Center））
読み方のコツ: 「個人向けプラン」と「商用・組織向けの契約」のどちらの話なのかを、まず見出しで確認します。同じサービス名でも、契約の種類が違えば書かれている扱いが変わります。読み取れなかった箇所や、公式の英語の意味が曖昧な箇所は、AIエージェントに「この文章を日本語で説明して」と頼んでよい（ただし最終判断は原文の公式ページで確認する）。

調べた結果を共有する

  • グループごとに、学習への利用・保存期間・注意点を1分ずつで発表する
  • 教員の答え合わせと違った点があれば、どちらが新しい情報かを公式ページの日付・記載で確認する

2限 前半 約50分

「学習に使われない」なら、何を入力してもよいのか

「学習されない」と「入力してよい」は別の話

  • クラウドAIサービスの「個人情報を扱えるレベルの安全設計」は、学習に使わない・保存期間を限る・アクセスできる人を限る・契約で扱いを定めるといった複数の要素の組み合わせで成り立っている。1つの要素だけで「安全」とは言えない
  • 「学習に使われない」ことは、情報の扱いが安全になる要素の1つに過ぎない。他にも、保存される期間、提供元の担当者が内容を見られるか、契約や規約で入力が認められているかなど、独立した論点がある
  • 例えば、進級制作で使うAWSのFree Planアカウントは、公式規約上評価目的での利用に限られ、機微なデータの処理には使わないこととされている（本科目の履修上の注意点）。「学習に使われない設計」であっても、そのアカウントで扱ってよいデータの範囲は別に決まっている
  • 手元の記録にも注意する。Claude Codeのセッション記録は手元に平文で残るため、共有PCや共有Codespaceでは入力した内容が他の人の目に触れる可能性もある

ケースで考える（グループで話し合い）

次の入力を、それぞれ「入れてよい」「条件つきで入れてよい」「入れない」の3つに分け、理由を1文で説明する。

  • 自分が作ったゲームのソースコード（Publicのリポジトリ）
  • 進級制作で使う、架空のテストデータ（名前・住所をランダムに作ったもの）
  • アルバイト先の顧客名簿の一部（実在する人の氏名・電話番号）
  • クラスメイトの実名と成績を含むデータ
  • AWSのアクセスキー、APIキー、パスワード
  • 自分の実名・住所を含む個人情報
  • 実習先の企業から預かった、社外に出してはいけない資料

考え方の軸を出し合う

  • グループの判断を共有し、意見が分かれたケースについてなぜ分かれたかを全体で話し合う
  • 「入れない」ものを、どうすれば入れる必要がない形にできるか（ダミーデータに置き換える、秘密の値は環境変数やシークレット管理に分ける、など）も考える
2限 後半 約30分

自分のエージェントの設定を実際に確認する

設定画面を開いて、現在の状態を見る

  • Claude（個人プランの人）: claude.ai/settings/data-privacy-controls で、モデル改善への利用の設定を確認する
  • Antigravity CLI: 自分のログイン方法（個人のGoogleアカウントか、組織のアカウントか）と、設定でデータの使われ方の選択があるかを確認する
  • Codex CLI（ChatGPT）: ChatGPTの「Data Controls」で「Improve the model for everyone」の状態を確認し、Codexの設定に「Include environments」があるかも確認する（見当たらない場合は講師へ）
  • Amazon Bedrock経由のClaude Codeの人: 契約が「商用の経路」であること、そしてAWSアカウントがFree Planか有料かを確認する
  • 見つからない・分からない場合は、無理に設定を変えず、今の状態だけを控えて講師に質問する

進級制作の「入力ルール」を3行でまとめる

  • 「入れる／入れない」の基準を、自分の言葉で3行にまとめる（例:「実在する人の個人情報は入れない。テストにはダミーを使う。キーやパスワードは入れない」）
  • チームで進級制作に取り組んでいる場合は、チーム内で共有して1つのルールにそろえる

課題・次回までにやること

必須
自分の「入力ルール」を進級制作のメモに残しておく

推奨
