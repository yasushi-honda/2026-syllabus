スコアを保存して守ろう：カード不要のNeonとセキュリティ

Week 5 木曜 3・4限
テーマ
前回の対戦ゲームの「スコア」を、クレジットカード不要の無料クラウドDB（Neon）に残す。AIエージェントに頼んで作りながら、接続文字列という「秘密」の守り方と、何を保存・入力してよいかを体験で学ぶ
キーワード
Neon（Postgres） / 接続文字列（パスワード相当） / 一時プロジェクトとclaim / 最小権限（読み取り専用ロール） / データガバナンス（データの置き場所・入力してよいデータ）
必要な準備
自分が使うAIエージェント（Claude Code／Codex CLI／Antigravity CLI）が使える状態のCodespace。ノートPCで公式ページを開けること。

この回のゴール

  • ゲームのスコアをクラウドのDBに保存し、Codespaceを止めても残る仕組みを、AIエージェントに頼んで作る
  • DBの接続文字列は「パスワード相当」の秘密であり、渡す・コミットすると何が起きてしまうかを体験する
  • AIエージェントに何が送られ、学習に使われるか・どれくらい保存されるかは、サービスや契約で違うことを公式資料で確認する
  • 最小権限（必要な権限だけを与える）の考え方を、読み取り専用ロールで体験する
  • クラウドAIサービスの「個人情報を扱えるレベルの安全設計」が、複数の要素の組み合わせで成り立つことを理解し、自分の入力ルールを決める
今日の進め方: 読む時間より、作って壊して直す時間を長くします。壊してよいのは、今日作る自分の使い捨てのDBだけです。他人のサービスや、本物の個人情報には絶対に触れないでください。

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

スコアを残したい——まず、データがどこへ行くのかを知る

前回のつづき

  • 前回のゲームは、Codespaceを止めるとスコアが消える。スコアをクラウドのDBに残したい——今日はそのための無料の道具を使う

AIエージェントに何が送られるか（教員が要点だけ提示）

  • Claude Codeの公式ドキュメントには次のように書かれている（Data usage）:「Claude Code runs locally. To interact with the LLM, Claude Code sends data over the network. This data includes all user prompts and model outputs, encrypted in transit via TLS 1.2+.」——手元で動いていても、指示文とモデルの出力はネットワーク越しに提供元へ送られる
  • エージェントにファイルを読ませると、その内容も指示文の一部として送られうる。後で作る.env（DBの秘密の接続文字列）を、エージェントに読ませるかどうかも「判断」の対象になる
  • 学習への利用・保存期間は、契約の種類で違う。個人向けプランでは設定がオンなら学習に使われ、保存も長い（Claudeは設定オンで5年・オフで30日）。API・Amazon Bedrockなどの商用の経路では、既定では学習に使われない（公式: 「Anthropic does not train generative models using code or prompts sent to Claude Code under commercial terms, unless the customer has chosen to provide their data to us for model improvement」）。Antigravity CLIは、利用経路（個人のアカウントか、組織の契約・APIキーか）で適用される規約が変わる（Google Antigravity Additional Terms of Service）。Codex CLIについては、OpenAIのヘルプセンターで各自が確認する（How your data is used to improve model performance。教員は本文を直接確認できていないため、必ず各自が公式ページで読む）
  • 「学習に使われない」だけでは安全とは言えない。学習に使わない・保存期間を限る・アクセスできる人を限る・契約で扱いを定めるといった、複数の要素の組み合わせ（データガバナンス）で「個人情報を扱えるレベルの安全設計」は成り立つ

今日使うDB: Neon

  • Neonは、Postgres（表形式のデータベース）のクラウドサービス。公式の料金ページには、Freeプランについて「The Free plan is permanent (not a trial); no credit card required」と書かれている（Pricing（Neon公式））——クレジットカードなしで使い始められる
  • Freeプランは、1プロジェクトあたり0.5 GBまで。使っていないときは自動で休止する（公式: 「suspends after 5 min」）
1限 後半 約50分

アカウントなしでDBを作り、AIエージェントにスコア保存を頼む

Codespaceを再開して、作業フォルダを用意する

  • これまでと同じ手順でCodespaceを再開し、新しい作業フォルダ（例: score-db）を作る
  • 最初に、フォルダに.gitignoreを作り、.envとnode_modulesを書き込んでおく（DBの秘密の接続文字列を、誤ってGitHubに載せないための備え。書き方が分からなければエージェントに頼んでよい）

アカウントなしで、一時的なDBを作る

  • Neonの公式CLIを入れる: npm i -g neon（うまくいかないときは、エージェントに「Neon CLIを入れて」と頼んでよい。公式: Neon CLI）
  • 次のコマンドで、アカウントを作らずに一時的なプロジェクトを作り、接続文字列を.envに書き出す: neon claim create --env-pull
  • 公式の説明: 「Unclaimed projects expire in 72 hours (project.expires_at) and are capped at 100 MB storage and 1 GB transfer.」——72時間で期限切れ（あとで自分のアカウントに引き継ぐ手順は2限後半に扱う）（Claimable Neon）
  • .envにはDATABASE_URLが入る。これがDBに入るための鍵（パスワード相当）。中身をチャットや画面に貼らない

AIエージェントに、スコア保存のスクリプトを頼む

  • 例: scoresテーブル（id・名前・スコア・作成日時）を作り、スコアを1件追加して、上位10件を表示するNode.jsのスクリプトscores.jsを書いてください。DBへの接続は、.envのDATABASE_URLを使い、pgパッケージで行ってください。必要なパッケージのインストールと、.envの読み込み方法（dotenvか、Nodeの--env-file）も含めてください
  • エージェントが書いたコードを読んでから実行する。接続文字列がコードの中に直接書かれていないか（.envから読み込んでいるか）を確認する（Nodeからの接続の公式例: Connect from any application）
  • 実行して、スコアが表示されれば成功。新しいターミナルでもう一度実行しても、スコアが残っていることを確かめる（時間があれば、Codespaceを一度止めて再開しても残っていることも確かめる。スコアは手元ではなくクラウドのDBにあるため）
詰まったら: 接続できない、エラーが出るときは、そのエラー全文をエージェントに貼って「原因と直し方を教えて」と頼んでよい。それでも進まなければ、講師に声をかけてください。教員のデモに切り替えるか、Neonの無料アカウント（カード不要）をブラウザで作ってプロジェクトを作成し、neon connection-stringで接続文字列を取り出す方法に切り替えます。
休憩 10分
2限 前半 約50分

鍵を渡すとどうなるか——壊して、守る

ミッション1: 隣の人の記録を消してみる（約20分）

  • ルール: 対象は自分たちが今日作った使い捨てのDBだけ。相手の同意を得て、授業内でのみ行う。他人のサービスや本物のデータには絶対に試さない
  • ①隣の人に、自分のDATABASE_URLを渡す。渡し方は画面に表示して、相手が手で入力する（チャット・メール・Slackなどに貼らない。履歴に残るため）。これは授業の中だけの例外で、本番では絶対にしない
  • ②渡された人は、エージェントに環境変数DATABASE_URLで指定されたDBのscoresテーブルの中身を全部消す、clear-scores.jsを書いてくださいと頼み、書かれたコードを読んでから、DATABASE_URL="受け取った文字列" node clear-scores.jsのように自分のターミナルに直接入力して実行する（接続文字列そのものは、エージェントへの質問には貼らない。貼ると、その内容も提供元へ送られうるため。これは後のケース討議の題材でもある）
  • ③持ち主は、自分のスクリプトを実行して、スコアが消えたことを確かめる
  • 気づいてほしいこと: 接続文字列を持っている人は、DBの持ち主と同じことができてしまう。ログインもパスワード入力も、そこには出てこない

ミッション2: 権限を絞る（最小権限）（約20分）

  • エージェントに頼む（例）: scoresテーブルを読むだけの、読み取り専用ロールreadonly_userを作ってください。そのロールの接続文字列で、SELECTはできて、INSERTとDELETEは失敗することを確かめてください
  • Neonの公式ドキュメントでは、読み取り専用ロールはデータベース・スキーマ・テーブルの各レベルで権限を与えると説明されている（「access must be granted at the database, schema, and object level」。Manage database access）。エージェントが書いたSQLを読んで、GRANT CONNECT・GRANT USAGE ON SCHEMA・GRANT SELECTに対応する行があるか探す
  • 読み取り専用ロールの接続文字列ももう1つの秘密。.envに別の名前（例: READONLY_DATABASE_URL）で書き、コードには直接書かない
  • ミッション1をもう一度、読み取り専用の接続文字列で試す——消せなくなったことを確認する
  • 一時的なプロジェクトの制限で作れない場合は、講師のデモで確認する

ミッション3: 漏れたらどうするか（約10分）

  • パスワードを変える（ローテーション）ことで、漏れた接続文字列を無効にする。Neonの公式には、コンソールの「Reset password」またはSQLのALTER USER … WITH PASSWORDで変えられると書かれている（Manage roles）。アカウントのない一時プロジェクトでは、コンソールはまだ使えない可能性が高いので、SQLで変えるか、作り直して捨てるのが手。コンソールの「Reset password」は、自分のアカウントに引き継いだ（claimした）あとの選択肢になる
  • もしPublicのリポジトリに接続文字列をpushしてしまったら、誰でも読めるため、消しても遅いと考えて、すぐにパスワードを変える。だから最初の.gitignoreが大事になる
2限 後半 約30分

何を保存・入力してよいか決めて、DBを自分のものにする

ケースで考える（グループで話し合い、約15分）

ゲームのスコアDBに入れる・エージェントに見せる内容を、「入れてよい」「条件つきで入れてよい」「入れない」に分け、理由を1文で説明する。

  • ニックネームとスコア
  • クラスメイトの実名とスコア
  • 参加者のメールアドレス（ランキングの通知用）
  • DBの接続文字列（.envの中身）をエージェントへの質問に貼る
  • 自分の実名・住所を含むテストデータ
  • アルバイト先や実習先から預かった、社外に出してはいけない資料

データの置き場所も判断材料になる

  • Neonの公式ドキュメントによると、Neonは複数のAWSリージョンで使えるが、日本（東京）のリージョンはない（一覧にあるアジア太平洋は、シンガポールとシドニー。Regions（Neon公式））。保存したデータは日本国外に置かれることがある——個人情報を扱うなら、置き場所や契約も確認が必要になる
  • 第3回で扱ったAWSのFree Planは評価目的に限られ、機微なデータの処理には使わないとされている（本科目の履修上の注意点）。「安全な設計」でも、そのアカウントで扱ってよいデータの範囲は別に決まっている

DBを自分のものにする（任意、約10分）

  • 72時間で消える一時プロジェクトを残したい人は、neon claim acceptで自分のNeonアカウントに引き継ぐ（claim）。公式の説明では、コマンドは「claim codeを作り、人がサインインしてプロジェクトを引き取るURLを開く」。Codespaceでは、ブラウザが自動で開かないことがあるので、表示されたURLを手元のブラウザで開く（Neon CLI）
  • アカウント作成の途中でクレジットカードの入力を求められたら、進まずに講師に声をかける（Freeプランはカード不要と公式に書かれているが、画面の実際の表示を確認する）
  • 引き継がないなら、72時間後に消えることを理解しておけばよい

自分の「入力ルール」を3行でまとめる

  • 例:「実在する人の個人情報は入れない。テストにはダミーを使う。接続文字列やキーは、コードにもチャットにも書かない」
  • チームで進級制作に取り組んでいる場合は、チームのルールとしてそろえる
まとめ 約10分

課題・次回までにやること

必須
接続文字列（.env）が、GitHubにpushされていないことを確認する

自分のリポジトリを開き、.envが見えないことを確かめる。もし見えてしまっていたら、すぐに講師に伝えて、パスワードを変える。あわせて、今日まとめた「入力ルール」を進級制作のメモに残しておく。

推奨
スコアの保存を、自分のゲームに組み込んでみる

前回のゲームに、スコアを送る処理を足してみましょう。ブラウザに接続文字列を直接書くと誰にでも見えてしまうので、どこから送るのが安全かも、エージェントと相談してみてください。
