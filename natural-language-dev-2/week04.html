AIエージェントを接続しよう

Week 4 木曜 3・4限
テーマ
3つのAIエージェント（Claude Code／Codex CLI／Antigravity CLI）に共通する仕組みを先に押さえてから、前回決めた経路でそれぞれ接続する
キーワード
ハーネス（AGENTS.md）/ スキル（SKILL.md）/ 確認プロンプトを減らす設定 / Amazon Bedrock / gcloud CLI・gh CLI
必要な準備
前回決めた「今日から使うAIエージェント」。AWSに登録した人は、Bedrockのモデルアクセスと予算アラートの設定を完了しておく。

この回のゴール

  • 3エージェントに共通する3つの仕組み——ハーネス・スキル・確認プロンプトを減らす設定——を理解する
  • 前回決めた経路で、自分のAIエージェントを接続する
  • 接続したAIエージェントに実際に指示を出し、動作を確認する
  • gcloud CLI・gh CLIをAIエージェント経由で呼び出す標準パターンを体験する
今日は人によって進み方が分かれます: Claude Code（個人契約）組・Claude Code（Bedrock経由）組・Codex CLI組・Antigravity CLI組で手順が異なります。自分が選んだ経路のセクションだけを見て進めれば大丈夫です。詰まったら遠慮なく手を挙げてください。

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

接続の前に、3エージェント共通の仕組みを押さえる

前回の振り返り

  • 自分の契約状況に応じて、Claude Code／Codex CLI／Antigravity CLI（Claude Codeは個人契約またはAmazon Bedrock経由）のいずれかを選んだことを1分で振り返る

①ハーネス（指示書ファイル）

  • プロジェクトの決まりごとを書いておくファイルを「ハーネス」と呼ぶ。AGENTS.mdはベンダー中立のオープン標準で、特定の企業ではなく複数の開発者が共同で策定した（公式: agents.md「Rather than introducing another proprietary file, we chose a name and format that could work for anyone」）
  • Codex CLI・Antigravity CLIはAGENTS.mdを直接読み込む。Claude Codeも取り込める仕組みを持つ（公式: How Claude remembers your project「Claude can also read a repository's AGENTS.md files, on their own or alongside CLAUDE.md」）——Claude Code独自のCLAUDE.mdと役割は同じだと考えてよい

②スキル

  • 再利用可能な手順をMarkdownでまとめ、スラッシュコマンドとして呼び出せるようにする仕組み。3エージェントともSKILL.mdという共通の形式を使う
  • Codex CLIでは、以前あったcustom promptsという仕組みが非推奨になり、SKILL.md形式のスキルに置き換わった
  • Antigravity CLIでは、プロジェクト直下の.agents/skills/配下にYAML front matter付きのSKILL.mdを置く（公式: Agent Skills「Skills are organized as directory bundles containing a required SKILL.md file」）

③確認プロンプトを減らす設定

  • どのエージェントも「ファイル編集は自動、コマンド実行やワークスペース外・ネットワークアクセスは確認」という考え方の設定を持つ
  • Codex CLIは（gitで管理されたプロジェクトの場合）既定でconfig.tomlのapproval_policy = "on-request" + sandbox_mode = "workspace-write"の組み合わせが推奨される（公式: Agent approvals & security「Version-controlled folders: Auto (workspace write + on-request approvals)」、設定項目の詳細はConfiguration Reference）
  • Antigravity CLIはaccept-editsモード——Shift+Tabで切り替えられる。ただしシェルコマンドの実行はどのモードでも別途確認が必要（公式: Choose an execution mode「Tool permission rules configured via /permissions or --dangerously-skip-permissions continue to govern shell commands (run_command) across all execution modes.」）

これを踏まえて、それぞれの接続手順に進む。

1限 後半 約50分

前回決めた経路で接続する

Claude Code（個人契約）組

  1. 未インストールの場合はターミナルで次のコマンドを実行する（公式: Quickstart）: curl -fsSL https://claude.ai/install.sh | bash
  2. ターミナルでclaudeと入力して起動する
  3. 初回のログインプロンプトで、自分のClaude契約（Pro等）のアカウントでブラウザ認証する
  4. 動作確認として、簡単な質問を投げてみる（例: あなたが何をできるか教えてください）

Claude Code（Amazon Bedrock経由）組

  1. 未インストールの場合は上記と同じコマンドでインストールする
  2. ターミナルでclaudeと入力して起動する
  3. 初回のログインプロンプトで「3rd-party platform」→「Amazon Bedrock」を選ぶ。既にサインイン済みでいきなりチャット画面が出た場合は、/setup-bedrockと入力してウィザードを開く
  4. ウィザードではAWSの認証方法を選ぶ。第3回で登録したばかりでAWS CLIの設定がまだの人は、AWSマネジメントコンソールでAmazon Bedrockコンソールを開き、左ナビゲーションの「API keys」→「Generate short-term API key」（または long-term）でBedrock APIキーを発行しておくのが一番簡単（公式: Accelerate AI development with Amazon Bedrock API keys）。ウィザードの認証方法の選択肢では「Amazon Bedrock API key」を選び、発行したキーを貼り付ける
  5. 続けてリージョン→利用するモデルの順に設定する
  6. モデルを固定（pin）する画面では、既定で優先される上位モデル（Opus）ではなくSonnetを選ぶ——Opusは1トークンあたりの料金がSonnetより高く、第3回で設定した予算の範囲内で利用料金を抑えるため（公式: Claude Code on Amazon Bedrockの「Pin model versions」節に「Opus models have a higher per-token price than Sonnet models」と明記）
  7. 設定は自動的に保存される。動作確認として、簡単な質問を投げてみる

Codex CLI組

  1. 未インストールの場合はターミナルで次のコマンドを実行する（公式: Codex CLI）: curl -fsSL https://chatgpt.com/codex/install.sh | sh
  2. ターミナルでcodexと入力して起動する
  3. 初回起動時に表示されるサインイン方法の選択で「Sign in with ChatGPT」を選び、第3回に確認した自分のアカウントでサインインする
  4. 動作確認として、簡単な質問を投げてみる

Antigravity CLI組

  1. 前期から使っている環境（Codespaces等）を開く
  2. 認証が切れている場合は、第1回の参考リンクで示した公式ドキュメントの手順（Antigravity CLI — Installation & auth）で再認証する
  3. agyと入力して起動し、動作確認として簡単な質問を投げてみる
早く終わった人へ: 他の経路を選んだ人の様子を見に行って、進み方の違いを比べてみるのもおすすめです。

2限 後半 約30分

gcloud CLI・gh CLIを呼び出すパターンを体験する

第3回の教員デモを思い出す

  • Google Cloudの操作はgcloud CLI、GitHubの操作はgh CLIを、使用中のAIエージェントから呼び出す——これが本科目の標準パターンになることを第3回のデモで見た

実際に試してみる

  • 自分が接続したAIエージェントにgcloud --versionを実行してください、またはgh --versionを実行してくださいのように頼んでみる
  • ③で確認した「確認プロンプトを減らす設定」があっても、コマンド実行は別途確認を求められることが多い——その場で許可・拒否を選べることを体感する
今日のポイント: 以降の授業では、Google Cloudの操作はgcloud CLI、GitHubの操作はgh CLIを、使用中のAIエージェントから呼び出す形が標準パターンになります。今日はまず「呼び出せること」を確認できれば十分です。
