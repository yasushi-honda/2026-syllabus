対戦ゲームの仕組みを読み解こう

Week 4 木曜 3・4限
テーマ
前回、AIエージェントへの指示だけで動いた「6人同時対戦のリアルタイム対戦ゲーム」を振り返り、その裏側の技術と、世界中の誰とでも対戦できるようにするために必要な発想を読み解く
キーワード
WebSocket / サーバーとルーム（部屋） / ローカルネットワーク / NAT（ネットワークアドレス変換） / グローバルネットワーク
必要な準備
前回作った対戦ゲームのプロジェクトが残っていれば開ける状態にしておく（消えていても今日は問題なく進められる）

この回のゴール

  • 前回動いた「6人同時対戦」が、裏側でどんな技術を使っていた可能性が高いかをAIエージェントと一緒に読み解く
  • サーバー役のPCと、パスコードで区別されるルーム（部屋）の関係を理解する
  • なぜ「学校WiFi内でしか」動かなかったのかを、ローカルネットワークとNATの仕組みから理解する
  • 世界中の誰とでも遊べるようにするには何が必要かを考える
今日の位置づけ: 前回のプロジェクトのコードが残っていなくても大丈夫です。今日は「AIエージェントがこの種の機能を実装するときに、一般的にどんな技術を使うか」をAIエージェントへの質問や図解を通じて理解することが目的です。断定できない部分は「〜という技術が使われていた可能性が高い」という形で扱います。

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

「なぜ動いたのか」を考える

前回の振り返り

  • 前回、AIエージェント（agy／Codex CLI）に「対戦ゲーム機能を追加して」と指示しただけで、学校WiFi上に6人同時対戦のリアルタイム対戦ゲームが実装されたことを振り返る
  • 誰か1人が「部屋」を作り、他の人がそのパスコードを入力して参加する仕組みだったことを思い出す

疑問を持つ

  • 「あのとき、画面の裏側で何が起きていたのか？」をペアやグループで話し合う
  • 仮説を立ててみる: 「自分のキャラクターを動かしたことが、どうやって他の人の画面にも反映されたのか」

AIエージェントに聞いてみる

  • 前回のプロジェクトが残っている人は、agyやCodex CLIを開きこのゲームの対戦機能はどんな仕組みで動いていますか？初心者にも分かるように説明してくださいと聞いてみる
  • プロジェクトが残っていない人・別の経路を使っていた人は、周りで聞けた内容を教え合う

教員からの補足

  • 出てきた答えの中でよく挙がるキーワード（WebSocket、リアルタイム通信、部屋／ルーム、パスコード）を整理する
  • この種の「複数人がリアルタイムに情報をやり取りする」機能を、AIコーディングエージェントが実装する際によく使う技術としてWebSocketを紹介する——サーバーとブラウザが接続したままになり、双方向にデータを送り合える仕組み（公式: WebSocket - Web APIs）
1限 後半 約50分

「サーバー」と「部屋（ルーム）」の関係を図解する

前回の体験を図に起こす

  • 「サーバー役だったPC」と「パスコードで入った各プレイヤーのブラウザ」の関係を、Googleドキュメント等で簡単な図にしてみる
  • 誰がサーバー役だったか、そのとき何をクリック・入力したかを思い出しながら描く

サーバーの役割を理解する

  • サーバー役のPCが、全員の操作（キャラクターの移動・攻撃等）をいったん受け取り、それを全員に配り直している——「ハブ」のような役割を果たしていたことを理解する
  • 自分の操作が他の人の画面に反映されるまでの流れ: 「自分の操作 → サーバー → 他の全員」という経路をたどっていたと考えられる

「部屋（ルーム）」の意味を考える

  • 同じサーバーの中に複数の対戦グループが同時に存在できるよう、パスコードで「今どの対戦グループに参加しているか」を区別する仕組みが「部屋（ルーム）」だったと考えられる

考えてみる: サーバー役がいなくなったら？

  • もしサーバー役の人が途中でノートPCを閉じてしまったら、対戦はどうなっていたと思うか話し合う
  • サーバーが1台に集中している構造では、その1台が止まると全員が影響を受ける——という弱点に気づく
休憩 10分
2限 前半 約50分

なぜ「学校WiFi内でしか」動かなかったのか

問いかける

  • 「もし週末に、家から同じ部屋のパスコードを入力してアクセスしようとしたら、うまくいったと思いますか？」

ローカルネットワークとグローバルネットワークの違い

  • 家庭のWiFiと学校のWiFiは、それぞれ別の「ローカルネットワーク」（同じルーターの内側の範囲）であることを整理する
  • インターネット全体を指す「グローバルネットワーク」と、自分の家や学校の中だけの「ローカルネットワーク」の違いを図で確認する

NAT（ネットワークアドレス変換）を知る

  • ルーターの内側にあるPCは、外部（インターネット）から直接アクセスできない仕組みになっている——これをNAT（Network Address Translation）と呼ぶ（公式: What is NAT (Network Address Translation)?「NAT can provide a measure of security by... preventing devices on the internal network from being accessed directly from the internet」）
  • だからこそ、サーバー役のPCに学校の外からはたどり着けなかった、と考えられる
余裕があれば: AIエージェントになぜこのゲームは家からは遊べないのですか？と聞いてみて、今日整理した内容と答えが近いか比べてみましょう。
2限 後半 約30分

世界中の誰とでも対戦できるようにするには？

発想を転換する

  • 「サーバー役を、誰かの個人PCではなく、みんなが外から確実にアクセスできる場所に置けばいい」という発想に気づく

クラウドにサーバーを置く、という考え方

  • クラウド（Cloud Run等）にサーバーを置くと、インターネット上のどこからでもアクセスできる公開アドレスが手に入る——これが第7回で学ぶCloud Runにつながることを予告する
  • Cloud RunはWebSocket通信にも対応している（公式: Using WebSockets）。ただし接続時間には既定5分・最大60分の上限があり再接続が必要になること、複数のサーバーが同時に動く構成ではプレイヤー情報を共有する仕組み（Firestore等、第9回で学ぶ）が必要になることにも触れておく

今日はここまで

  • 今日は「世界中と対戦できるようにするには何が必要か」を概念として理解するところまで。実際にクラウドにデプロイする体験は、第7回（Cloud Run）・第9回（Firestore）で扱う
まとめ 約10分
