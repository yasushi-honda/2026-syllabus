AIエージェントに効率よく働いてもらう、指示の4つの型

Week 8 木曜 3・4限

📱 スマホで開く

教室の画面を見ながら、自分のスマートフォンで、このページを開けます。スマートフォンのカメラで、このQRコードを読み取ってください。QRコードを押すと、大きく表示されます。

テーマ
同じAIエージェントでも、指示のしかたで、できあがりと手間が大きく変わる。使用中のAIエージェントに効率よく働いてもらうための4つの型（①先に質問させる ②計画だけ立てさせる ③道具で解決できるか聞く ④確かめ方を渡す）を知り、自分の題材で試す
キーワード
先に質問させる（選択肢で提案） / AskUserQuestion / plan（計画）モード / CLIとMCPで解決できる？ / 確かめ方を渡す / 指示ファイル（CLAUDE.md・AGENTS.md・GEMINI.md） / 指示の型カード
必要な準備
自分が使うAIエージェント（Claude Code／Codex CLI／Antigravity CLI）が使える状態のCodespace。第7回の作業フォルダ（仕様の1ページと、動く最小版）。今日は、新しいサービスの登録はしません。

この回のゴール

  • 指示を4つの型に分けて説明でき、それぞれどんなときに効くかが言える
  • 実行する前に、選択肢つきで質問させる指示を書ける（使用中のエージェントでの出方の違いを知る）
  • 「これはCLIやMCPで済む？」と、道具を先に聞くことができる
  • 合否が出る確かめ方を渡して、実行した結果を証拠として見せてもらえる
  • 自分の題材で、4つの型を使った指示を試し、変える前と後を比べて、指示の型カードにまとめられる
今日の進め方: 型の名前を覚えるより、自分の指示を1つ書き換えて、結果が変わるのを見ることが目的です。エージェントは3種類（Claude Code／Codex CLI／Antigravity CLI）が混ざっています。機能の名前は違っても、「実行する前に、選択肢を出して選ばせて」のような普通の文章は、どれでも試せます（出方は違うことがあります）。ツールごとの違いは、表で確かめます。

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

ここまでの学びを振り返り、今日の4つの型の地図を見る

① ここまでの振り返り（約15分）

  • 第1〜7回で、クラウドの考え方、AIエージェント、Neon、仕様を書いて作らせる、を体験してきた。1人1分で、「うまくいった指示」と「つまずいた指示」を1つずつ、隣の人に話す
  • 全体で、いくつか聞く。つまずいた指示は、今日の4つの型でどう書き換えられるかを、あとで考える材料になる

② 今日の地図：指示の4つの型（約10分）

③ 今日の例の題材を決める（約15分）

  • 第7回で作った動く最小版（または、自分の進級制作の一部）を開く。今日の指示の練習は、すべてこれを題材にする
  • 題材に対して、「こう直したい／こう足したい」を1つ決める（例: 結果の表示を見やすくする、入力のチェックを足す、Neonへ保存する項目を増やす）。最初の指示（型を使う前の、ふつうの1文）を、メモに書いておく。これが、あとで「変える前」になる
  • 先に、DBが動くか確かめる: 第7回で作ったNeonの一時DBは72時間で期限切れになるので、今日は切れている可能性が高い。保存や集計を使う題材のときは、第6回の手順でDBを作り直して、接続文字列（.env）を差し替える。DBを使わない題材（画面や入力チェックの直しなど）を選んでもよい
  • 「変える前」の結果を残す: ①作業フォルダを2つコピーする（名前の例: start＝何も変えずに取っておく／base＝最初の指示を試す用。エージェントに「このフォルダをstartとbaseの名前でコピーして」と頼んでもよい）②baseで、最初の指示をそのまま送り、できあがりを画面かスクリーンショットと変わったファイルの名前でメモする（これが「変える前」の結果）。startは、触らない（以降の練習は、startのコピーでする）③エージェントは、フォルダごとに新しく起動し直す（前の会話を引き継がない。同じ会話を続けると、前の指示や答えが混ざって、比べられなくなる）
1限 後半 約50分

型①先に質問させる、型②計画だけ立てさせる

型①　先に質問させる（選択肢で提案してもらう）（約25分）

  • 書き方の例（どのエージェントでも試せる、ふつうの文章。出方は違うことがある）:
この題材を直したいです。実行する前に、決めることを選択肢つきで質問してください。
質問は一度に3つまで、それぞれ選択肢にはおすすめも添えてください。
私が選んでから、実行してください。
  • 使用中のエージェントでの出方（公式で確認したこと。確認日 2026-11-05）は、下の表のとおり。「名前を書けば必ずこの画面が出る」とは、公式には書かれていません。画面が文章の箇条書きになっても、中身が同じなら正解です
エージェント「先に質問させる」の公式の説明
Claude Code質問のための道具AskUserQuestionがある。公式: "Asks multiple-choice questions to gather requirements or clarify ambiguity."（要件を集めたり、あいまいさをなくすために、選択式の質問をする）。選ぶか、Otherで自分の文章を入力する
Codex CLIPlanモードで確認の質問をする。公式: "Plan mode lets Codex gather context, ask clarifying questions, and build a stronger plan before implementation."。「先に質問してください」と頼む使い方も、公式のベストプラクティスにある
Antigravity CLI（agy）/planは、要件があいまいなときなどに、質問の画面が出る。/grill-meは、最初から1問ずつ聞く。公式: "the agent initiates a focused interview using interactive question prompts and structured options."（/plan）。/grill-meは、おすすめの答えを添えて聞く
  • やってみる（約10分）: startをコピーしてtryを作り、tryで、③で決めた「直したいこと」について、上の例を自分の題材に合わせて書き、エージェントに送る。どんな質問が返ってきたか、自分では考えていなかった質問はあったかを、メモする。選んで、実行してもらい、base（最初の指示）の結果とできあがりがどう違うかを比べる
  • Claude Codeには、「あなたにインタビューして、仕様を書いて」と頼む使い方が、公式のベストプラクティスにある（例: "Interview me until you could write the spec, then write it to SPEC.md."）。仕様がまだ固まっていないときに便利

型②　計画だけ立てさせる（plan モード）（約25分）

  • plan（計画）モードは、Claude Codeの公式の説明では、ファイルを変えずに、まず案だけを出してもらうモード（Codex CLI・agyにも同じ名前のモードがある）。大きな変更や、壊したくないものの前に使う。人が計画を読んで、OKを出してから、実行する
  • 3つのエージェントとも、plan モードがある（公式、確認日 2026-11-05）。切り替えは次のとおり
エージェントplanモードへの入り方（公式）
Claude CodeShift+Tabを押す、または、1回だけなら、指示の先頭に/planを付ける。起動時にclaude --permission-mode planも使える
Codex CLI/plan、またはShift+Tab（公式: "Toggle with /plan or Shift+Tab."）
Antigravity CLI（agy）Shift+Tabで、default → accept-edits → auto → plan の順に切り替わる。起動時はagy --mode=plan
 
（planモードで）この変更の計画を立ててください。
・変えるファイルと、変えない（触らない）ファイル
・手順を、番号つきで
・壊れる可能性があるところと、確かめ方
まだ実行しないでください。
  • やってみる（約15分）: ③の題材で、planモードに入って上の例を送る。出てきた計画を読んで、変えてほしくないファイルが入っていないか、手順が多すぎないかを確かめる。直したい点があれば、計画のまま言葉で直してから、「この計画で実行して」と頼む
  • 型①と型②は、組み合わせると強い。「先に質問してから、計画を立てて」と頼むと、聞く→計画→人がOK→実行の順になる

型③道具で解決できる？と聞く、型④確かめ方を渡す

型③　道具で解決できる？と聞く（CLIとMCP）（約25分）

  • MCPは、公式の定義では、"an open-source standard for connecting AI applications to external systems."（AIアプリを外部のシステムにつなぐための、オープンソースの標準）。公式は、"Think of MCP like a USB-C port for AI applications."（AI用のUSB-Cポートのようなもの）とたとえている（modelcontextprotocol.io、確認日 2026-11-05）
  • CLIについては、Claude Codeの公式のベストプラクティスに、"If that system has a CLI, that's usually the easiest way in."（そのシステムにCLIがあるなら、たいていそれがいちばん簡単な入り口）、例として、ghを入れてログインしていれば、説明しなくても、プルリクエストを開いたり、レビューのコメントを読んだりできる、とある。知らないCLIは、--helpを見せるだけで足りる、とも書かれている。Codex CLIとagyの公式では、同じ趣旨の記述は見つかっていません。同じように使えるかは、試して確かめましょう
  • だから、手作業を始める前に、エージェントに、先に聞く:
この作業（例：Google Cloudのプロジェクト一覧を確認する）は、
gcloud などのCLIや、MCPで、あなたが自分で実行できますか？
できるなら、使う道具と、実行するコマンドを、先に見せてください。
まだ実行しないでください。
エージェントMCPサーバーの足し方（公式）
Claude Codeclaude mcp add --transport http notion https://mcp.notion.com/mcp（公式のベストプラクティスの例）
Codex CLIcodex mcp add context7 -- npx -y @upstash/context7-mcp（公式の例）
Antigravity CLI（agy）/mcpの管理画面か、設定ファイル（全体用は~/.gemini/config/mcp_config.json、プロジェクト用は.agents/mcp_config.json）。agy mcp addのような追加コマンドは、公式に見つかっていません
  • 今日は、新しいMCPサーバーを足しません（接続の作業はしない。Playwright MCPを実際に使うのは、第13回）。上の表は「足し方は、エージェントごとに違う」ことを知るためのもの。MCPには外部のサービスにつなぐ力があるので、よく知らないMCPサーバーは入れない
  • やってみる（約10分）: 自分の題材で、「手作業でやっていること」を1つ探す（例：Neonの中身の確認、GitHubへの反映、ブラウザでの動作確認）。上の例を、自分の作業に書き換えて送る。答えを読んで、実行はしない（コマンドの意味が分かってから実行する）

型④　確かめ方を渡す（約25分）

  • エージェントは、「できました」と答えても、実際には動かないことがある。そこで、合否が出る確かめ方を、指示と一緒に渡す。Claude Codeの公式のベストプラクティスに、"Give Claude something it can run that comes back pass or fail."（実行して、合格か不合格かが返ってくるものを渡す）とある
  • 確かめ方の例: テストを実行する、プログラムを動かして出力を見る、画面のスクリーンショットと見比べる、SQLを実行して件数を見る
  • さらに、実行したコマンドと、その出力を見せてもらう（「証拠」を求める）と、「やったふり」を見分けられる
直したら、確認のため、次のことをしてください。
1. プログラムを実行する（コマンドを教えてください）
2. 出力が「〇〇」になるかを確かめる
実行したコマンドと、出力を、そのまま見せてください。
合わなければ、直して、もう一度確かめてください。
毎回言わなくて済むように：指示ファイル（くわしく）
  • 「確かめ方」や「やってはいけないこと」を、プロジェクトの指示ファイルに書いておくと、毎回の指示に書かなくて済む。エージェントごとに、読むファイルが違う（公式、確認日 2026-11-05）
  • Claude CodeはCLAUDE.md、Codex CLIはAGENTS.md（公式: "Codex reads AGENTS.md files before doing any work."）、Antigravity CLI（agy）はAGENTS.mdまたはGEMINI.md（プロジェクトのフォルダか、その親フォルダに置く）
  • 書く内容の例: 「実行するコマンド（テストの実行など）」「触ってはいけないファイル（.envなど）」「変更したら必ず確かめること」。秘密の値（パスワード、接続文字列）は書かない
  • やってみる（約10分）: ③の題材で、「直したら、こう確かめて」を足した指示を送る。エージェントが確かめ方を実行して、出力を見せてくれたかを確かめる。見せてくれた出力が、本当に合っているかは、自分の目で読む
2限 後半 約30分

自分の題材で4つの型を組み合わせ、変える前と後を比べる

  • ① 組み合わせて試す（約15分）: startをもう一度コピーしてtry2を作る（tryの変更が混ざらないようにするため）。try2のフォルダで、エージェントを新しく起動し直して（baseやtryのときの会話を引き継がない）、1限前半③の「最初の指示」と同じ内容を、4つの型を使って書き直して送る。使う型は、自分で選んでよい（最低2つ）
  • ② 変える前と後を比べる（約8分）: base（最初の指示）とtry2（型を使った指示）を比べて、次の3点を、メモに書く
    • 質問・計画・確認が入ったことで、何が変わったか（できあがり、やり取りの回数、手戻り）
    • 効かなかった型はあったか。なぜか
    • エージェントの答えで、自分の目で確かめたところ
  • ③ 隣の人と、1つずつ見せ合う（約7分）: いちばん効いた指示を、隣の人に見せる。違うエージェントを使っている人の指示は、自分のエージェントでも通じるかを考える
まとめ 約10分

「指示の型カード」を書き、次回を知る

  • 指示の型カードを書く（約5分）。自分が今後も使う指示の言い回しを、4行で残す。次の形を、自分の言葉に直してコピーしておく
① 先に質問：実行する前に、決めることを選択肢つきで質問してください。
② 計画：まず計画だけ出してください。まだ実行しないでください。
③ 道具：これは CLI や MCP で実行できますか？ 使う道具と手順を先に見せてください。
④ 確認：直したら確かめ方を実行して、コマンドと出力をそのまま見せてください。
  • 次回（第9回）：Cloudflare WorkersとD1に触れてみよう——第7回で図だけ見た「ブラウザとDBの間のサーバー」をCloudflare Workersで実際に置き、SQLのデータベースD1にスコアを保存・取得する。Wranglerの操作とコードは、使用中のAIエージェントと、今日の型で進める（授業計画を変更し、Google Cloudは使いません。授業計画一覧）。今日の型は、そのまま使えます
  • 「今日の型のうち、明日からも使うと決めたもの」を一言メモして退出

課題・次回までにやること

必須
