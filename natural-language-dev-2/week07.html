シラバス一覧 / 自然言語開発 II / 第7回

話題のAI製ゲームを、自然言語で再現しよう

Week 7 木曜 3・4限
テーマ
2026年10月に話題のAI製ゲーム『80億分の1』を遊んで仕組みに分解し、そのアイデアだけを借りて、自分の題材を仕様（自然言語）で書いてAIエージェントに作らせる。結果は第6回のNeonに残し、自然言語で集計する
キーワード
『80億分の1』 / 授業用モード / 仕組みを6つの箱に分ける（入力・状態・ルール・データ・出力・保存） / 仕様を1ページで書く / アイデアは自由・コードは写さない / Neonに結果を残す / 間にサーバーを置く理由 / Cloud Run（見るだけ）
必要な準備
自分が使うAIエージェント（Claude Code／Codex CLI／Antigravity CLI）が使える状態のCodespace。ノートPCで1in8b.lifeを開けること。第6回の作業フォルダ（score-dbなど）。今日は、Google Cloudの登録や操作はしません。

この回のゴール

  • 話題のAI製ゲームを遊び、その仕組みを6つの箱（入力・状態・ルール・データ・出力・保存）に分けて、自分の言葉で説明できる
  • アイデアだけを借りて、自分の題材を決め、仕様を1ページで書ける（データには出典を書く）
  • 仕様をAIエージェントに渡して動く最小版を作り、書かれたコードを読んで確かめる
  • 結果をNeonに残し、自然言語で集計して、書かれたSQLを読んで確かめる
  • ブラウザから直接DBへ送らず、間にサーバーを置く理由と、Cloud Runがその置き場所の一つであることを説明できる
今日の進め方: 遊ぶ時間より、仕様を書いて作る時間を長くします。他の人が作ったゲームのプログラム・文章・絵は、そのまま写しません（理由は2限後半で、公式の「ご利用案内」を読んで確かめます）。壊してよいのは、今日作る自分の使い捨てのDBだけです。本物の個人情報には触れないでください。

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

話題のAI製ゲームを遊び、仕組みを6つの箱に分ける

今日の地図と、前回の振り返り（約8分）

  • 第6回では、Neonに一時的なDBを作り、スコアを保存して、自然言語で質問した。今日は、その題材そのものを、話題のAI製ゲームから考える
  • 第6回で作った一時DBは72時間で期限切れになる（第6回のページ）。そのため、2限前半で作り直す

『80億分の1』を遊ぶ（約12分、授業用モード）

  • 『80億分の1』は、公式サイトによると、172か国の実際の統計にもとづく無料の人生シミュレーション（15歳以上、ベータ版）。運営者がAI（Claude）と一緒につくっていると書かれ、数字は国連・世界銀行などの公開統計（80億分の1 公式、2026-10-21確認）。2026年10月5日に公開され、SNSで流行し、フォロワー作品が多数登場している（Game Spark（Yahoo!ニュース配信）、2026-10-19）
  • 授業用モードで開く。最初の画面の下に、「先生ですか？授業では授業用モードで開くをお使いください。重い内容を控えめにし、投稿と支払いを切った画面です。」と書かれている（公式）。公式の「ご利用案内」（ページ名は「利用案内と返金」）には、授業用モードは「先生が一緒に見ながら指導してください」と書かれている（2026年10月19日からの予定の変更として掲載。ご利用案内）。名前や連絡先は入力しない
  • 重い出来事（公式には、死、病気、戦争、貧困、飲酒やギャンブル、薬物依存、家庭内の暴力や性暴力、自殺など）も、実際の統計どおりに起こると書かれている。場面は描かれず、相談先も案内される。過去の世界では、戦争や虐殺のような実際の歴史も出てくる。授業では、「いまの世界」を選ぶ。画面に「怖い場面を除く」の設定があるので、オンにしてから始めてよい。つらくなったら、やめてよく、その場で講師に声をかける。授業用モードで内容がどこまで控えめになるかは、授業前に教員が実画面で確認する
  • 1回の人生は、設定で約30分〜。一時停止や倍速ができる（公式）。最後まで遊ばなくてよい。5歳の「ひと息」（時間が止まって問いが出る場面）まで見て、画面に何が出ているかを観察する

何でできているか、6つの箱に書き出す（約20分）

  • 遊んだ画面を見て、6つの箱を、自分の言葉でノート（メモ）に書き出す。入力（人が選ぶもの）／状態（時間とともに変わる数字）／ルール（何が起きるかを決めるきまり）／データ（元になる数字）／出力（画面に出るもの）／保存（残るもの）
  • 分からない箱は、推測で埋めてよい。「たぶん、○○の数字を使って、○○で決めている」と書く（正解を確かめる必要はない）
  • ページのソースや、ブラウザの開発者ツールで中身を見て、写すことはしない。見えるのは、あくまで画面に出ているものから、仕組みを考える練習
1限 後半 約50分

自分の題材で、仕様を1ページ書き、最小版を作らせる

① 自分の題材を決める（約10分）

  • 借りるのは、アイデアだけ。『80億分の1』のアイデアは、「統計やデータの割合で決まる、ランダムな体験」。題材・名前・文章・絵は、自分のものにする。例: 自作の表（10〜20行）から1つ引く「今日の学食ガチャ」／公開統計（出典を書く）の割合で、ランダムに1つの都道府県を選ぶ
  • データは、自作の小さな表か、出典つきの公開統計にする。本物の個人情報や、特定の人を扱う題材は選ばない。死・事件・病気など、重い題材は選ばない
  • フォロワー作品（『80億分の1』の題材を、別の対象に置き換えただけのもの）と同じにならないように、自分にしか出せない題材を1つ決める

② 仕様を1ページで書く（約15分）

  • 前期の第6回（Spec-Driven Development入門）と同じ考え方で、AIに渡す前に、自分で言葉にする。次の項目を、1項目1〜3行で書く
  • 目的（何を体験できるゲームか）／入力（人が選ぶもの）／ルール（何がどんな割合で起きるか）／データ（元の表。出典を書く）／出力（画面に出るもの）／保存（結果としてDBに残すもの）／やらないこと（今日は作らないもの）
  • 「やらないこと」は大事。最小版に絞るために、ユーザー登録・画像・音・ランキングなどを、あえて外す

③ AIエージェントに渡して、最小版を作らせる（約25分）

  • Codespaceを再開し（第4回と同じ手順）、新しい作業フォルダ（例: my-game）を作って、そこでエージェントを起動する。最初に、.gitignoreに.env・.env.local・node_modulesを書き、空の.envを作っておく（第6回と同じ。書き方が分からなければ、エージェントに頼んでよい）
  • エージェントに、仕様を貼って頼む（例）: 次の仕様で、Node.jsのコマンドで動く最小のゲームgame.jsを書いてください。画面やブラウザは不要です。「node game.js」で1回遊び、結果を文章で表示してください。データは、同じフォルダのdata.jsonに置いてください。（ここに、自分の仕様を貼る）
  • 最小版は、コマンドで動く形にする（ブラウザの画面やポート転送は、今日は使わない。第6回のスコア保存と同じ形）
  • エージェントが書いたコードを、読んでから実行する。ランダムに決める部分と、データを読む部分を探して、自分の仕様と合っているかを確かめる。2回実行して、結果が変わることも確かめる
  • 仕様と違う動きがあれば、何が違うかを言葉にして、追加で指示する（コードを自分で直すより、仕様の言葉を直す）
休憩 10分
2限 前半 約50分

結果をNeonに残し、自然言語で集計して聞く

① Neonを作り直す（約10分）

  • エージェントに頼む: Neonの公式CLI（neon）をインストールして、neon claim create --env-pull を実行して、アカウントなしの一時的なDBを作ってください。.envの中身は表示しないでください（手順の詳しい説明と、うまくいかないときの切り替えは、第6回のページと同じ）
  • 第6回のDBがまだ残っている人は、それを使ってよい（期限は72時間）。.envに値が書かれたことは、変数名だけで確かめる（例: grep -o '^[A-Z_]*=' .env）。値（鍵そのもの）は表示しない
  • .gitignoreに.envが入っているかを、必ず自分で確認する（--env-pullは、.envを入れてくれないことがある。第6回のページ）

② 結果を保存する（約20分）

  • エージェントに頼む（例）: game.jsを、遊んだ結果をNeonに保存するように直してください。resultsテーブル（id・結果の名前・遊んだ日時）を作り、「node game.js」で1回遊んで結果を1件追加してください。「node game.js list」では、何も追加せずに、最近の10件を表示してください。接続は、.envのDATABASE_URLとpgパッケージを使ってください（追加する操作と、見る操作を分けるのは、第6回と同じ理由）
  • 10回ほど遊んで、結果を貯める。新しいターミナルを開いてnode game.js listを実行し、さっきの結果が残っていることを確かめる
  • 保存するのは、ゲームの結果だけ。名前・メールアドレスなどの個人情報は入れない（誰が遊んだかを残したいときは、ニックネームで十分）

③ 自然言語で集計して聞く（約20分）

  • エージェントに頼む（例）: resultsテーブルから、結果ごとの回数と割合を数えて、日本語で答えてください。使ったSQLも見せてください
  • 返ってきたSQLを読む（何を選び（SELECT）、どの表から（FROM）、どうまとめるか（GROUP BY））。読み方は、第6回と同じで、分からない行は、エージェントに聞く
  • 確かめる問い: 自分が仕様に書いた割合と、実際に出た割合は、近いか？10回では、ずれて当たり前。回数を増やすと近づくかを、エージェントに頼んで、100回まわして確かめてもよい（自分の目で、結果と仕様を見比べる）
  • データを変える（追加・消す）依頼は、実行の前に、何を変えるのかを確かめる（第6回と同じ）
2限 後半 約30分

ブラウザからDBへ送る道すじと、再現の作法

① 間にサーバーを置く理由と、Cloud Run（約15分、図と教員の説明）

  • 今日作ったものは、自分のCodespaceからNeonへつないでいる。これを、ブラウザのゲームにするなら、ブラウザは鍵を持てないので、間にサーバーを置いて、サーバーだけが鍵を持つ形にする
  • Cloud Runは、そのサーバーを置く場所の一つ。公式の説明では、「Cloud Run is a fully managed application platform for running your code, function, or container on top of Google's highly scalable infrastructure.」（コード・関数・コンテナを動かすための、フルマネージドのアプリケーション基盤）とされ、既定では、リクエストがないときにインスタンスがゼロまで減る（scale to zero）（What is Cloud Run（Google Cloud公式）、2026-10-21確認）
  • 教員が、小さなサーバーをCloud Runに置く様子を見せる（実施できない場合は、図の説明のみ）。学生は、今日はGoogle Cloudの登録も操作もしない。見て、何をどこに置くのかを理解すればよい
  • 自分の題材を、ブラウザのゲームにするなら、どんなデータを、サーバーに送るかを、1行で書く（個人情報は入れない前提）

② 再現の作法（約8分）

  • 『80億分の1』の「ご利用案内」（項目「人生シミュレーション」）には、次のように書かれている（2026年10月23日からの予定の変更として掲載。ご利用案内、2026-10-21確認）。「80億分の1のプログラム、文章、絵の著作権は運営者にあり、許可なくそのまま写したり、手を加えて配布したり販売したりすることはできません。」（中略）「実際の統計で生まれ、一つの人生を生きてみるといったアイデアは誰のものでもないので、そのアイデアから自分だけの新しい作品をつくるのは自由です。」
  • つまり、アイデアは借りてよい。ただし、プログラム・文章・絵は、そのまま写さない。今日の進め方（画面から推測して、自分の仕様を書く）は、これに沿っている
  • ほかの作品を元にするときの3つの確認: ①規約や権利を読む ②データの出典を書く ③個人情報と、重い題材を扱わない
  • 話題のゲームには、似た作品がすぐ多数出る（Game Sparkの記事）。そのなかで、自分にしか出せない題材と仕様を決めることが、今日のねらい

③ 見せ合う（約7分）

  • 隣の人に、自分の仕様の1ページと、動いた結果を見せる。「仕様のどこが、そのまま動きになったか」と、「仕様と違った部分と、直し方」を、1つずつ話す
  • 接続文字列（.envの中身）は、見せない・送らない（隣の人とDBを共有しない）
まとめ 約10分
