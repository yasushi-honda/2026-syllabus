チームの役割を決める（これまでのチームのまま参加するので、手短に）

心構え（3か条）

  1. 困ったら、早めに声に出す5分悩んだら、チームに共有する（報告・連絡・相談）。何を押して何が表示されたかを、そのまま伝える。
  2. 経験のある人は、初めての人を助ける代わりにやってしまわず、横で見ながら、一緒に進める。
  3. 枠が尽きたら、交代するagyやCodespacesの無料枠が尽きたら、枠に余裕のある人に交代する（交代できるよう、チームのリポジトリや見本のForkには、メンバーを招待しておく。手順は後で行う）。有料プランを自分で使える人（CodexやClaude Codeなど）は、自分で操作して手伝ってよい。アカウントやログイン情報を、他の人に貸すことはしない。

agyの約束事（実際に触るのは2限前半。ここでは考え方だけ共有する）

  • agyとは: 正式名称はAntigravity CLI（アンチグラビティ・シーエルアイ。「agy」はそのコマンド名で、この講座ではagyと呼ぶ）。Googleが提供する、Codespacesのターミナル（文字で操作する画面）で動くAIエージェント。日本語で指示を出すと、コードを書いて直してくれる
  • 使い方の流れ: 入力する人が指示を入力し、確認する人が結果を確認する。うまくいかないときは、表示された内容をそのままagyに伝える
  • 指示は小さく: 1回に1つの変更にする。「全部作り直して」は避ける
  • 無償枠には限りがある: 週単位で回復し、複雑な指示ほど多く消費する。agyの中で /usage と入力すると、残りの枠を確認できる（公式: Plans）。上限に達したら、上の「枠が尽きたら、交代する」

GitHubとCodespacesの基本を知り、全員で一度開いて閉じる

まず言葉を整理する

手順（教員の画面を見ながら、チーム全員で同じ手順を一斉に進める）

  1. 全員: GitHubにログインする登録がまだの人は github.com/signup から新規登録する。登録後、メールの確認（verify）を済ませる。教員が個別にフォローする。
  2. 代表者: チームのリポジトリを作るGitHub右上の「+」→「New repository」を選び、Repository name にチームの名前（例: team-app）を入力する。Privateを選び（本授業ではPrivateにする。APIキー等を誤って公開しないため）、「Add a README file」にチェックを入れて「Create repository」をクリックする（最初のコミットがないと、Codespacesを作る元のブランチがない）。（公式: Creating a new repository）
  3. 代表者: チームのメンバーを招待するリポジトリの「Settings」→「Collaborators」→「Add people」で、メンバーのGitHubアカウントを追加する。招待を受けた人は、届いたメールから承認する。承認が済むと、リポジトリが見えるようになる（公式: Inviting collaborators to a personal repository）。
  4. 全員: 自分のアカウントでCodespacesを開く招待の承認が済み、チームのリポジトリが見えることを確認してから進む。リポジトリを開き、「Code」ボタン→「Codespaces」タブ→「＋」で作る。ブラウザ上にVS Codeの画面が立ち上がれば成功。左にファイル一覧、真ん中にエディタ、下にターミナルがある。作成時のダイアログ下部に「誰が支払うか」のメッセージが出るので確認する。使った時間は、自分のアカウントの無料枠から引かれる（公式: Creating a codespace for a repository）。
  5. 全員: 確認できたらすぐ停止するgithub.com/codespaces を開き、一覧のCodespaceの「…」→「Stop codespace」を選ぶ（公式: Stopping and starting a codespace）。削除はしない。保存した変更は、次に起動したときも残る。代表者がここで作ったCodespacesが、2限でチームが使うものになる。
なぜ全員が開いて閉じるのか: 起動している間は、その人の無料枠の時間が減ります（停止中は、保存領域の分だけ）。開いたらすぐ停止する習慣をつけるためです。もう1つの理由は、代表者のCodespacesの無料枠が尽きたとき、交代要員が自分のアカウントで続けられるようにするためです。

無料枠を確認し、交代要員を決める

  • 各自 github.com/settings/billing の「Codespaces」欄で、今月の使用状況を確認する（公式: GitHub Codespaces billing）。他の授業でも使っている人は、特に注意する
  • GitHub Freeの無料枠は月120コア時間（2-coreマシンなら約60時間）。使い切って支払い方法が未登録だと、Codespacesを新たに起動・再開できなくなる
  • 枠に余裕のあるメンバーを、交代要員として決めておく。止まったときの回避策は、授業概要の「無料枠の注意」を参照する

agyを導入し、見本ゲームをForkして対戦を体験する

ここからは代表者のCodespacesを使う

代表者は、1限後半に作って停止したCodespacesを、github.com/codespaces の一覧からCodespacesの名前をクリックして再開する（停止して再開する練習にもなる）。他のメンバーの練習用Codespacesは、停止したままにしておく。代表者のPC（画面）を使い、キーボードを持つ人を交代しながら、全員が一度はキーボードを持つ。

Antigravity CLI（agy）を導入して認証する

  1. インストールするCodespacesのターミナル（Linux）に次のコマンドを貼り付けてEnter。自分のPCのPowerShellなどには貼らない（公式: Installation & Auth - Antigravity CLI）。 
    curl -fsSL https://antigravity.google/cli/install.sh | bash
    終わったら agy --version と入力してEnter。バージョン番号が表示されれば成功。
  2. 認証するターミナルで agy と入力してEnter。表示された認可URLを、Ctrlキー（Macの場合はCmdキー）を押しながらクリックして新しいタブで開き、Googleアカウントでサインインする。表示された英数字のコードをコピーし、ターミナルに戻って貼り付けてEnter。
  3. 認証できたか確認する話しかけてみて（例: あなたが何をできるか、自己紹介してください）、返事が返ってくれば成功。agyの画面上部（ヘッダー）に、サインインしたアカウントのメールアドレスが表示される。
つまずいたとき: 認可URLが出ない → もう一度 agy と入力する。コードを貼ってもエラー → 前後に余分な空白や改行が入っていないか確認してコピーし直す。時間がかかりすぎる → Ctrl+C で中断して、agy から最初からやり直す。それでも動かなければ手を挙げる。agyの無償枠は週単位で回復し、複雑な指示ほど多く消費します。agyの中で /usage と入力すると、残りの枠を確認できます（公式: Plans）。指示は小さく、1回に1つの変更にしましょう。

見本ゲーム「CYBER TETRIS」をForkして、チームで対戦を体験する

ポート転送を「Public」にすると何ができるのかを、担当教員が用意した見本ゲーム（2人対戦つきのテトリス。原型はagyだけで作成）で体験する。Forkは初めての人が多いので、画面を見ながら1つずつ進める。目安は、agyの導入に約20分、この対戦体験に約30分。

なぜForkするのか: 他の人のリポジトリは、そのままでは自分で書き換えられません（書き込みの権限がないため）。そこで「Fork」を使って、自分のアカウントにコピーを1つ作ります。コピーは自分のものなので、Codespacesで開いて自由に動かしたり、直したりできます。直しても、元の見本ゲームは変わりません。Forkは、GitHubでよく使われる基本の操作です。今日は初めての人が多いので、1つずつ進めます。

  1. 代表者: 見本ゲームのページを開くgithub.com/yas-honda/Tetris を開く（GitHubにログインした状態で）。 
    https://github.com/yas-honda/Tetris
  2. 代表者: Forkするページ右上の「Fork」ボタンをクリックする。「Create a new fork」の画面が出る。「Owner」が自分のアカウントになっていることを確認し、名前は変えずに、緑の「Create fork」をクリックする。自分のアカウントの下に （自分のアカウント名）/Tetris ができ、リポジトリ名の下に「forked from yas-honda/Tetris」と表示されれば成功（公式: Fork a repo）。
  3. 代表者: Forkしたリポジトリにも、チームのメンバーを招待する1限後半と同じ手順で、Forkした自分のTetrisの「Settings」→「Collaborators」→「Add people」から、メンバーのGitHubアカウントを追加する。招待を受けた人は、届いたメールから承認する。無料枠が尽きたときに、別のメンバーが同じ内容で続けたり、改造した変更を引き継いだりできるようにするため（Forkは代表者のアカウントのものなので、招待しないと、他のメンバーは変更を保存できない）。
  4. 代表者: Forkした自分のリポジトリで、Codespacesを作る表示されているのが「yas-honda/Tetris」ではなく自分のアカウントの Tetrisであることを確認する。「Code」ボタン→「Codespaces」タブ→「＋」で作る。1〜2分ほどで、ブラウザ上にVS Codeの画面が立ち上がる（初回は数分かかることがある）。ゲームのサーバーは自動では起動しないので、次の手順で起動する。これは、前のブロックのチームのCodespacesとは別のCodespaces。
  5. 代表者: ターミナルで npm start を実行し、ゲームのサーバーを起動する下のパネルの「ターミナル」タブに、次のコマンドを入力してEnter。 
    npm start
    「CYBER TETRIS Server running on http://localhost:8000」と表示されれば成功。このターミナルは、遊んでいる間ずっと使う（閉じたり、Ctrl+Cを押したりすると、ゲームが止まる）。ほかの作業は、ターミナルの右上の「＋」で新しいターミナルを開いて行う。
  6. 代表者: 「ポート」タブで、8000番をPublicにする下のパネルの「ポート」タブに、8000番（Cyber Tetris Server）が表示される。「表示範囲（Visibility）」は最初Privateなので、必ず手動でPublicに変更する（8000の行を右クリック→「ポートの表示範囲」→「Public」（英語表示の場合は「Port Visibility」）。設定ファイルでは、最初からPublicにはできない）。Publicにするのは、自分のスマートフォンや、チームの他の端末から開けるようにするため。ポートが表示されないときは、前の手順の npm start が動いているかを確認する。
  7. チーム全員: 対戦する8000番の行にある地球儀のアイコン（ブラウザーで開く）をクリックして、ゲーム画面を開く。初めて開くときにGitHubの注意画面が出たら、内容を読んでボタンを押して進む（スマートフォンで開くときも、最初に同じ画面が出る）。「ONLINE BATTLE」→「CREATE ROOM」→「COPY LINK」で招待リンクをコピーし、チームの別の端末（メンバーのスマートフォンやPC）に送って開く。全員が揃ったら、ホストが「START BATTLE」を押す。パソコンはキーボード、スマートフォンは画面のボタンで操作する。
  8. チーム全員: 様子を見て、感想を共有する対戦しない人は、画面を見てもらう。キーボードを持つ人を交代しながら、全員が一度は対戦する。「ブラウザだけで、スマホからも、離れた場所の人とも対戦できる」ことと、これが「ポート転送をPublicにする」仕組みで動いていることを確認する。
  9. 代表者: 使い終わったらCodespacesを停止する2限後半もこのCodespacesを使うチーム（対戦体験の続き・見本のアップデート）は、停止せずに続ける。使い終わったら、必ず停止する（最後の片付けでも確認する）。停止すると公開URLは開けなくなり、無料枠も減らなくなる（github.com/codespaces で、見本ゲーム用のCodespacesの「…」→「Stop codespace」）。
うまくいかないとき: まず手を挙げる。時間がかかりすぎるときは、ゲーム画面をスマートフォンで開くところまでで進めてよい（それだけでも、Publicにすると別の端末から開けることは確認できる）。Publicにしたポートは、URLを知っている人なら誰でも、認証なしで開ける（公式: Forwarding ports in your codespace）。ゲームの中に、個人情報は入力しない。

公開URLは https:// で始まります。

セキュリティを確認し、チームで方向性を選ぶ

セキュリティの確認（全員・約10分）

  • Publicにしたポートは、URLを知っている人なら誰でも、認証なしで開ける（公式: Security in GitHub Codespaces）
  • 公開するものに、個人情報や機微な内容を映さない・入力しない
  • 合言葉やパスコードは、本物のアクセス制限にはならない
  • 使い終わったら、Codespacesを停止する（ポートの公開もやめる）

チームで方向性を選ぶ（約20分）（スキルや進み具合に合わせて、チームごとに違ってよい）

  1. 対戦体験の続き全員が対戦に参加できたかを確認し、ホストとゲストの両方を体験する。キーボードを持つ人を交代しながら、全員が操作する。
  2. 見本ゲームのアップデート見本ゲームを、小さな指示で改造する。例: ブロックの色を青系にしてください。／ライン消去の効果音を変えてください。。1回に1つの変更にして、動くことを確認してから、次へ進む。
  3. 新しい方向性で「最初の動くもの」進級制作への応用か、新しい対戦ゲーム（人生ゲームなど）のうち、作りたい方を決め、最初の1画面を作る。進級制作の課題をAIで解決するワークでもよい（ただし、成果発表では進級制作そのものは発表できない。活かしたい仕組みを取り出した小さなデモを発表の対象にする）。下の指示の例を参考にする。

②（見本のアップデート）でagyを使うとき：見本ゲームのCodespacesには、agyが入っていません。次の手順で入れる。

  1. 新しいターミナルを開くnpm start を動かしているターミナルは、そのままにする。ターミナルの右上の「＋」で、新しいターミナルを開く。
  2. agyを入れる新しいターミナルに、次のコマンドを貼り付けてEnter（1限・2限前半と同じコマンド）。 
    curl -fsSL https://antigravity.google/cli/install.sh | bash
    終わったら agy と入力してEnter。認証を求められたら、2限前半と同じ手順で、Googleアカウントでサインインする。
  3. 小さな指示を出す次の指示を、1つずつ試す。1回に1つだけ頼み、動くことを確認してから、次へ進む。 
    ブロックの色を青系にしてください。
    ライン消去の効果音を変えてください。
    変更したら、ブラウザで開いているゲーム画面を再読み込みして確認する。サーバーを止める必要はない（npm start のターミナルは動かしたまま）。

Day1の選択は仮のものでよい。Day2の冒頭に、あらためてチームで方向性を確定する。対戦体験の続きをしたチームも、Day2では3つの方向性（見本ゲームのアップデート／進級制作への応用／新しい対戦ゲーム）から選べる。「新しい方向性」の最初の1画面は、時間がなければ作らなくてもよい（任意）。

コードを変えた場合は、変更をGitHubに記録する（下の「作って、確認して、記録する」）。見本のアップデートは自分のForkに、新しい方向性はチームのリポジトリに記録する。対戦体験の続きで、コードを変えていないチームは、記録するものがなければ不要。

「新しい方向性」を選んだ場合：最初の1画面を作る

チームで相談して、作りたいものを決める。次のどちらかにする。agyには、いちばん小さな1画面だけを頼む。

  • 今回の体験を、進級制作に活かすための試し（活かしたい仕組みを取り出した、小さなデモ。進級制作の課題をAIで解決するワークでもよい）
  • 新しい対戦ゲーム（Day2に人生ゲームに取り組む予定。今日は、構想を話し合うだけでもよい）
（作りたいもの）を作りたいです。まず、いちばん小さな1画面だけ作ってください。

作って、確認して、記録する

  • 入力する人がagyに指示を入力し、確認する人が結果を確認する。うまくいかないときは、何を押したら何が表示されたかをagyにそのまま伝える
  • ポートの設定は、前のブロックの見本ゲームと同じ（「ポート」タブでPublicにする）。自分たちのアプリは python3 -m http.server 8000 などで動かして確認する
  • できたら、変更をGitHubに記録する。プッシュしないと、Codespacesの中にしか残りません。交代要員が引き継ぐためにも必要

片付けチェック（全員で確認）
