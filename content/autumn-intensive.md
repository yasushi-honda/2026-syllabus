## 8. 授業概要
- 通常の時間割枠に入らない、後期のスピンオフ企画「**AI駆動でのチーム開発体験**」です。**学科横断で参加する既存のチーム**のまま、AIエージェントと協働してアプリを開発します。新しくチームを組み直すことはせず、これまで積み重ねてきたチームワークをそのまま活かします（**唯一の例外**として、個人制作が中心のハード科は、今回に限り **学科で1つのチーム** を新たに編成し、協働する体験を積みます）。
- **学年ごとの位置づけ**: 1年次は自然言語での開発を体験し、まず完成させることを目指します。2年次はAIを活用した短納期でのチーム開発とトラブルシューティングを主導し、自然言語を使った課題解決を目指します。3年次以上は自チームの取り組みを進めながら、**下級生チームのサポートに回り**、教える側の視点で開発の注意点を学びます。
- Day1の見本ゲームの体験をもとに、Day2以降は**チームで方向性を選びます**。選べるのは、**見本ゲームのアップデート**（Antigravity CLI〔agy〕で小さく改造する）、**今回の体験を進級制作に活かす**、**新しい対戦ゲームを作る**（余力のあるチーム向け。Day2は人生ゲーム〔ターン制〕、Day3はボンバーマン〔6人同時〕）の3つです（Day3からは、④を加えた4つ）。Day3からは、昨日の学生の様子を受けて、生成AIのツール（画像から3D・音楽など）・Unity・ゲームのコントローラーなどを取り入れる**④自由に広げる**も選べます（端末・コントローラーの持ち込みは、持っている人はOK）。チームの状況によっては、**進級制作の課題をAIで解決するワーク**に取り組んでもかまいません。ただし成果発表では進級制作そのものは発表できないため、発表の対象は今回の講座で作った成果物にします（進級制作に活かす方向性のチームは、活かしたい仕組みを取り出して試作した**小さなデモ**を、発表の対象にします）。
- **規模の方針**: 1〜5分で成果を見せられる規模を基本とし、複雑なシステムは避けます。新しい機能を増やすことよりも、使える状態に仕上げることを優先します。
- （**全チーム共通の鍵となる事実**）GitHub Codespacesの **ポート転送を「パブリック」に設定するだけで**、追加のクラウド契約なしに **世界中からアクセスできる状態になります**（公式: Security in GitHub Codespaces）。同時対戦も、この標準機能で動かせる場合があります（担当教員が1つのポートでの動作を確認、2026-10-04）。一方で「パブリック」は **認証なしで誰でもアクセスできる** ことも意味するため、公開する場面ではセキュリティの基本もあわせて学びます（詳細は授業計画・履修上の注意点を参照）。
- チームで1つの **GitHub Codespaces** を起動し、**Antigravity CLI（agy）** でAIエージェントに指示を出しながら開発します。各日、**1限はその日の課題、2限＋まとめはチームのブラッシュアップ**に充てます（Day1のみ、環境づくりを含む構成です）。
- **GitHubとCodespacesの扱い方**は、Day1に伝えます。1年次・3年次はGitHubとCodespacesの経験があり、2年次はGitHubの利用経験があります（Codespacesとagyは初めてです）。ハード科は少人数のため、必要に応じて別途フォローします。経験のあるチームは先に進んでかまいません。
- **Codespacesの無料枠** には月間の上限があり、使い切ると開発が止まります。備えと、止まったときの回避策（別のメンバーのアカウントで続ける、チーム内で調整する）は、履修上の注意点にまとめています。
- **agyの無償枠は週単位で回復** し、複雑な指示ほど消費が大きくなります。そのため、動くものを土台に小さな指示で改造していく進め方を基本とします。Codex・Claude Codeなどを自分で使える人は使ってもかまいません。チームで助け合って進めてください。
- **救済レーン**: agyの無償枠が尽きて進めなくなったチームは、教員が声をかけたうえで、**Google AI StudioのBuild**で簡単なアプリを作って共有する進め方に切り替えられます（担当教員が学校のGoogleアカウントで利用できることを確認。2026-10-05。管理者の設定によっては使えない場合があります）。通信対戦ができるかは未検証のため、1台で動くアプリを作って共有するところまでを想定します。通常の選択肢には並べません。
- Day1では、担当教員が用意した **見本ゲーム「CYBER TETRIS」**（2人対戦つきのテトリス。原型は担当教員がagyだけで作成）を使います。代表者のアカウントでForkしてCodespacesで起動し、ポート転送を「パブリック」にして、チームのスマートフォンとPCから実際に対戦します。「自然言語での指示で、ここまで作れる」という実感をチーム全員で共有することが、ねらいです。
- **チームビルディング**として、Day1に役割分担・進め方をすり合わせる時間を取ります。役割は入力する人／確認する人の交代制ですが、**ログインするGitHubアカウントは代表者のまま**（Codespacesは作成者本人しか再開できないため）とし、キーボードを持つ人だけを交代します。
- Day4は、**1年次が巡回する日**です。1年生が4グループに分かれ、1回に1グループずつ、**2年次・3年次以上・ハード科のチームを、30分、自由に回ります**（体験・質問・交流。1限の最初の15分は今日の説明と上級生の準備、そのあと巡回30分・バッファ15分・巡回30分、休憩をはさんで2限も巡回2回とまとめ15分。巡回していない1年生は制作を続けます）。**投票や推薦はしません**。1年生は巡回のふりかえりをフォームで提出し、上級生は見せて、質問に答えます。Day5は、**前半に、Day4の刺激をもとにアップデート**し、**後半に、ハード科・上級生が、どんなアプローチで作ったかを解説**する予定です（詳細は調整中）。作品は **デフォルトパス通りでも、独自の工夫を加えても構いません**。

## 9. 到達目標

### 知識・理解
1. AIエージェント（Antigravity CLI）が、人間の指示をコードに変換して実行する仕組みの概要を理解している。
2. GitHub Codespaces上で動かしたプログラムを、インターネット経由でスマートフォンやPCから開く仕組み（ポート転送）の概要を理解している。
3. （対戦ゲームを作るチーム）複数人でリアルタイムに情報をやり取りする際、1台のサーバー役が全員の操作を受け取り配り直す「サーバー」と「部屋（ルーム）」の基本的な考え方を理解している。
4. GitHub Codespacesのポート転送を「パブリック」に設定するだけで世界中からアクセス可能になる仕組みと、それが「認証なしで誰でもアクセスできる」ことも意味するという、セキュリティ上の注意点を理解している（全チーム共通）。
5. チーム開発における役割分担（入力する人／確認する人）の意味を理解している。

### 思考・判断
1. 通信量やAIエージェントの利用制限、「1〜5分で見せられる規模」という方針の中で、何を作るかを現実的に絞り込める。
2. 自分たちのチームで作りたいものを、実現可能な範囲に分解して計画できる。

### スキル・表現
1. GitHubとCodespacesの基本的な使い方を理解し、自分の手で起動して操作できる。
2. Antigravity CLIに指示を出し、Webアプリを作成・修正できる。
3. 自分たちのチームが選んだ方向性（見本ゲームのアップデート／進級制作への応用／新しい対戦ゲーム）を、AIエージェントと協働で実装し、日ごとに進捗を示せる。（対戦ゲームを作るチーム）複数人の操作をリアルタイムに同期する仕組みを、AIエージェントと協働で組み込める。
4. チームで作ったアプリやゲームを、他チームの端末で実際に動かして見せられる。
5. （1年次）AIエージェントへの指示（プロンプト）を通じて、自然言語による開発の可能性を体験できる。
6. （2年次）チームの実装作業とトラブルシューティングを主導できる。

### 関心・意欲・態度
1. これまでのチームのまま、メンバーと役割を交代しながら協力する姿勢を持つ。
2. うまく動かないときに、AIエージェントに状況を説明し、一緒に解決へ向かう姿勢を持つ。
3. 出来上がったものを他チームに見せ、フィードバックを受け取る姿勢を持つ。
4. （3年次以上）下級生チームのサポートを通じて、教える側の視点で自然言語開発の注意点を捉え直す姿勢を持つ。

## 14. その他（履修上の注意点）
- アプリの公開にはGitHub Codespacesの **ポート転送（Public設定）** を使います（公式: Forwarding ports in your codespace）。Publicにしたポートは **URLを知っている人なら誰でも認証なしでアクセスできます** ——これが授業概要で触れた「全チーム共通の鍵となる事実」の裏返しです。個人情報や機微な内容を映さない・入力しない運用を徹底してください。チームのリポジトリもPublicにするため、APIキー・パスワード・個人情報はコミットしないでください。
- （**対戦ゲームを作るチーム**）静的ファイル配信とWebSocketサーバーは、同じポート1つに載せても動作した実例があります（担当教員がagyとCodespacesで、1つのポートでHTTPとWebSocketを同居させ、対戦の同期を確認、2026-10-04）。接続が不安定なときは、ポートを分けて両方をPublicに設定すると原因を切り分けやすくなります。WebSocketの接続先は **wss://の転送URL** を指定します（`ws://`や`localhost`では他の端末から接続できません）。**パスコードは本物のアクセス制限にはならない** ため、接続数やメッセージ頻度の制限も1つ入れ、想定外の参加者が入ってきた場合の対処（部屋の作り直し等）もチームで決めておきましょう。
- **Antigravity CLI（agy）はGoogleアカウントでの認証のみで追加契約は不要** ですが、無償枠には利用制限があります。公式ドキュメントでは、無償枠は **週単位で回復** し、具体的な回数は公表されていません。使える量はAIが行う作業の量に応じて変わり、簡単な指示ほど多く送れ、複雑な指示ほど多く消費します（公式: Plans、確認日 2026-10-04）。上限は予告なく変わることもあります。枠を大切に使うため、次のことを心がけてください。
  - 指示は小さく、1回に1つの変更にする。「全部作り直して」は避ける。
  - 動いているものを土台にして、部分的に直す。
  - `/usage`で、モデルごとの残りの枠を時々確認する。あるモデルの枠が尽きたら、`/model`で別のモデル（Claudeなど）に切り替えて続ける。

  枠が尽きたときは、無償枠が週単位のため、待っても授業期間中に回復しない場合があります。その場合は、枠に余裕のあるメンバーが交代する、有料の枠を持つ人やCodex・Claude Codeなどを自分で使える人が担当するなど、チーム内で助け合って続けてください。Codespaceを再開したのにagyが反応しない場合は、再認証してください。
- **GitHub Codespacesは個人のGitHubアカウントごとに月120コア時間の無料枠** があります（2-coreマシンでは実質60時間相当。公式: About billing for GitHub Codespaces）。本講座の使用量（代表者のアカウントに15時間程度）は無料枠に収まる見込みですが、他の授業でも使っている場合や、起動したまま放置した場合は消費が増えます。**枠を使い切り、支払い方法も未登録の場合は、Codespacesを新たに起動・再開できなくなり、集中講座の続きが止まります**。
  - 止まる前に（備え）: Day1に、各メンバーの今月の使用状況を確認し、交代要員（予備のアカウント）を決めておく。交代要員がリポジトリにアクセスできるようにしておく。こまめにコミット＆プッシュして作業をリポジトリに残す。使い終わったらCodespaceを停止し、起動したまま放置しない。
  - 止まったら（回避策）: チーム内で調整し、枠に余裕のあるメンバーのアカウントで新しいCodespaceを作って続ける（この場合に限り「5日間同じアカウント」の原則の例外）。元のCodespaceを再開できるのは作成者本人だけのため、新しく作り直す。元の変更は、ブランチにエクスポートして引き継ぐ（公式: 使用がブロックされたときの選択肢の1つ）。新しいCodespaceの使用時間は、作ったメンバーの枠から消費される。新しいCodespaceでは公開URLが変わり、agyの再認証が必要になる場合がある。APIキーなどの設定も確認する。誰のアカウントでも続けられない場合は、担当教員に相談する。
- 各自の端末の通信環境（学校のWi-Fiに接続できるか、モバイル回線の電波状況・データ通信量）は当日までに確認します。
- 体調やメンタル面で不安がある場合は、無理せず担当教員または学校の相談窓口に相談してください。
