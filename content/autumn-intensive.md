## 8. 授業概要
- 通常の時間割枠に入らない、後期のスピンオフ企画です。**学科横断で参加する進級制作チーム**（学科・学年をまたいだ編成のまま）で、AIエージェントと協働してアプリを開発します。新しくチームを組み直すことはせず、進級制作で積み重ねてきたチームワークをそのまま活かします。
- 作るものは3つの選択肢から選びます。**トラックA「カメラ×AI」**（スマートフォンのカメラを使うWebアプリ）、**トラックB「同時対戦ゲーム」**（複数人でリアルタイムに対戦できるゲーム）、**トラックC「自由テーマ」**（AI×端末であれば形式自由の自チーム独自プロダクト）です。トラックA・Bには段階的な日次課題を用意し、トラックCは自チームで段階目標を設定します。
- （**全トラック共通の鍵となる事実**）GitHub Codespacesの **ポート転送を「パブリック」に設定するだけで**、追加のクラウド契約なしに **世界中からアクセスできる状態になります**（公式: Security in GitHub Codespaces）。トラックBの同時対戦も、この標準機能だけで実現できます。一方で「パブリック」は **認証なしで誰でもアクセスできる** ことも意味するため、公開する場面ではセキュリティの基本もあわせて学びます（詳細は授業計画・履修上の注意点を参照）。
- チームで1つの **GitHub Codespaces** を起動し、**Antigravity CLI（agy）** でAIエージェントに指示を出しながら開発します。各日、**1限はトラックごとの段階的なステージ課題、2限＋まとめはチームのブラッシュアップ** に充てます。
- 初めて一緒に作るメンバーもいるため、Day1には **チームビルディング**（役割分担・進め方のすり合わせ）の時間も取ります。役割はドライバー／ナビゲーターの交代制とします。
- Day4に中間デモ、Day5に成果発表会を行い、**他チームの端末で実際に動かしてもらう** ことを目標にします。発表は **デフォルトパス通りでも、独自の工夫を加えても構いません**。

## 9. 到達目標

### 知識・理解
1. （トラックA）ブラウザでカメラ映像を扱うには、通信が暗号化された安全な環境（secure context / HTTPS）が必要であることを理解している。
2. AIエージェント（Antigravity CLI）が、人間の指示をコードに変換して実行する仕組みの概要を理解している。
3. GitHub Codespaces上で動かしたプログラムを、インターネット経由でスマートフォンやPCから開く仕組み（ポート転送）の概要を理解している。
4. （トラックA）AIモデルのAPIキーを、ブラウザ側のコードに書いてはいけない理由を理解している。
5. （トラックB）複数人でリアルタイムに情報をやり取りする際、1台のサーバー役が全員の操作を受け取り配り直す「サーバー」と「部屋（ルーム）」の基本的な考え方を理解している。
6. GitHub Codespacesのポート転送を「パブリック」に設定するだけで世界中からアクセス可能になる仕組みと、それが「認証なしで誰でもアクセスできる」ことも意味するという、セキュリティ上の注意点を理解している（全トラック共通）。
7. チーム開発における役割分担（ドライバー／ナビゲーター）の意味を理解している。

### 思考・判断
1. （トラックA）撮影した映像・画像を扱う際に、誰の同意が必要かを判断できる。
2. 通信量やAIエージェントの利用制限といった制約の中で、何を作るかを現実的に絞り込める。
3. 自分たちのチーム・トラックで作りたいものを、実現可能な範囲に分解して計画できる。

### スキル・表現
1. Antigravity CLIに指示を出し、Webアプリを作成・修正できる。
2. （トラックA）カメラ映像を取得し、画面に表示・加工するプログラムを、AIエージェントと協働で書ける。／（トラックB）複数人の操作をリアルタイムに同期する仕組みを、AIエージェントと協働で組み込める。／（トラックC）自チームで設定した段階目標を、AIエージェントと協働で実装し、日ごとに進捗を示せる。
3. （トラックA）AIエージェント（レシピA・レシピBいずれか）を自分たちのアプリに組み込める。
4. チームで作ったアプリやゲームを、他チームの端末で実際に動かして見せられる。

### 関心・意欲・態度
1. 進級制作チームのまま、学科・学年の違うメンバーと役割を交代しながら協力する姿勢を持つ。
2. うまく動かないときに、AIエージェントに状況を説明し、一緒に解決へ向かう姿勢を持つ。
3. 出来上がったものを他チームに見せ、フィードバックを受け取る姿勢を持つ。

| 日 | テーマ | 主な内容・活動 |

## 14. その他（履修上の注意点）
- （**トラックA**）カメラを使うため、**他人を撮影する場面が発生します**。撮影前に必ず声をかけ、同意を得てください。撮った映像・画像を無断で公開・共有しないでください。レシピB使用時は画像が外部（Google）に送信される旨も伝えてください。
- アプリの公開にはGitHub Codespacesの **ポート転送（Public設定）** を使います（公式: Forwarding ports in your codespace）。Publicにしたポートは **URLを知っている人なら誰でも認証なしでアクセスできます** ——これが授業概要で触れた「全トラック共通の鍵となる事実」の裏返しです。個人情報や機微な内容を映さない・入力しない運用を徹底してください。
- （**トラックB**）静的ファイル配信用とWebSocketサーバー用でポートを分けて転送し、**両方をPublicに設定** してください。WebSocketの接続先は **wss://の転送URL** を指定します（`ws://`や`localhost`では他の端末から接続できません）。パスコードだけに頼らず、接続数やメッセージ頻度の制限も1つ入れましょう。
- （**トラックA**）AIレシピBを使うチームは、**APIキーを必ずサーバ側のコードにのみ置いてください**（ブラウザ側に書くと誰でも見られます）。公開URLを知っていれば誰でも呼び出せてしまうため、**サーバ側でレート制限** も設けましょう。無料APIキーで送信したデータはGoogleのサービス改善に使われる場合があります（公式: Gemini API Additional Terms of Service）。
- 余力があるチームが **レシピC「お喋りAI」（Gemini Live API）** に挑戦する場合も、APIキーの扱いは同じ原則です。公式はサーバ側で発行する一時的なトークン（ephemeral token）の使用を推奨しています。実装難易度が高いため、必須課題としては求めません。
- **Antigravity CLI（agy）はGoogleアカウントでの認証のみで追加契約は不要** ですが、無償枠には利用制限があります。上限に達した場合はチーム内で待つ・使う頻度を調整するなどして対応してください。Codespaceを再開したのにagyが反応しない場合は、再認証してください。
- **GitHub Codespacesは個人のGitHubアカウントごとに月120時間の無料枠** があります（2-coreマシンでは実質60時間相当）。本講座の使用量（1人あたり15時間程度）は無料枠に十分収まりますが、他の授業でも使っている場合は月間の消費量に留意してください。
- 各自の端末の通信環境（学校のWi-Fiに接続できるか、モバイル回線の電波状況・データ通信量）は当日までに確認します。
- 体調やメンタル面で不安がある場合は、無理せず担当教員または学校の相談窓口に相談してください。
