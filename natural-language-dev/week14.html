プロジェクト最終仕上げ①：最終調整・テスト

Week 14 木曜 1・2限
テーマ
第10〜13回で積み上げてきたSDD実践プロジェクトの技術面の仕上げに充てる回。第12回で docs/tech-debt.md に棚卸しした技術的負債と、第13回で docs/responsible-ai-week13.md に記録した先送り事項を、優先度順に実際に潰していく。ドキュメント整備や発表準備は次回（第15回）に譲り、本日は動くもの・テストの質を上げることに集中する
キーワード
docs/tech-debt.md P0/P1消化 / docs/responsible-ai-week13.md 先送り事項の解消 / テストカバレッジ最終確認 / GitHub Project の Done 移動 / npm audit fix / Security タブ再確認 / ADR追記
必要な準備
第10〜13回の成果物一式（spec.md・plan.md・ADR・docs/tech-debt.md・docs/responsible-ai-week13.md）にアクセスできる状態／Antigravity CLI agy セッションが起動できる／GitHub Project の Todo・In progress・Done の現状が分かる状態

この回のゴール

  • docs/tech-debt.md に登録されている項目のうち、優先度P0を全件・P1を最低1件実際に解消し、該当項目を「解消」マークに更新する
  • docs/responsible-ai-week13.md のチェックリストで先送りにした項目を最低1件確認・解消する
  • 第12回で読み直したテストの3軸（coverage / .skip・.todo / フレーク）を再計測し、Before（第12回時点）と比較して改善したかを確認する
  • GitHub Project の In progress に残っているタスクを、可能な範囲で Done まで進める
  • 本日の作業内容と「今回も直しきれなかったもの」を新規ADR（例: docs/adr/0004-week14-final-fixes.md）に記録する

「動くだけでは足りない」を仕上げに変える最終回

ここまでの積み上げ: 第10回（設計）→第11回（実装）→第12回（検証と改善：負債の可視化）→第13回（責任あるAI開発：倫理・規制・著作権のチェック）と重ねてきた。本日は可視化した負債・先送り事項を実際に減らす回。全部を解消する必要はないが、「可視化したものが実際に減った」という体験を1つでも作ることが目的。ドキュメント整備・発表準備は次回（第15回）でまとめて扱う。

授業の流れ

2コマ連続(90分 + 90分 = 計180分)。途中休憩あり。

1限 前半 約40分

残タスクの棚卸し → 本日解消する項目に優先順位を付ける

現状の棚卸し(20分)

  • 各自、以下の3つのドキュメントを開き直し、現状を確認する:
    • docs/tech-debt.md — 第12回で登録した項目。優先度P0/P1がいくつ残っているか数える
    • docs/responsible-ai-week13.md — 第13回のチェックリストで「先送り」にした項目
    • GitHub Project — Todo・In progress に残っているタスクの枚数
  • 近くの人と「残っている項目の数」を1分ずつ報告し合う。多い・少ないで一喜一憂せず、今日どれを潰すかに意識を向ける

本日のゴールを1人ずつ決める(20分)

  • 本日中に解消する項目を具体的に選ぶ基準:
    1. P0（公開前に必ず直す）を最優先で全部選ぶ
    2. P0が無ければP1から1〜2件
    3. 責任あるAI開発（第13回）の先送り事項から1件
  • 選んだ項目を docs/tech-debt.md の該当行にコメントで「本日着手」と印を付ける
今日の合言葉: 「全部直そうとしない、選んだものを確実に終わらせる」。第12回で学んだ負債の3原則（隠さない・忘れない・過剰対応しない）の3つ目がそのまま今日にも当てはまる。
1限 後半 約50分

tech-debt.md の P0/P1 を実装で解消する

負債の解消作業(45分)

  • 選んだ項目ごとに、通常のGitHub Flow（fix/<area>-<short-slug> ブランチ → commit → PR → CI緑 → squash merge）で1件ずつ解消する
  • agy への指示例（第12回で登録した負債を解消する場合）: 
    docs/tech-debt.md の T-002（テストのフレーク疑い）を解消したいです。
routing.test.js を開き、時刻依存・ランダム依存・実行順依存の
3仮説を1つずつ検証してください。原因が特定できたら
修正案を提示し、npm test の結果を貼って Green を確認してから
止まってください。
  • 依存パッケージの脆弱性（第12回 Dependabot alerts / npm audit）でCritical・Highが残っている場合は、npm audit fix を試し、fix後は必ず npm test でGreenを再確認する（依存バージョンアップが挙動を変えることがあるため）
  • 1件解消するごとに、docs/tech-debt.md の該当項目を削除するか「✅ 解消済み（Week14）」に書き換えてcommitする

解消できなかった場合の記録(5分)

  • 時間内に解消しきれなかった項目は、docs/tech-debt.md に「Week14でも着手したが未解消」と正直に追記する。隠さないことが第12回からの一貫した姿勢
休憩 10分
2限 前半 約50分

テストカバレッジを再計測 → Before/After を比較する

テストの3軸を再計測(20分)

  • 第12回で計測した3軸を再度計測し、数字で比較する:
    1. Coverage: npm test -- --coverage（プロジェクトのスクリプト依存）で計測し、第12回の数字と比較
    2. .skip / .todo: grep -rn "\.skip\|\.todo" src/ で件数を再カウント
    3. フレーク: GitHub Actions test.yml の直近実行で色が変わっているテストが残っていないか確認
  • Before（第12回）→ After（本日）の変化を docs/tech-debt.md の末尾か新規メモに1行で残す（例: 「Coverage 62% → 71%、フレーク疑い1件 → 0件」）

GitHub Project を最新状態にする(30分)

  • In progress に残っているタスクを、本日解消できた分だけ Done に移動する
  • 今学期中に着手できないタスクは、Issueに今回は見送りとコメントを残し、postponed ラベル等（プロジェクトの運用に合わせる）を付けてクローズせず保留にする。クローズして忘れるのではなく、保留として記録を残すのが「隠さない」姿勢の実践
  • GitHub Project のスクリーンショットを1枚撮り、後で第15回・第16回の振り返り資料に使えるようにしておく
数字で見る効用: 「頑張った気がする」ではなく、Coverage・件数などの数字の変化で進捗を確認する。数字が悪化していた場合も、それ自体が「なぜ悪化したか」を考える材料になる。
2限 後半 約30分

Security タブを再確認 → 責任あるAI開発の先送り事項を1件解消

Security タブの再確認(15分)

  • 第12回で確認したGitHubの Security タブ（Secret scanning + Dependabot alerts）を開き直し、Critical・Highのアラートが残っていないかを確認する
  • 残っている場合は本日中に対応するか、docs/tech-debt.md にP0として明示的に登録し直す

責任あるAI開発の先送り事項を1件解消(15分)

  • 第13回 docs/responsible-ai-week13.md でチェックが付かなかった項目から1つ選び、実際に確認・修正する（例: 依存ライブラリのライセンス一覧の確認、見慣れないライセンス表記の除去）
  • 解消できたら docs/responsible-ai-week13.md の該当項目にチェックを入れてcommit
まとめ 約10分
