進級制作で Map を使う：Leaflet × ジオコード × 天気 API

Week 9 木曜 1・2限
テーマ
学生リクエストを起点に、進級制作の具体機能としてマップを組み込む実装回。Leaflet + OpenStreetMap で地図を描画し、Open-Meteo Geocoding API で地名→緯度経度を取得、Open-Meteo Forecast API で現在の天気を地図ピンの popup に表示する最小機能を、Antigravity CLI（agy）と協働で 1 ファイル構成（HTML + JS）から組み立てる。React は次回以降の SDD 実践プロジェクトで段階的に検討する
キーワード
Leaflet 1.9.4 / OpenStreetMap タイル / L.map / L.tileLayer / L.marker / L.popup / ジオコーディング（forward） / Open-Meteo Geocoding API / Open-Meteo Forecast API / WMO weather_code / Map ライブラリ選定（Leaflet / Mapbox GL JS / Google Maps Platform）/ AI コーディング 4 作法（完成イメージ先出し／公式 API 仕様の貼り付け／失敗ケースの再現手順／1 ステップずつ）
必要な準備
第8回完了（進級制作リポジトリに .geminiignore / .github/workflows/test.yml / Antigravity CLI agy 環境が揃っている状態）／ブラウザだけで動く HTML+JS の最小構成で進める（フレームワーク不要・React は今回扱わない）／Codespaces 内のターミナルから python3 -m http.server でローカルプレビューを立てる手順を覚えていること（第1〜2回の演習で実施済み）

この回のゴール

  • Leaflet + OpenStreetMap タイルでブラウザに地図を表示できる（緯度経度・ズーム・タイル URL・attribution の役割を 1 行ずつ説明できる）
  • Open-Meteo Geocoding API を fetch() で叩いて、地名（例：「大阪市天王寺区」）から緯度経度・ヒット名・国名を取得できる
  • Open-Meteo Forecast API を fetch() で叩いて、緯度経度から現在の気温（temperature_2m）と天気コード（weather_code）を取得できる
  • 取得した緯度経度に L.marker を立て、bindPopup で「ヒット名 / 気温 / 天気テキスト」を組み立てて表示できる
  • Leaflet / Mapbox GL JS / Google Maps Platform の判断軸（OSS or 商用・API キーの要否・無料枠の有無・利用規約上の制約）を 1 行ずつ説明できる
  • Antigravity CLI（agy）への効果的なプロンプトの 4 作法（① 完成イメージを先に貼る ② 公式 API 仕様を貼り付ける ③ 失敗ケースの再現手順を渡す ④ 1 ステップずつ進める）を、3 段階の実装で自分のセッションで実演できる

Map サービスの全体地図（15分）

  • 地図サービスは 3 つの層に分かれている。まずこれを押さえる:
    1. 地図ライブラリ（ブラウザで地図を描画する JavaScript）: Leaflet / MapLibre GL JS / Mapbox GL JS / Google Maps JS API
    2. タイルサーバー（地図画像の供給元）: OpenStreetMap タイル / MapTiler / Stamen / Carto / Mapbox タイル / Google タイル など
    3. ジオコーディングサービス（地名↔緯度経度の変換 API）: Nominatim（OSM） / Open-Meteo Geocoding / Mapbox Geocoding / Google Geocoding など
  • 地図ライブラリの比較（本日採用 = Leaflet）:
    • Leaflet: BSD-2 ライセンスの OSS、API キー不要、CDN だけで動く、軽量で学習資料が多い。本日採用
    • MapLibre GL JS: BSD-3 ライセンスの OSS。Mapbox GL JS v1 からのフォーク。ベクトルタイル前提で見栄えは良いが、タイルサーバー（MapTiler 等）の準備が要る
    • Mapbox GL JS: 商用ライブラリ（無料枠あり）。アカウント登録 + アクセストークン発行が必要。学生リクエストに直接該当するが、登録手順を 180 分内でやるとそこで時間が消える
    • Google Maps JavaScript API: Google Maps Platform の一部。クレジットカード登録が API キー発行に必要。学校 PC では授業時間内に各自登録するのは現実的でない
  • ジオコーディングサービスの比較（本日採用 = Open-Meteo Geocoding）:
    • Nominatim（OSM 公式）: 無料・キー不要だが、Usage Policy が厳しい（1 req/sec 上限、独自 User-Agent 必須、高頻度利用は自前サーバー推奨）。教材デモなら可だが、本日扱う「ボタンクリックで叩く」スタイルは Usage Policy にギリギリ
    • Open-Meteo Geocoding: GeoNames データベースに基づく無料の地名検索 API。API キー不要・非商用無料・language=ja 対応。同じプロバイダの Forecast API と組み合わせやすい。本日採用
    • Mapbox Geocoding: 商用（無料枠あり）、API キー必要
    • Google Geocoding: 商用、API キー + クレカ必要
  • 「ライブラリ・タイル・ジオコード」の 3 層は組み合わせ自由。今日は Leaflet × OSM タイル × Open-Meteo Geocoding という最小の組み合わせを使うが、本格運用では「Leaflet × MapTiler タイル × Mapbox Geocoding」のような混成構成も普通にあり得る

AI コーディングへの効果的なプロンプトの 4 作法（15分）

  • 学生リクエストの 1 つ「AI を利用したコーディング。AI の正しい使い方。どう指示すれば精度の高いコードを生成してくれるか」をここで言語化する。本日 180 分の実装は、この 4 作法を 1 限後半・2 限前半・2 限後半の 3 段階で実演する場でもある
  • ① 完成イメージを先に貼る（Goal first）
    「住所を入れたら地図にピンが立って popup で天気が見える」のような完成形のスクリーンショットや 1 文の動作仕様を最初に貼る。AI は「何が完成か」を共有できないと、勝手に範囲を広げたり、似て非なるものを作り始める
  • ② 公式 API 仕様を貼り付ける（Spec injection）
    使う API の 公式 docs から該当パラメータ・エンドポイント・レスポンス JSON 例を切り抜いて貼る。AI の中の古い知識（学習時点のスナップショット）より、今このセッションで貼った docs を優先するルールが守られやすい。Open-Meteo は API が安定しているので docs を 5〜10 行貼るだけで十分
  • ③ 失敗ケースの再現手順を渡す（Reproducible failure）
    「コンソールにこのエラーが出た」「このプロンプトを入れたらこの応答が返った」を貼る。AI は「ありそうな原因」を推測で直したがる傾向があるが、再現手順を渡すと「読みに行く」モードに入る。今日は 1 限後半で動かなかったときに 2 限前半で実演する
  • ④ 1 ステップずつ進める（Vertical slice）
    「いきなり全部作って」と頼まない。「まず地図描画だけ」「次に検索 → ピン」「最後に天気 popup」と 3 段階に分けて、各段階でブラウザで動作確認する。これがハルシネーションを抑える最大の作法。180 分のタイムラインそのものが 4 作法 ④ の実演になる
  • 4 作法はカード（手元のメモ・ノート）に書き写す。1 限後半以降の各演習で、自分が出したプロンプトを「4 作法のどれを守れたか」自己採点する
「AI コーディングの正しい使い方」は「指示を磨くこと」: AI に向かって「いい感じに作って」と頼むと、いい感じの幻覚が返ってくる。完成像を先に貼り、公式 docs を貼り、失敗ケースを貼り、1 ステップずつ進めるだけで、同じ AI から返るコードの精度が体感で変わる。今日 180 分はそれを実体験する場でもある。

Open-Meteo Geocoding API で地名 → 緯度経度を取得 → Marker をその地点に立てる

ジオコーディングとは何か（10分）

  • 定義:
    • Forward geocoding: 地名 / 住所 → 緯度経度（今日扱う）
    • Reverse geocoding: 緯度経度 → 地名 / 住所（今日扱わない・進級制作で扱いたい人は宿題）
  • 「住所→緯度経度の辞書」は誰かが集めて公開している: OpenStreetMap / GeoNames / Google / Mapbox など
  • 本日採用する Open-Meteo Geocoding API の前提:
    • データ源は GeoNames（CC-BY ライセンス）
    • API キー不要・非商用無料・language=ja で日本語名対応
    • 同プロバイダの Forecast API と組み合わせる前提で設計されている（学生リクエストの「Open-Meteo に使う位置情報をジオコードで取る」に直接マッチ）
  • 「なぜ Nominatim ではなく Open-Meteo Geocoding か」を 1 行ずつ:
    • Nominatim は OSM 公式ジオコーダーだが、Usage Policy が厳しい（1 req/sec 上限・独自 User-Agent 必須・高頻度利用は自前サーバー推奨）。ボタン連打すると簡単に弾かれる
    • Open-Meteo Geocoding は「Open-Meteo に位置情報を渡すための地名検索」として設計されており、本日のスコープに自然に収まる
    • 進級制作を本格的に運用するなら、商用本格運用なら Mapbox / Google / HERE を比較対象に入れる（料金・SLA・候補リスト UX を比べる）

curl で生のレスポンスを観察する（10分）

  • JS を書く前に、まず素の API レスポンスを見て JSON 構造を把握する。これが 4 作法 ② の現場感覚を養う基礎
  • ターミナルで: 
    curl 'https://geocoding-api.open-meteo.com/v1/search?name=大阪市天王寺区&count=3&language=ja' | jq
  • 観察ポイント:
    • results 配列に id / name / latitude / longitude / country / country_code / population / feature_code / admin1 / postcodes 等が入る
    • 候補が 0 件のときは results キー自体が無い（= undefined）。ここを見落とすと data.results[0] で TypeError
    • language=ja を入れると日本語名がヒットする（市・区・町名は ja 表記に最適化）
    • count を 3 にすると複数候補が見られる（同名地名の曖昧性が体感できる）
  • 「Open-Meteo Geocoding API docs」を 1 タブ開いておく（次のプロンプトに貼る）。一次出典: Open-Meteo — Geocoding API docs

レスポンス (抜粋):

なし (これは新規追加)

# ステップ
1) index.html に <input id="q"> と <button id="go"> を追加
2) app.js にクリックハンドラ
3) fetch して results[0] の latitude/longitude/name/country を取り出す
4) setView + L.marker + bindPopup
5) 2 回目以降は前のマーカーを remove してから新しいマーカーを置く
  • 期待される生成物（app.js に追記）: 
    let marker = null;

document.getElementById('go').addEventListener('click', async () => {
  const name = document.getElementById('q').value.trim();
  if (!name) return;

  const url =
    'https://geocoding-api.open-meteo.com/v1/search'
    + '?name=' + encodeURIComponent(name)
    + '&count=1&language=ja';

  const res = await fetch(url);
  const data = await res.json();

  if (!data.results || data.results.length === 0) {
    alert('見つかりませんでした: ' + name);
    return;
  }

  const hit = data.results[0];
  map.setView([hit.latitude, hit.longitude], 13);

  if (marker) marker.remove();
  marker = L.marker([hit.latitude, hit.longitude])
    .addTo(map)
    .bindPopup(hit.name + ' (' + hit.country + ')')
    .openPopup();
});
  • 動作確認: 「大阪市天王寺区」「東京駅」「札幌」「自分の自宅最寄り駅」を順に入れて、ピンが正しい位置に立つかを目視する

失敗を起こして 4 作法 ③ を実演する（10分）

  • 意図的に失敗させて、再現手順を agy に渡す体験をする:
    • 存在しない地名（例: ahkjsdh） → alert が出ること・コンソールに何が出ているかを観察
    • 「大阪」だけを count=5 で叩く → 大阪市・大阪府・大阪城などが返って「最初の 1 件」が必ずしも意図と一致しないことを観察
  • 2 つ目の体験から「地名が曖昧なときの UX」（候補リスト UI）を発展課題に回せることが分かる。今日は「最初の 1 件で進める」割り切り
  • 「曖昧なときの UX」をその場で AI に丸投げすると、想像で UI を生成し始める。これが 4 作法 ① 「完成イメージを先に」を守らなかった場合の失敗の典型。割り切りを宣言してから実装に進む方が、結果として速い
「最初の 1 件で進める」は技術的な妥協ではなく、設計の意思決定: 候補リスト UI は「やる価値がある機能」だが、180 分の中では「やらない」と決める。「やらないことを明示する」のも進級制作の設計力。決めた割り切りは docs/ に ADR として残しておくと、第10回以降の SDD 実践プロジェクトで再評価できる。

Open-Meteo Forecast API で天気を取得 → Popup に組み込んで完成

Forecast API の最小利用を curl で確認（10分）

  • 2 限前半と同じく、まず素の JSONを観察する: 
    curl 'https://api.open-meteo.com/v1/forecast?latitude=34.6435&longitude=135.5132¤t=temperature_2m,weather_code' | jq
  • 観察ポイント:
    • current フィールドに temperature_2m（地上 2m の気温・摂氏）と weather_code（WMO 標準の天気コード・整数）が入る
    • weather_code は WMO Weather interpretation codes: 0=快晴 / 1〜3=晴れ〜曇り / 45〜48=霧 / 51〜67=雨 / 71〜86=雪 / 95〜99=雷雨 等。詳細表は Open-Meteo docs の下部にある
    • API キー不要・非商用無料
  • 一次出典: Open-Meteo — Weather Forecast API docs

    async function fetchWeather(lat, lon) {
  const url =
    'https://api.open-meteo.com/v1/forecast'
    + '?latitude=' + lat + '&longitude=' + lon
    + '&current=temperature_2m,weather_code';
  const res = await fetch(url);
  const data = await res.json();
  return data.current; // { time, temperature_2m, weather_code, ... }
}

const WMO_TEXT = {
  0: '快晴', 1: '晴れ', 2: '一部曇り', 3: '曇り',
  45: '霧', 48: '着氷霧',
  51: '霧雨', 53: '霧雨 (中)', 55: '霧雨 (強)',
  61: '雨', 63: '雨 (中)', 65: '雨 (強)',
  71: '雪', 73: '雪 (中)', 75: '雪 (強)',
  80: 'にわか雨', 81: 'にわか雨 (中)', 82: 'にわか雨 (強)',
  95: '雷雨', 96: '雷雨と雹', 99: '雷雨と雹 (強)'
};

// クリックハンドラ内 (marker 設置の直前) を以下に差し替え:
const w = await fetchWeather(hit.latitude, hit.longitude);
const wText = WMO_TEXT[w.weather_code]
  ?? ('天気コード ' + w.weather_code);

if (marker) marker.remove();
marker = L.marker([hit.latitude, hit.longitude])
  .addTo(map)
  .bindPopup(
    '<b>' + hit.name + '</b><br>'
    + wText + ' / 気温 ' + w.temperature_2m.toFixed(1) + '°C'
  )
  .openPopup();
  • 動作確認: 「大阪市天王寺区」「東京駅」「札幌」「那覇」を順に入れて、地点ごとに気温と天気が変わることを観察する
