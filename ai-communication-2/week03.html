agyをもっと使いこなす

Week 3 火曜 3・4限
テーマ
公式ベストプラクティス「探索→計画→実行」の進め方、/rewindで安全に試行錯誤する方法、@によるファイル参照、画像を貼り付けて伝える方法など、agyを日々の作業でもっと便利に使うテクニックを学ぶ
キーワード
探索→計画→実行 / スラッシュコマンド / /rewind / @ファイル参照 / 画像貼り付け（ctrl+v）
必要な準備
第1回・第2回で使用したリポジトリ・Codespaces環境にアクセスできる状態（見当たらない場合は担当教員に確認）

この回のゴール

  • 公式ベストプラクティス「探索→計画→実行」の3段階を理解し、実際に使える
  • /rewindで会話を巻き戻せることを知り、安心して試行錯誤できる
  • @キーでファイルを指定しながらagyに指示を出せる
  • ctrl+vで画像を貼り付け、視覚的に伝えられることを知っている

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

「話しかけるだけ」からもう一歩、今日の全体像を知る

前回の振り返り（10分）

  • 第2回で学習ガイドを使い理解した「エージェント型AIとは何か」「なぜagyを使うのか」、そしてCodespacesを開き直して改めてagyに触れたことを思い出す
  • これまでは自然言語で「作って」「教えて」と話しかけるだけだったことを確認する

「もっと便利に使えるはず」という問いかけ（10分）

  • agyには、ただ話しかける以外にも公式が推奨する進め方や便利な操作がいくつも用意されていることを共有する
  • 今日はその中から4つ（探索→計画→実行・スラッシュコマンド・@ファイル参照・画像貼り付け）を体験する

今日の全体像を知る（20分）

  • 前半: 公式ベストプラクティス「探索→計画→実行」を体験する
  • 後半: /rewindで安全に試行錯誤し、@でファイルを指定し、画像を貼り付けて伝える
  • 前回・前々回で使用したリポジトリを開き、停止していたCodespaceを再開（resume）する——「Create codespace」で新規作成しない
  • 第2回で自己紹介ページを作った人は、今日はそのページを育てていく。作っていない・見当たらない人は、agyに「シンプルな自己紹介ページ（index.html）を作って」と依頼するところから始める
1限 後半 約50分

公式ベストプラクティス「探索→計画→実行」を体験する

公式の進め方を知る（10分）

  • Antigravity CLI公式のベストプラクティスには、複雑な依頼は「探索（Exploration）」「計画（Planning）」「実行（Execution）」の3段階に分けるとよいと書かれている（公式: Best Practices — "Explore, plan, then execute"）
  • ①まずコードベースを調べさせる ②実装計画（どのファイルを、どう変更するか）を立てさせる ③その計画を確認・承認してから実行させる、という流れ
  • 公式の例文（意訳）: 「ルーターが/docs/:pageをどう解決しているか調べて。/docs/best-practicesを追加する実装計画を書いて」——調査と計画を先に頼み、実行は別に指示している点がポイント

まず「いきなり実行」を試す（15分）

  • 自己紹介ページ（index.html）に対して、一気に次のように依頼する： 
    好きなものを3つ紹介するセクションを追加して
  • agyがどんな順序で作業するか、応答をよく観察する（何も聞かれずにいきなりファイルが変更される場合が多いはず）

次に「探索→計画→実行」の3段階で試す（25分）

  • 同じような依頼を、今度は3段階に分けて出してみる： 
    ①探索: index.htmlの今の構造を調べて、どんなセクションがあるか教えて
②計画: 好きなものを3つ紹介するセクションを追加する実装計画を立てて
③実行: その計画通りに実行して
  • ②の計画が提示されたら、内容を読んで納得してから③を指示する（気になる点があれば、③の前に「〇〇の部分を変えて」と計画を修正させてもよい）
  • 2つのやり方を比べて、「見通しが立つ」「想定外の変更が起きにくい」等の違いをペアで話し合う
大きな依頼ほど「探索→計画→実行」が効く: 公式ドキュメント（Best Practices）は「自律型ローカルエージェントは、複雑な変更を探索・計画・実行の3段階に分けたときに最も高い精度で動作する」（意訳）と説明しています。簡単な依頼はいきなり実行させてもよいですが、規模が大きい・失敗すると困る依頼ほど、この型を意識してみましょう。
休憩 10分
2限 前半 約50分

スラッシュコマンドで安全に試行錯誤する

?でヘルプ一覧を見る（10分）

  • プロンプト入力欄で?とだけ打つと、使えるスラッシュコマンドの一覧が表示されることを確認する（公式: Using AGY CLI — Quick Tips）
  • 一覧の中から、今日使う/rewindと/clearを見つけておく

/clearで新規セッションを試す（10分）

  • /clearと打つと、会話がリセットされ新しいセッションが始まることを確認する（公式: Using AGY CLI — Quick Tips「Use /clear to clear the prompt and start a new conversation session」）。実際にそれまで作ったファイルが消えるかどうかをlsで自分の手で確かめてみる

/rewindで会話を巻き戻す（20分）

  • まずagyに、わざと大胆な依頼をしてみる： 
    index.htmlの見出しの文字色を全部赤に変えて
  • Simple Browserで結果を確認し、「思っていたのと違う」「やっぱり元に戻したい」と感じたら、/rewind（または/undo）と打つ（公式: Using AGY CLI — Quick Tips「Use /rewind or /undo to rewind the conversation history」）
  • 会話とファイルの変更が、依頼する前の状態に戻ることを確認する

気づきをまとめる（10分）

  • 「/rewindがあると分かって、依頼の仕方はどう変わりそうか」を1つメモに残す
失敗を恐れず試せるのが/rewindの強み: 「変な結果になったらどうしよう」という不安があると、思い切った依頼がしにくくなります。/rewindでいつでも戻せると知っていれば、色々な指示を気軽に試せます。
2限 後半 約30分

@でファイルを指定する／画像で伝える

@でファイルパスを補完しながら指示する（15分）

  • プロンプト入力欄で@と打つと、リポジトリ内のファイル候補が一覧表示されることを確認する（公式: Using AGY CLI — Quick Tips「@ will trigger path suggestions」）
  • @index.htmlのようにファイルを指定してから、「この中の見出しを1つ、絵文字付きに変えて」のように依頼してみる。「どのファイルの話か」をagyに正確に伝えられることを確認する

画像を貼り付けて伝える（15分）

  • Simple Browserで自己紹介ページを表示し、OSのスクリーンショット機能（WindowsはWin+Shift+S、MacはCmd+Shift+4等）で画面の一部を撮ってクリップボードにコピーする
  • agyのプロンプト入力欄にカーソルを合わせ、ctrl+vで貼り付ける（公式: Best Practices — Attaching visual evidence「capture a screenshot or video recording, copy it, and press ctrl+v inside the prompt box to attach it」）
  • 貼り付けた画像を見せながら「この部分のレイアウトをこう変えたい」のように、言葉で説明しにくいことを画像で補う依頼をしてみる
まとめ 約10分
