担当教員

本田 康志

非常勤講師 / ヤススシステム代表

複数の教員で連携して実施します。

AIエージェントと一緒にゼロからアプリを作り上げる特別編です。これまでともに歩んできているチームのまま参加し、それぞれの得意なことを持ち寄りながら進めてください。うまく動かなくても大丈夫です。AIエージェントに状況を説明し、一緒に直していく経験こそがこの講座の一番の狙いです。最後は、自分たちの作ったアプリやゲームを、他のチームに実際に触ってもらいましょう。

授業概要

  • 5日間
    時間割枠外の集中講座
  • 180分／日
    1限90分＋2限・まとめ90分（休憩は枠外）
  • 3つの方向性
    見本のアップデート／進級制作への応用／新しい対戦ゲーム
  • 1〜5分
    成果を見せられる規模（発表の目安）
  • 通常の時間割枠に入らない、後期のスピンオフ企画「AI駆動でのチーム開発体験」です。学科横断で参加する既存のチームのまま、AIエージェントと協働してアプリを開発します。新しくチームを組み直すことはせず、これまで積み重ねてきたチームワークをそのまま活かします（唯一の例外として、個人制作が中心のハード科は、今回に限り学科で1つのチームを新たに編成し、協働する体験を積みます）。
  • 学年ごとの位置づけ: 1年次は自然言語での開発を体験し、まず完成させることを目指します。2年次はAIを活用した短納期でのチーム開発とトラブルシューティングを主導し、自然言語を使った課題解決を目指します。3年次以上は自チームの取り組みを進めながら、下級生チームのサポートに回り、教える側の視点で開発の注意点を学びます。
  • Day1の見本ゲームの体験をもとに、Day2以降はチームで方向性を選びます。選べるのは、見本ゲームのアップデート（Antigravity CLI〔agy〕で小さく改造する）、今回の体験を進級制作に活かす、新しい対戦ゲームを作る（余力のあるチーム向け。Day2は人生ゲーム〔ターン制〕、Day3はボンバーマン〔6人同時〕）の3つです。チームの状況によっては、進級制作の課題をAIで解決するワークに取り組んでもかまいません。ただし成果発表では進級制作そのものは発表できないため、発表の対象は今回の講座で作った成果物にします（進級制作に活かす方向性のチームは、活かしたい仕組みを取り出して試作した小さなデモを、発表の対象にします）。
  • 規模の方針: 1〜5分で成果を見せられる規模を基本とし、複雑なシステムは避けます。新しい機能を増やすことよりも、使える状態に仕上げることを優先します。
  • （全チーム共通の鍵となる事実）GitHub Codespacesのポート転送を「パブリック」に設定するだけで、追加のクラウド契約なしに世界中からアクセスできる状態になります（公式: Security in GitHub Codespaces）。同時対戦も、この標準機能で動かせる場合があります（担当教員が1つのポートでの動作を確認、2026-10-04）。一方で「パブリック」は認証なしで誰でもアクセスできることも意味するため、公開する場面ではセキュリティの基本もあわせて学びます（詳細は授業計画・履修上の注意点を参照）。
  • チームで1つのGitHub Codespacesを起動し、Antigravity CLI（agy）でAIエージェントに指示を出しながら開発します。各日、1限はその日の課題、2限＋まとめはチームのブラッシュアップに充てます（Day1のみ、環境づくりを含む構成です）。
  • GitHubとCodespacesの扱い方は、Day1に伝えます。1年次・3年次はGitHubとCodespacesの経験があり、2年次はGitHubの利用経験があります（Codespacesとagyは初めてです）。ハード科は少人数のため、必要に応じて別途フォローします。経験のあるチームは先に進んでかまいません。
  • Codespacesの無料枠には月間の上限があり、使い切ると開発が止まります。備えと、止まったときの回避策（別のメンバーのアカウントで続ける、チーム内で調整する）は、履修上の注意点にまとめています。
  • agyの無償枠は週単位で回復し、複雑な指示ほど消費が大きくなります。そのため、動くものを土台に小さな指示で改造していく進め方を基本とします。Codex・Claude Codeなどを自分で使える人は使ってもかまいません。チームで助け合って進めてください。
  • 救済レーン: agyの無償枠が尽きて進めなくなったチームは、教員が声をかけたうえで、Google AI StudioのBuildで簡単なアプリを作って共有する進め方に切り替えられます（担当教員が学校のGoogleアカウントで利用できることを確認。2026-10-05。管理者の設定によっては使えない場合があります）。通信対戦ができるかは未検証のため、1台で動くアプリを作って共有するところまでを想定します。通常の選択肢には並べません。
  • Day1では、担当教員が用意した見本ゲーム「CYBER TETRIS」（2人対戦つきのテトリス。原型は担当教員がagyだけで作成）を使います。代表者のアカウントでForkしてCodespacesで起動し、ポート転送を「パブリック」にして、チームのスマートフォンとPCから実際に対戦します。「自然言語での指示で、ここまで作れる」という実感をチーム全員で共有することが、ねらいです。
  • チームビルディングとして、Day1に役割分担・進め方をすり合わせる時間を取ります。役割は入力する人／確認する人の交代制ですが、ログインするGitHubアカウントは代表者のまま（Codespacesは作成者本人しか再開できないため）とし、キーボードを持つ人だけを交代します。
  • Day4はチーム同士で作品を触り合う相互体験、Day5はピックアップ形式の成果発表会（選ばれたチームがデモ実演）を行います。発表はデフォルトパス通りでも、独自の工夫を加えても構いません。

到達目標

知識・理解

  1. AIエージェント（Antigravity CLI）が、人間の指示をコードに変換して実行する仕組みの概要を理解している。
  2. GitHub Codespaces上で動かしたプログラムを、インターネット経由でスマートフォンやPCから開く仕組み（ポート転送）の概要を理解している。
  3. （対戦ゲームを作るチーム）複数人でリアルタイムに情報をやり取りする際、1台のサーバー役が全員の操作を受け取り配り直す「サーバー」と「部屋（ルーム）」の基本的な考え方を理解している。
  4. GitHub Codespacesのポート転送を「パブリック」に設定するだけで世界中からアクセス可能になる仕組みと、それが「認証なしで誰でもアクセスできる」ことも意味するという、セキュリティ上の注意点を理解している（全チーム共通）。
  5. チーム開発における役割分担（入力する人／確認する人）の意味を理解している。

思考・判断

  1. 通信量やAIエージェントの利用制限、「1〜5分で見せられる規模」という方針の中で、何を作るかを現実的に絞り込める。
  2. 自分たちのチームで作りたいものを、実現可能な範囲に分解して計画できる。

スキル・表現

  1. GitHubとCodespacesの基本的な使い方を理解し、自分の手で起動して操作できる。
  2. Antigravity CLIに指示を出し、Webアプリを作成・修正できる。
  3. 自分たちのチームが選んだ方向性（見本ゲームのアップデート／進級制作への応用／新しい対戦ゲーム）を、AIエージェントと協働で実装し、日ごとに進捗を示せる。（対戦ゲームを作るチーム）複数人の操作をリアルタイムに同期する仕組みを、AIエージェントと協働で組み込める。
  4. チームで作ったアプリやゲームを、他チームの端末で実際に動かして見せられる。
  5. （1年次）AIエージェントへの指示（プロンプト）を通じて、自然言語による開発の可能性を体験できる。
  6. （2年次）チームの実装作業とトラブルシューティングを主導できる。

関心・意欲・態度

  1. これまでのチームのまま、メンバーと役割を交代しながら協力する姿勢を持つ。
  2. うまく動かないときに、AIエージェントに状況を説明し、一緒に解決へ向かう姿勢を持つ。
  3. 出来上がったものを他チームに見せ、フィードバックを受け取る姿勢を持つ。
  4. （3年次以上）下級生チームのサポートを通じて、教える側の視点で自然言語開発の注意点を捉え直す姿勢を持つ。

授業計画（全5日）

各日の時間配分は固定です：1限前半40分／1限後半50分／（休憩10分・枠外）／2限前半50分／2限後半30分／まとめ10分（授業合計180分）。1限（90分）はその日の課題（Day2は方向性の決定と最初の制作、Day3は挑戦課題または続き）に取り組む共通の時間枠、2限＋まとめ（90分）はチームごとのブラッシュアップ・自由探究にあてる構成です。チームの状況によっては、この時間を進級制作の課題をAIで解決するワークに充ててもかまいません。ただしDay1だけは、1限を環境づくり（チームの役割決め、心構え、agyの約束事、GitHubとCodespacesの入門）、2限前半をagyの導入と見本ゲームの対戦体験、2限後半をセキュリティの確認とチームごとの方向性の選択にあてます。Day2の冒頭には、チームで方向性（見本ゲームのアップデート／進級制作への応用／新しい対戦ゲーム）を選びます。技術的な詳細・図解は、日別の詳細ページ（Day1は作成済み、以降は作成予定）で扱います。

各日の180分の使い方

  1. 1限 90分その日の課題
    （前半40分＋後半50分）
  2. 休憩10分
  3. 2限＋まとめ 90分チームのブラッシュアップ
    （50分＋30分＋まとめ10分）

授業時間の合計は 90 + 90 = 180分（休憩は含まない）。Day1のみ内訳が異なります（上の説明を参照）。

日 テーマ 主な内容・活動
1チームで参加／環境をつくる講座の狙いと5日間の流れを共有し、チームの役割（代表者・入力する人／確認する人・交代要員）を決める。GitHubとCodespacesの扱い方を学び（1年次・3年次は経験済み、2年次はGitHub経験あり・Codespacesとagyは初めて、ハード科は必要に応じて別途フォロー）、全員が一度Codespacesを開いて閉じる。代表者のアカウントで見本ゲーム「CYBER TETRIS」をForkしてCodespacesを起動し、Antigravity CLI（agy）の導入とポート転送のPublic設定を確認する。確認したら、チームのスマートフォンとPCから対戦を体験し、メンバー全員で様子を見る。agyの残り枠を/usageで確認し、小さな指示で進めるコツも共有する。無料枠の確認も行う。2限後半は、セキュリティを確認したうえで、チームごとに方向性を選ぶ（対戦体験の続き／見本ゲームのアップデート／新しい方向性〔進級制作への応用／新しい対戦ゲーム〕で最初の「動くもの」）。経験のあるチームは先に進んでよい。1日目の終わりに、Googleフォームのアンケートに答える。
2方向性を選ぶ／最初の制作前日の気づきを共有し、1限前半の40分ほどで、チームで方向性（見本ゲームのアップデート／進級制作への応用／新しい対戦ゲーム）を話し合って選ぶ（Day1の選択は仮のもの）。新しい対戦ゲームを選んだチームは、人生ゲーム（ターン制。ボンバーマンより同期する状態が少ない想定）に取り組む。2限はブラッシュアップ。2年次はトラブルシューティングを主導する。
3挑戦する／仕上げるDay3は、チームで挑戦か続きかを決める。余力のあるチームはボンバーマン（6人同時の対戦）に挑戦する。そのほかのチームは、Day2の続き（見本ゲームのアップデート・進級制作への応用・人生ゲームの仕上げ）を進める。進級制作に活かすチームは、活かしたい仕組みを取り出した小さなデモを作る。対戦ゲームを公開するチームは、パブリック公開の確認とパスコード以外の対策を1つ入れる。
4相互体験／つくりこむチーム同士で作品を触り合う相互体験を行い、フィードバックを反映して実装を進める。3年次以上は下級生チームのサポートにも回る。うまく動かない状況をAIエージェントに説明する練習（エラーの伝え方）にも取り組む。
5🎤 成果発表会／仕上げて見せる最終確認と発表準備のあと、ピックアップ形式の成果発表会（1〜5分のデモ実演）。全チームの作品を他チームの端末で実際に動かし合い、振り返る。発表の対象は、見本ゲームのアップデートは改造した見本、進級制作への応用は小さなデモ、新しい対戦ゲームは作ったゲーム。救済レーンのチームは、共有したアプリの画面を見せる程度でよい。

評価方法・基準

完成度そのものより、チームでAIエージェントと協働しながら手を動かし、最後まで作り切ったかを重視します。

25%チーム開発・実装の実践 — 役割を交代しながら、実際に手を動かした度合い。
25%AIエージェントとの協働プロセス — 指示の出し方、うまくいかないときの立て直し方。
20%学年ごとの目標への到達 — 1年次: まず完成させられたか／2年次: 自然言語を使った課題解決とトラブルシューティングを主導できたか／3年次以上: 自チームの取り組みと下級生チームのサポートに取り組めたか。
15%選んだ方向性のコア機能と安全面への配慮 — 選んだ方向性のコア機能（見本ゲームの改良、進級制作への応用の成果（小さなデモ）、対戦ゲームのリアルタイム同期など）と、公開時の安全面（個人情報を映さない・入力しない、パスコード以外の対策、通信量の扱いなど）への配慮を踏まえた実装。
15%相互体験・発表・振り返りの実践 — Day4の相互体験、Day5の振り返りへの取り組み。ピックアップ発表に選ばれたかどうかで評価に差はつけません。

その他（履修上の注意点）

  • アプリの公開にはGitHub Codespacesのポート転送（Public設定）を使います（公式: Forwarding ports in your codespace）。PublicにしたポートはURLを知っている人なら誰でも認証なしでアクセスできます——これが授業概要で触れた「全チーム共通の鍵となる事実」の裏返しです。個人情報や機微な内容を映さない・入力しない運用を徹底してください。チームのリポジトリもPublicにするため、APIキー・パスワード・個人情報はコミットしないでください。
  • （対戦ゲームを作るチーム）静的ファイル配信とWebSocketサーバーは、同じポート1つに載せても動作した実例があります（担当教員がagyとCodespacesで、1つのポートでHTTPとWebSocketを同居させ、対戦の同期を確認、2026-10-04）。接続が不安定なときは、ポートを分けて両方をPublicに設定すると原因を切り分けやすくなります。WebSocketの接続先はwss://の転送URLを指定します（ws://やlocalhostでは他の端末から接続できません）。パスコードは本物のアクセス制限にはならないため、接続数やメッセージ頻度の制限も1つ入れ、想定外の参加者が入ってきた場合の対処（部屋の作り直し等）もチームで決めておきましょう。
  • Antigravity CLI（agy）はGoogleアカウントでの認証のみで追加契約は不要ですが、無償枠には利用制限があります。公式ドキュメントでは、無償枠は週単位で回復し、具体的な回数は公表されていません。使える量はAIが行う作業の量に応じて変わり、簡単な指示ほど多く送れ、複雑な指示ほど多く消費します（公式: Plans、確認日 2026-10-04）。上限は予告なく変わることもあります。枠を大切に使うため、次のことを心がけてください。
    • 指示は小さく、1回に1つの変更にする。「全部作り直して」は避ける。
    • 動いているものを土台にして、部分的に直す。
    • /usageで、モデルごとの残りの枠を時々確認する。あるモデルの枠が尽きたら、/modelで別のモデル（Claudeなど）に切り替えて続ける。
    枠が尽きたときは、無償枠が週単位のため、待っても授業期間中に回復しない場合があります。その場合は、枠に余裕のあるメンバーが交代する、有料の枠を持つ人やCodex・Claude Codeなどを自分で使える人が担当するなど、チーム内で助け合って続けてください。Codespaceを再開したのにagyが反応しない場合は、再認証してください。
  • GitHub Codespacesは個人のGitHubアカウントごとに月120コア時間の無料枠があります（2-coreマシンでは実質60時間相当。公式: About billing for GitHub Codespaces）。本講座の使用量（代表者のアカウントに15時間程度）は無料枠に収まる見込みですが、他の授業でも使っている場合や、起動したまま放置した場合は消費が増えます。枠を使い切り、支払い方法も未登録の場合は、Codespacesを新たに起動・再開できなくなり、集中講座の続きが止まります。備えと回避策は下の図にまとめています。
  • 各自の端末の通信環境（学校のWi-Fiに接続できるか、モバイル回線の電波状況・データ通信量）は当日までに確認します。
  • 体調やメンタル面で不安がある場合は、無理せず担当教員または学校の相談窓口に相談してください。
