秋の集中講座

集中講座（時間割枠外） 全5日間 / 各日180分 学科横断・進級制作チーム単位

担当教員

本田 康志

非常勤講師 / ヤススシステム代表

複数の教員で連携して実施します。

AIエージェントと一緒にゼロからアプリを作り上げる特別編です。進級制作でともに歩んできているチームのまま参加し、それぞれの得意なことを持ち寄りながら進めてください。うまく動かなくても大丈夫です。AIエージェントに状況を説明し、一緒に直していく経験こそがこの講座の一番の狙いです。最後は、自分たちの作ったアプリやゲームを、他のチームに実際に触ってもらいましょう。

授業概要

  • 通常の時間割枠に入らない、後期のスピンオフ企画「AI駆動でのチーム開発体験」です。学科横断で参加する既存の進級制作チームのまま、AIエージェントと協働してアプリを開発します。新しくチームを組み直すことはせず、進級制作で積み重ねてきたチームワークをそのまま活かします。個人制作が中心のハード科は、学科で1つのチームとして協働する体験を積みます。
  • 学年ごとの位置づけ: 1年次は自然言語での開発を体験し、まず完成させることを目指します。2年次はAIを活用した短納期でのチーム開発とトラブルシューティングを主導し、自然言語を使った課題解決を目指します。3年次以上は自チームの取り組みを進めながら、時々下級生チームのサポートに回り、教える側の視点で開発の注意点を学びます。
  • 作るものは3つの選択肢から選びます。トラックA「カメラ×AI」（スマートフォンのカメラを使うWebアプリ）、トラックB「同時対戦ゲーム」（複数人でリアルタイムに対戦できるゲーム）、トラックC「自由テーマ」（AI×端末であれば形式自由の自チーム独自プロダクト）です。トラックA・Bには段階的な日次課題を用意し、トラックCは自チームで段階目標を設定します。チームの状況によっては、進級制作の課題をAIで解決するワークに取り組んでもかまいません。ただし成果発表では進級制作そのものは発表できないため、発表の対象は今回選んだトラックの成果物にします。
  • 規模の方針: 1〜5分で成果を見せられる規模を基本とし、複雑なシステムは避けます。新しい機能を増やすことよりも、使える状態に仕上げることを優先します。
  • （全トラック共通の鍵となる事実）GitHub Codespacesのポート転送を「パブリック」に設定するだけで、追加のクラウド契約なしに世界中からアクセスできる状態になります（公式: Security in GitHub Codespaces）。トラックBの同時対戦も、この標準機能だけで実現できます。一方で「パブリック」は認証なしで誰でもアクセスできることも意味するため、公開する場面ではセキュリティの基本もあわせて学びます（詳細は授業計画・履修上の注意点を参照）。
  • チームで1つのGitHub Codespacesを起動し、Antigravity CLI（agy）でAIエージェントに指示を出しながら開発します。各日、1限はトラックごとの段階的なステージ課題、2限＋まとめはチームのブラッシュアップに充てます。
  • チームビルディングとして、Day1に役割分担・進め方をすり合わせる時間を取ります。役割はドライバー／ナビゲーターの交代制ですが、ログインするGitHubアカウントは代表者のままとし、キーボードを持つ人（ドライバー）だけを交代します。
  • Day4はチーム同士で作品を触り合う相互体験、Day5はピックアップ形式の成果発表会（選ばれたチームがデモ実演）を行います。発表はデフォルトパス通りでも、独自の工夫を加えても構いません。

到達目標

知識・理解

  1. （トラックA）ブラウザでカメラ映像を扱うには、通信が暗号化された安全な環境（secure context / HTTPS）が必要であることを理解している。
  2. AIエージェント（Antigravity CLI）が、人間の指示をコードに変換して実行する仕組みの概要を理解している。
  3. GitHub Codespaces上で動かしたプログラムを、インターネット経由でスマートフォンやPCから開く仕組み（ポート転送）の概要を理解している。
  4. （トラックA）AIモデルのAPIキーを、ブラウザ側のコードに書いてはいけない理由を理解している。
  5. （トラックB）複数人でリアルタイムに情報をやり取りする際、1台のサーバー役が全員の操作を受け取り配り直す「サーバー」と「部屋（ルーム）」の基本的な考え方を理解している。
  6. GitHub Codespacesのポート転送を「パブリック」に設定するだけで世界中からアクセス可能になる仕組みと、それが「認証なしで誰でもアクセスできる」ことも意味するという、セキュリティ上の注意点を理解している（全トラック共通）。
  7. チーム開発における役割分担（ドライバー／ナビゲーター）の意味を理解している。

思考・判断

  1. （トラックA）撮影した映像・画像を扱う際に、誰の同意が必要かを判断できる。
  2. 通信量やAIエージェントの利用制限、「1〜5分で見せられる規模」という方針の中で、何を作るかを現実的に絞り込める。
  3. 自分たちのチーム・トラックで作りたいものを、実現可能な範囲に分解して計画できる。

スキル・表現

  1. Antigravity CLIに指示を出し、Webアプリを作成・修正できる。
  2. （トラックA）カメラ映像を取得し、画面に表示・加工するプログラムを、AIエージェントと協働で書ける。／（トラックB）複数人の操作をリアルタイムに同期する仕組みを、AIエージェントと協働で組み込める。／（トラックC）自チームで設定した段階目標を、AIエージェントと協働で実装し、日ごとに進捗を示せる。
  3. （トラックA）AIエージェント（レシピA・レシピBいずれか）を自分たちのアプリに組み込める。
  4. チームで作ったアプリやゲームを、他チームの端末で実際に動かして見せられる。

関心・意欲・態度

  1. 進級制作チームのまま、メンバーと役割を交代しながら協力する姿勢を持つ。
  2. うまく動かないときに、AIエージェントに状況を説明し、一緒に解決へ向かう姿勢を持つ。
  3. 出来上がったものを他チームに見せ、フィードバックを受け取る姿勢を持つ。
  4. （3年次以上）下級生チームのサポートを通じて、教える側の視点で自然言語開発の注意点を捉え直す姿勢を持つ。

授業計画（全5日）

各日の時間配分は固定です：1限前半40分／1限後半50分／（休憩10分・枠外）／2限前半50分／2限後半30分／まとめ10分（授業合計180分）。1限（90分）はトラックごとの段階的なステージ課題に取り組む共通の時間枠、2限＋まとめ（90分）はチームごとのブラッシュアップ・自由探究にあてる構成です。チームの状況によっては、この時間を進級制作の課題をAIで解決するワークに充ててもかまいません。技術的な詳細・図解は、日別の詳細ページ（作成予定）で扱います。

日 テーマ 主な内容・活動
1進級制作チームで参加／環境をつくる講座の狙いと5日間の流れ、3つのトラック（A: カメラ×AI／B: 同時対戦ゲーム／C: 自由テーマ）を共有し、進級制作チームのまま参加する。チームで1つのリポジトリを作成し、代表者1名のアカウントでGitHub Codespacesを起動する（作成者本人しか再開できないため、5日間同じアカウントで起動・再開する）。チームビルディング（役割分担・進め方のすり合わせ）を行い、Antigravity CLI（agy）とポート転送のPublic設定を確認する。1限のうちに、トラックを選び最初の「動くもの」を1つ作る（トラックAはカメラ表示まで、secure context/HTTPSが必要な理由も確認する。撮影・個人情報の取り扱いルールもここで確認する）。2限は各チームでブラッシュアップ。1日目の終わりに、各チームが学年ごとの完成目標に沿った当日の目標を発表して確定する。

3AIを載せる／みんなで同時に使えるようにする（1限、トラック別のステージ課題）トラックA: （余力があれば）AIレシピB「考えるAI」（Gemini API）を組み込み、APIキーをサーバ側のみに置く・呼び出し回数を制限する・通信量を抑えるという設計原則を学ぶ。トラックB: パスコード付きの「部屋（ルーム）」を使ったリアルタイム同期を組み込み、ポートをパブリックにした瞬間に世界中からアクセス可能になることを確認する。パスコードは本物のアクセス制限にはならないため、それ以外の対策も1つ入れる。ゲーム自体は小さく保つ。トラックC: 次の段階目標に取り組む。2限は仕様を整理してから実装し、最初の動作確認を行う。

評価方法・基準

完成度そのものより、チームでAIエージェントと協働しながら手を動かし、最後まで作り切ったかを重視します。

25%チーム開発・実装の実践 — 役割を交代しながら、実際に手を動かした度合い。
25%AIエージェントとの協働プロセス — 指示の出し方、うまくいかないときの立て直し方。
20%学年ごとの目標への到達 — 1年次: まず完成させられたか／2年次: 自然言語を使った課題解決とトラブルシューティングを主導できたか／3年次以上: 自チームの取り組みと下級生チームのサポートに取り組めたか。
15%トラックのコア機能と安全面への配慮 — 選んだトラックのコア機能（レシピA・Bの検出・応答、またはリアルタイム同期など）と、secure context・通信量・APIキーの扱いなど安全面への配慮を踏まえた実装。
15%相互体験・発表・振り返りの実践 — Day4の相互体験、Day5の振り返りへの取り組み。ピックアップ発表に選ばれたかどうかで評価に差はつけません。

その他（履修上の注意点）

  • （トラックA）カメラを使うため、他人を撮影する場面が発生します（肖像権・個人情報への配慮が必要です）。撮影前に必ず声をかけ、同意を得てください。撮った映像・画像を無断で公開・共有しないでください。レシピB使用時は、画像がGoogleに送信され、無料APIキーでは人間のレビュアーが確認する場合もある旨も伝えてください。
  • アプリの公開にはGitHub Codespacesのポート転送（Public設定）を使います（公式: Forwarding ports in your codespace）。PublicにしたポートはURLを知っている人なら誰でも認証なしでアクセスできます——これが授業概要で触れた「全トラック共通の鍵となる事実」の裏返しです。個人情報や機微な内容を映さない・入力しない運用を徹底してください。
  • （トラックB）静的ファイル配信用とWebSocketサーバー用でポートを分けて転送すると、同一ポートに両方を載せた場合に起きうる接続不安定を避けやすくなります（分ける構成を推奨、両方をPublicに設定）。WebSocketの接続先はwss://の転送URLを指定します（ws://やlocalhostでは他の端末から接続できません）。パスコードは本物のアクセス制限にはならないため、接続数やメッセージ頻度の制限も1つ入れ、想定外の参加者が入ってきた場合の対処（部屋の作り直し等）もチームで決めておきましょう。
  • （トラックA）AIレシピBを使うチームは、APIキーを必ずサーバ側のコードにのみ置いてください（ブラウザ側に書くと誰でも見られます）。ブラウザに持たせる合言葉も通信から取り出せるため本物のアクセス制限にはならず、公開URLを知っていれば誰でも呼び出せてしまうため、サーバ側でレート制限も設けましょう（公式: Gemini API Additional Terms of Service、無料版データはサービス改善に使われる場合あり）。
  • 余力があるチームがレシピC「お喋りAI」（Gemini Live API）に挑戦する場合も、APIキーの扱いは同じ原則です。公式はサーバ側で発行する一時的なトークン（ephemeral token）の使用を推奨しています。実装難易度が高いため、必須課題としては求めません。
  • Antigravity CLI（agy）はGoogleアカウントでの認証のみで追加契約は不要ですが、無償枠には利用制限があります。上限に達した場合はチーム内で待つ・使う頻度を調整するなどして対応してください。Codespaceを再開したのにagyが反応しない場合は、再認証してください。
  • GitHub Codespacesは個人のGitHubアカウントごとに月120時間の無料枠があります（2-coreマシンでは実質60時間相当）。本講座の使用量（代表者のアカウントに15時間程度）は無料枠に十分収まりますが、他の授業でも使っている場合は月間の消費量に留意してください。
  • 各自の端末の通信環境（学校のWi-Fiに接続できるか、モバイル回線の電波状況・データ通信量）は当日までに確認します。
  • 体調やメンタル面で不安がある場合は、無理せず担当教員または学校の相談窓口に相談してください。
