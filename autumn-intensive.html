秋の集中講座

集中講座（時間割枠外） 全5日間 / 各日180分 学科横断・進級制作チーム単位

担当教員

本田 康志

非常勤講師 / ヤススシステム代表

5日間という短い期間で、AIエージェントと一緒にゼロからアプリを作り上げる特別編です。進級制作でともに歩んできたチームのまま参加し、学科・学年の違うメンバーで得意なことを持ち寄りながら進めてください。うまく動かなくても大丈夫です。AIエージェントに状況を説明し、一緒に直していく経験こそがこの講座の一番の狙いです。最後は、自分たちの作ったアプリやゲームを、他のチームに実際に触ってもらいましょう。

授業概要

  • 通常の時間割枠に入らない、後期のスピンオフ企画です。学科横断で参加する進級制作チーム（学科・学年をまたいだ編成のまま）で、5日間かけてAIエージェントと協働してアプリを開発します。新しくチームを組み直すことはせず、進級制作でこれまで積み重ねてきたチームワークをそのまま活かします。
  • 作るものは3つの選択肢から選びます。トラックA「カメラ×AI」は自分たちのスマートフォンのカメラを使うWebアプリ、トラックB「同時対戦ゲーム」は複数人でリアルタイムに対戦できるゲーム、トラックC「自由テーマ」はAI×端末であれば形式自由の自チーム独自プロダクトです。トラックA・Bには段階的な日次課題（デフォルトパス）を用意しており、トラックCのチームもA・Bの課題を参考にしながら自分たちで段階目標を設定します。
  • チームで1つのGitHub Codespacesを起動し、Antigravity CLI（agy）を使ってAIエージェントに指示を出しながら開発します。他の科目（AIコミュニケーション基礎Ⅱ等）と同じ環境なので、操作に迷いにくいのが利点です。Codespacesのポート転送機能で公開したHTTPSのURLを、QRコードでチームメンバーのスマートフォンやPCに配って開きます。
  • 各日とも、1限（90分）は全トラック共通の段階的なステージ課題（その日までに最低限できるようにする内容）、2限＋まとめ（90分）はチームごとのブラッシュアップ・自由探究に充てます。丸投げにせず、日ごとに一歩ずつ前進できる構成です。
  • （トラックA）カメラ映像をブラウザで扱うにはsecure context（HTTPS）が必須です。「なぜHTTPSが要るのか」という制約に触れることが、Day1の重要な学びになります。アプリに載せるAIは2種類から選べます。レシピA「その場で見るAI」は、MediaPipe Tasksを使い手や顔の動きをブラウザ内だけでリアルタイムに検出します（通信ほぼゼロ）。レシピB「考えるAI」は、撮った写真をCodespaces上の簡易サーバ経由でGoogle AI Studio（aistudio.google.com）で発行する無料のGemini APIキーを使ってGemini APIに送り、判定や説明を返します。APIキーは絶対にブラウザ側に置かないという、実務で最も重要な設計原則をここで体験します。あわせて、公開したURLを知っていれば誰でもサーバを呼び出せてしまいます。ブラウザに持たせる合言葉は通信を見れば誰でも取り出せるため本物のアクセス制限にはならないことを確認し、代わりにサーバ側で呼び出し回数の上限（レート制限）を設けるなど、被害を現実的に抑える工夫を一緒に作ります。無料のAPIキーで送信したデータはGoogleのサービス改善に使われ、人間のレビュアーが内容を確認する場合があるため、他人の顔が写った画像を送る際のセキュリティ・プライバシー上の注意点として必ず共有します（公式: Gemini API Additional Terms of Service）。時間に余裕があるチーム向けの発展的な選択肢（レシピC「お喋りAI」）として、Gemini Live APIを使ったリアルタイム音声対話アプリにも挑戦できます。ただしAPIキーをサーバ側で守りながら一時的なトークン（ephemeral token）を発行する、レシピBよりも難易度の高い構成が公式に推奨されているため、必須課題ではなく余力があるチームのみの位置づけとします。
  • （トラックB）複数人でリアルタイムに対戦するには、1台のサーバー役PCが全員の操作を受け取って配り直す構造と、パスコードで対戦グループを区別する「部屋（ルーム）」の仕組みが必要になります（自然言語開発Ⅱの実際の授業で1人の学生がAIエージェントへの指示だけで実装した実例と同じ構造）。AIエージェントに「対戦機能を追加して」のように自然言語で指示しながら組み込みます。GitHub Codespacesのポート転送は複数ポートを同時に転送できるため（公式: Forwarding ports in your codespace）、静的ファイル配信用とWebSocketサーバー用でポートを分ける構成にしておくと、同一ポートに両方を載せた場合に起きうる接続不安定を避けやすくなります。
  • 学生の端末が学校のWi-Fiに接続できない環境も想定し、通信はモバイル回線でも成立する構成（インターネット経由のポート転送）を基本とします。（トラックA）撮影した画像はその場で圧縮してから送るなど、通信量を抑える工夫も学びます。
  • （トラックA）撮影を伴う開発のため、肖像権・個人情報の取り扱いルールをDay1で必ず共有します。
  • Day4に中間デモ、Day5に成果発表会を行い、他チームの端末で実際に動かしてもらうことを目標にします。発表はデフォルトパス通りでも、独自の工夫を加えても構いません。

到達目標

知識・理解

  1. （トラックA）ブラウザでカメラ映像を扱うには、通信が暗号化された安全な環境（secure context / HTTPS）が必要であることを理解している。
  2. AIエージェント（Antigravity CLI）が、人間の指示をコードに変換して実行する仕組みの概要を理解している。
  3. GitHub Codespaces上で動かしたプログラムを、インターネット経由でスマートフォンやPCから開く仕組み（ポート転送）の概要を理解している。
  4. （トラックA）AIモデルのAPIキーを、ブラウザ側のコードに書いてはいけない理由を理解している。
  5. （トラックA）無料のAPIキーで送信したデータが、サービス提供元の改善に使われる場合があることを理解している。
  6. （トラックB）複数人でリアルタイムに情報をやり取りする際、1台のサーバー役が全員の操作を受け取り配り直す「サーバー」と「部屋（ルーム）」の基本的な考え方を理解している。
  7. チーム開発における役割分担（ドライバー／ナビゲーター）の意味を理解している。

思考・判断

  1. （トラックA）撮影した映像・画像を扱う際に、誰の同意が必要かを判断できる。
  2. 通信量やAIエージェントの利用制限といった制約の中で、何を作るかを現実的に絞り込める。
  3. 自分たちのチーム・トラックで作りたいものを、実現可能な範囲に分解して計画できる。

スキル・表現

  1. Antigravity CLIに指示を出し、Webアプリを作成・修正できる。
  2. （トラックA）カメラ映像を取得し、画面に表示・加工するプログラムを、AIエージェントと協働で書ける。／（トラックB）複数人の操作をリアルタイムに同期する仕組みを、AIエージェントと協働で組み込める。
  3. （トラックA）AIエージェント（レシピA・レシピBいずれか）を自分たちのアプリに組み込める。
  4. チームで作ったアプリやゲームを、他チームの端末で実際に動かして見せられる。

関心・意欲・態度

  1. 進級制作チームのまま、学科・学年の違うメンバーと役割を交代しながら協力する姿勢を持つ。
  2. うまく動かないときに、AIエージェントに状況を説明し、一緒に解決へ向かう姿勢を持つ。
  3. 出来上がったものを他チームに見せ、フィードバックを受け取る姿勢を持つ。

授業計画（全5日）

各日の時間配分は固定です：1限前半40分／1限後半50分／（休憩10分・枠外）／2限前半50分／2限後半30分／まとめ10分（授業合計180分）。1限（90分）は全トラック共通の段階的なステージ課題、2限＋まとめ（90分）はチームごとのブラッシュアップ・自由探究にあてる構成です。

日 テーマ 主な内容・活動
1進級制作チームで参加／環境をつくる講座の狙いと5日間の流れ、3つのトラック（A: カメラ×AI／B: 同時対戦ゲーム／C: 自由テーマ）を共有する。チームは新規編成せず、進級制作チームのまま参加する。チームで1つのリポジトリを作成し、代表者1名のアカウントでGitHub Codespacesを起動する（Codespacesは作成者本人しか再開できないため、5日間同じアカウントで起動・再開（resume）し続ける——公式: Opening an existing codespace「You can only open your own codespaces」）。役割はドライバー／ナビゲーターの交代制だが、ログインするGitHubアカウントは代表者のままとし、画面の前でキーボードを持つ人（ドライバー）だけを交代する。Antigravity CLI（agy）を導入し、Codespacesのポート転送をPublicに設定する基本操作を確認する。1限のうちに、トラックを選び最初の「動くもの」を1つ作る——トラックAは自分のスマホでカメラ映像が表示されるところまで（なぜHTTPS/secure contextが必要かも確認）、トラックBは1人で遊べる最小限のゲーム（入力すると何か反応する）まで、トラックCは自チームで決めた最初の一歩まで進める。（トラックA）撮影と個人情報の取り扱いルールをここで確認する。2限は各チームでブラッシュアップ。

評価方法・基準

完成度そのものより、チームでAIエージェントと協働しながら手を動かし、最後まで作り切ったかを重視します。

25%チーム開発・実装の実践 — 役割を交代しながら、実際に手を動かした度合い。
25%AIエージェントとの協働プロセス — 指示の出し方、うまくいかないときの立て直し方。
20%端末連携・入出力の実装 — secure context・通信量への配慮を踏まえた実装（トラックA: カメラ連携／トラックB: 複数端末からの入力同期／トラックC: 自チームの端末連携）。
15%AI機能・リアルタイム機能の組み込み — 選んだトラックのコア機能（レシピA・Bの検出・応答、またはリアルタイム同期など）をアプリに活かせたか。
15%発表・相互フィードバックの実践 — 中間デモ・最終発表への取り組み。

その他（履修上の注意点）

  • （トラックA）カメラを使うアプリを作るため、他人を撮影する場面が発生します。撮影前に必ず声をかけ、同意を得てください。撮った映像・画像を許可なく外部に公開・共有しないでください。レシピB「考えるAI」で撮影した画像をAPIに送る場合、その画像は外部（Google）のサーバに送信されることになるため、同意を得る際はその点も伝えてください。
  • アプリの公開にはGitHub Codespacesのポート転送（Public設定）を使います。「ポート」タブでポートを右クリック→「ポートの可視性」→「パブリック」を選択（公式: Forwarding ports in your codespace）。PublicにしたポートはURLを知っている人なら誰でも認証なしでアクセスできます。個人情報や機微な内容を映さない・入力しない運用を徹底してください。
  • （トラックB）複数ポートを転送する場合、それぞれのポートで個別に可視性（Public/Private）を設定する必要があります。静的ファイル配信用ポートとWebSocketサーバー用ポートの両方をPublicに設定しないと、チームメンバーの端末から接続できません（公式: Forwarding ports in your codespace）。同一ポートにHTTP配信とWebSocketを両方載せる構成は、Web版Codespaces環境で起動直後に接続が不安定になる報告があるため、可能な限りポートを分けることを推奨します。
  • （トラックA）AIレシピB「考えるAI」を使うチームは、Google AI Studio（aistudio.google.com）でGemini APIの無料APIキーを発行します。APIキーはサーバ側のコードにのみ置き、ブラウザ側のコード（HTML・JavaScript）には絶対に書かないでください。ブラウザに書いたキーは誰でも見られる状態になります。それだけでは不十分で、公開URLを知っている人なら誰でもサーバを呼び出せてしまいます。ブラウザに持たせる合言葉（トークン）は、通信を見れば誰でも取り出せてしまうため本物のアクセス制限にはなりません。サーバ側で呼び出し回数の上限（レート制限）を設けるなど、現実的に被害を抑える工夫を一緒に作ってください。対策がないと、他の人にAPIの利用上限を消費されたり、想定外の課金が発生する可能性があります。あわせて、無料のAPIキー（Unpaid Services）で送信したデータはGoogleのサービス改善に使われ、人間のレビュアーが内容を確認する場合があることを公式利用規約（Gemini API Additional Terms of Service）で確認しています。撮影した人物の同意を得る際は、この点もあわせて説明してください。
  • 余力があるチームがレシピC「お喋りAI」（Gemini Live API）に挑戦する場合も、APIキーの扱いはレシピBと同じ原則です。公式はブラウザに直接APIキーを埋め込まず、サーバ側で発行する一時的なトークン（ephemeral token）を使う構成を推奨しています。実装難易度が高いため、必須課題としては求めません。
  • Antigravity CLI（agy）はGoogleアカウントでの認証のみで追加契約は不要ですが、無償枠には利用制限があります。上限に達した場合はチーム内で待つ・使う頻度を調整するなどして対応してください（Google公式）。Codespaceを再開（resume）したのにagyが反応しない場合は、認証セッションが切れている可能性があるため再認証してください（AIコミュニケーション基礎Ⅱ 第2回でも同様の事例あり）。
  • GitHub Codespacesは個人のGitHubアカウントごとに月120時間の無料枠があります（GitHub公式、2-coreマシンでは実質60時間相当）。本講座の使用量（1人あたり5日×180分＝15時間程度）は無料枠に十分収まりますが、他の授業でもCodespacesを使っている場合は月間の消費量が積み重なる点に留意してください。
  • 各自の端末の通信環境（学校のWi-Fiに接続できるか、モバイル回線の電波状況・データ通信量）は当日までに確認します。案内があるまでは各自のデータ通信量に留意してください。
  • 体調やメンタル面で不安がある場合は、無理せず担当教員または学校の相談窓口に相談してください。
