必要な準備
前期から使っているGitHubリポジトリとCodespaces。前期のバグ修正ワークの記録に使ったNOTES.md（またはREADME.md。今のリポジトリに見当たらなければ今日、新しく作る）。AIはCopilot Chat（使える人）かGemini（ブラウザの別タブ）のどちらか

この回のゴール

  • 「エラーが出るバグ」と「エラーが出ないのに動きがおかしいバグ」を見分け、後者はconsole.logで値を見て探せる
  • NaN・数字の連結・リロードで消えるデータ、という3つの症状から、原因の見当をつけられる
  • AIが書いたバグ入りコードを、症状 → 予想 → 確かめる → 直すの順で直せる
  • AIの「答え合わせ」を鵜呑みにせず、直したコードを自分で動かして確かめることができる

調べる4つのステップと、3つの道具（20分）

  • 道具3: DevToolsのApplicationタブ——Local Storageを開くと、localStorageに保存されているキー名と値が見える。見当たらないときは、ConsoleにlocalStorage.getItem("cart")と打てば、保存されている値が返ってくるので確かめられる

練習問題 cart-bug.html の4つのバグを、順に直す

cart-bug.htmlを作る（5分）

  • リポジトリの一番上のフォルダに、新規ファイルcart-bug.htmlを作り、下のコードを貼り付けて保存する。これは「ミニ雑貨店のカート」で、バグが4つ入っている。ここでは、まだ直さない

    <!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>ミニ雑貨店のカート</title>
  <style>
    body { font-family: sans-serif; margin: 0; padding: 16px; }
    li { margin-bottom: 4px; }
  </style>
</head>
<body>
  <h1>ミニ雑貨店</h1>
  <form id="add-form">
    <select id="product">
      <option value="0">マグ（800円）</option>
      <option value="1">ノート（300円）</option>
      <option value="2">ペン（150円）</option>
    </select>
    <input type="number" id="qty" value="1" min="1">
    <button type="submit">カートに入れる</button>
  </form>
  <h2>カート</h2>
  <ul id="cart-list"></ul>
  <p>合計: <span id="total">0</span>円</p>

  <script>
    const products = [
      { name: "マグ", price: 800 },
      { name: "ノート", price: 300 },
      { name: "ペン", price: 150 }
    ];

    function loadCart() {
      const saved = localStorage.getItem("carts");
      if (saved === null) {
        return [];
      }
      return JSON.parse(saved);
    }

    function saveCart() {
      localStorage.setItem("cart", JSON.stringify(cart));
    }

    const cart = loadCart();

    function render() {
      const ul = document.getElementById("cart-list");
      ul.innerHTML = "";
      let total = 0;
      for (let i = 0; i < cart.length; i++) {
        const item = cart[i];
        const li = document.createElement("li");
        li.textContent = item.name + " × " + item.qty + "（" + item.price * item.qty + "円）";
        ul.appendChild(li);
        total = total + item.prise * item.qty;
      }
      document.getElementById("total").textContent = total;
    }

    document.getElementById("add-form").addEventListener("submit", function (e) {
      e.preventDefault();
      const product = products[document.getElementById("product").value];
      const qty = document.getElementById("qty").value;
      let found = null;
      for (let i = 0; i < cart.length; i++) {
        if (cart[i].name === product.name) {
          found = cart[i];
        }
      }
      if (found) {
        found.qty = found.qty + qty;
      } else {
        cart.push({ name: product.name, price: product.price, qty: qty });
      }
      saveCart();
      render();
    };

    render();
  </script>
</body>
</html>
  • Simple Browserのアドレスバーの末尾だけを/cart-bug.htmlに書き換えてEnter。商品を選んで個数を入れ、「カートに入れる」を押してみる
  • 1つ目のバグ（構文エラー）が残っているあいだは、スクリプト全体が動かず、ほかのバグが見えない。1つ目を直したら、番号順に1つずつ進める

症状を見て、順に直す（35分）

  • 各バグは、次の順で進める: 症状を読む → 原因を1行で予想する → 確かめる → 直す。ヒントと答えは折りたたみに入っている。先に自分で考えてから、開く
  • 1つ目の症状: 「カートに入れる」を押しても何も起きない（ページが読み込み直されることがある）。Consoleに赤い文字が出る
    • ヒントを見る

      赤い文字に書かれた行番号とメッセージを読む。メッセージはmissing ) after argument listのような形で、カッコの数が合っていないことを教えている。addEventListener(...)の最後を見る。

    • 答えを見る

      document.getElementById("add-form").addEventListener("submit", function (e) { ... };の最後が};になっている。addEventListener(で開いたカッコを閉じる)が足りないので、});に直す。

  • 2つ目の症状: 商品を入れると、一覧には「マグ × 1（800円）」と出るのに、合計がNaNになる
    • ヒントを見る

      NaNは「数として計算できない」という意味の値（Not a Number）。一覧の金額は合っているのに、合計だけがおかしい。一覧の行と合計の行で、書き方が違うところを探す。render()の中のfor文にconsole.log(item);を足して、itemの中身（プロパティ名）を見る。

    • 答えを見る

      合計の行がitem.priseになっている（priceの打ち間違い）。JavaScriptは、存在しないプロパティを読んでもエラーにせずundefinedを返す。undefined * 1はNaNになる。item.priceに直す。確認できたら、足したconsole.logは消す。

  • 3つ目の症状: マグを「1個」入れたあと、続けて「2個」入れると、3個ではなく「12個」（9600円）になる
    • ヒントを見る

      入力欄から取り出した値は、数字に見えても文字列のことがある。"1" + "2"は"12"になる。フォームから値を取る行にconsole.log("qty:", qty, typeof qty);を足して、typeofの結果を見る。

    • 答えを見る

      .valueで取り出した値は、数字を入れても文字列になる。.valueの部分をNumber()で包んで、数に変換する：

      const qty = Number(document.getElementById("qty").value);

      確認するときは、足し算が合うかを試す（1個のあとに2個を足して、3個になるか）。この時点では4つ目のバグが残っていて、ページを更新するとカートが空に戻る。それは次のバグなので、先に進んでよい。

  • 4つ目の症状: カートに入れて合計も合っているのに、ページを更新（リロード）すると、カートが空に戻る
    • ヒントを見る

      DevToolsのApplicationタブ→Local Storageを見る。データは保存されているか、保存されているならキー名は何か。そのキー名と、loadCart()が探しているキー名を見比べる。

    • 答えを見る

      保存はlocalStorage.setItem("cart", ...)、読み込みはlocalStorage.getItem("carts")になっている。保存と読み込みでキー名が違うので、読み込みが空になる。getItem("cart")に直す。

      直したあと、ConsoleにlocalStorage.getItem("cart")と打って、保存されている値を見る。3つ目のバグが起きていたあいだに保存された古いデータ（個数が文字列のまま）が残っていると、読み込まれて足し算が「12」のようにまたつながり、3つ目が直っていないように見える。その場合はlocalStorage.removeItem("cart")で消し、ページを更新してから、もう一度試す。更新してもカートが残ることを確かめる。

  • 直せたら、4つの症状ごとに「エラーが出た／出なかった」を数える。エラーが出なかったバグが何個あったかを確認する（答え: 3つ）

ペアで振り返る（10分）

  • 隣の人と、「一番見つけにくかったバグはどれか。なぜか」を話し合う
  • 見つけるのに役立った道具（Consoleの赤い文字／console.log／Application）を、バグごとに1つずつ言ってみる
  • 4つ目を直した直後は、3つ目のバグのあいだに保存した古いデータが読み込まれて、症状が続いて見えることがある。バグを直したのに直っていないように見えたら、保存されているデータも疑う
「エラーが出ない」は、いちばん困るバグ: 前期第10回でも書いたとおり、赤い文字が出るバグは、場所を教えてくれる親切なバグです。今日の2つ目〜4つ目のように、動くのに結果がおかしいバグは、自分から値を見に行く必要があります。見に行く道具がconsole.logです。

AIにバグ入りコードを生成させ、読み解いて直す

AIに頼むプロンプトを選んで送る（10分）

  • CodespacesのCopilot Chat（使える人）か、ブラウザの別タブで開いたGemini（gemini.google.com）に、自分が選んだジャンルのプロンプトを貼り付けて送る。Copilotが使えない人は、Geminiだけで進めてよい

  • ゲームを選んだ人のプロンプト

    JavaScriptの学習者向けの練習問題として、わざとバグを3つ入れたHTMLファイルを書いてください。
- <!DOCTYPE html> から </html> までの1ファイルで、40〜60行
- 題材は「ゲームのスコア記録」。名前とスコアを入力するフォームがある
- 記録は「オブジェクトの配列」で持ち、スコアの高い順に一覧で表示する
- localStorageに保存して、ページを更新しても記録が残る
- バグは3つ。そのうち2つ以上は「エラーが出ないのに、動きがおかしい」ものにする
- バグの場所と原因は、私が「答えを見せて」と言うまで教えないでください

  • ECサイトを選んだ人のプロンプト

    JavaScriptの学習者向けの練習問題として、わざとバグを3つ入れたHTMLファイルを書いてください。
- <!DOCTYPE html> から </html> までの1ファイルで、40〜60行
- 題材は「ショップの在庫管理」。商品名・値段・在庫数を入力するフォームがある
- 商品は「オブジェクトの配列」で持ち、一覧で表示する。在庫が0の商品には「売り切れ」と出す。全商品の値段の合計も出す
- localStorageに保存して、ページを更新しても商品が残る
- バグは3つ。そのうち2つ以上は「エラーが出ないのに、動きがおかしい」ものにする
- バグの場所と原因は、私が「答えを見せて」と言うまで教えないでください
  • AIが出したコードを、新規ファイルbug-ai.htmlに貼り付けて保存する。AIが出した<!DOCTYPE html>から</html>までを、そのまま全部貼る
  • 貼ったら、直す前にコピーを取っておく（ペアで交換するとき、バグ入りの元の状態が必要になる）： 
    cp bug-ai.html bug-ai-original.html
  • 同じプロンプトでも、AIの答えは毎回違う。隣の人と内容が違っていてよい。それぞれが自分の問題に取り組む

動かして、症状を探す（15分）

  • Simple Browserのアドレスバーの末尾だけを/bug-ai.htmlに書き換えてEnter。実際に、入力して、追加して、更新して、動きを確かめる
  • Consoleに赤い文字が出ていないかを見る。出ていれば、行番号を手がかりにする
  • 見つけた症状を、次の形でメモする: 「何をしたら ／ 何が起きたか ／ 本当はどうなるはずか」。症状は、バグの数（3つ）より少なく見えたり、多く見えたりしてよい

読み解いて、直す（20分）

  • 症状ごとに、1限後半と同じ4つのステップ（症状 → 予想 → 確かめる → 直す）で進める。予想は、確かめる前に1行で書く
  • 確かめるときに使う道具: console.log(値, typeof 値)／Consoleの赤い文字／ApplicationのLocal Storage
  • 1つ直すたびに、同じ操作でもう一度試す。直したつもりで、ほかの動きを壊していないかも確認する
  • 直せなかった症状は、メモに「分かったこと」だけ残しておく。直せなくても、探した跡は記録になる

答え合わせをする（5分）

  • 自分で直せるところまで進んだら、AIに「答えを見せて」と送る。AIが言ったバグの場所と原因を、自分が見つけたものと照らし合わせる
  • AIの答えも間違うことがある。たとえば、「バグは3つ」と言いながら実際には2つしかない、別の場所を指している、直し方が不十分、などが起こりうる。AIの答えを見たら、直したコードを実際に動かして、症状が消えたかを自分で確かめる
  • 自分の予想とAIの答えがずれた箇所が、いちばんの学びになる。メモしておく
