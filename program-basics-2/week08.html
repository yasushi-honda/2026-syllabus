テーマ
選んだジャンルの土台部分を制作する。ゲーム班は盤面・キャラクター表示、EC班は商品一覧表示。データをオブジェクトの配列で持ち、for文で画面に並べる
キーワード
個人制作 / 土台 / オブジェクトの配列 / for文 / getElementById / createElement / appendChild / データと表示を分ける
必要な準備
前期から使っているGitHubリポジトリとCodespaces。第5回のplan.mdと、第6回のlayout.html（無い人は、今日渡す骨組みから始められる）。AIはCopilot Chat（使える人）かGemini（ブラウザの別タブ）のどちらか

この回のゴール

  • 作品に出てくるもの（ゲームならキャラクター、ECサイトなら商品）をオブジェクトの配列で持てる
  • for文で配列を1件ずつ見て、画面の部品として並べるコードを書ける
  • 配列に1件足すだけで、HTMLを書き換えなくても画面の数が増えることを確かめられる
  • 自分のplan.mdの「4. 持つデータ」に合わせて、データの項目と表示を広げ、pushできる

配列のデータを作り、for文で画面に並べる

① データを書く（10分）

  • 骨組みの<script>の中の、コメントの行を消して、自分のジャンルのデータを書く。nameやicon、priceなどの項目名（プロパティ名）は、第2回のfavoritesと同じ決まりで、名前: 値をカンマで区切る
  • ゲーム班: キャラクターを2体。positionは盤面のどのマスに置くか（0〜5の番号。左上が0、右へ数え、2段目は3から）
  • EC班: 商品を5つ。priceは数字なので、引用符で囲まない（引用符を付けると文字列になり、第7回で見たNaNや文字のつながりの原因になる）

  • ゲーム班のデータ

    const characters = [
  { name: "もぐら", icon: "🐹", position: 1 },
  { name: "うさぎ", icon: "🐰", position: 4 }
];

  • EC班のデータ

    const products = [
  { name: "マグ", price: 800 },
  { name: "ノート", price: 300 },
  { name: "ペン", price: 150 },
  { name: "ふせん", price: 200 },
  { name: "ハサミ", price: 500 }
];

② 配列を画面に並べるコードを書く（25分）

  • データの下に、自分のジャンルのコードを書く（コピーしてよい）。1行ずつ、上の4つの手順のどれかを確認しながら貼り付ける

  • ゲーム班の表示のコード（盤面の6マスを作り、positionが合うマスにキャラクターの絵文字を入れる）

    const board = document.getElementById("board");

for (let i = 0; i < 6; i++) {
  const cell = document.createElement("div");
  cell.className = "hole";

  for (let j = 0; j < characters.length; j++) {
    if (characters[j].position === i) {
      cell.textContent = characters[j].icon;
      cell.title = characters[j].name;
    }
  }

  board.appendChild(cell);
}

    外側のforはマス（0〜5）を1つずつ作り、内側のforは「このマスにいるキャラクターはいるか」を配列から探している。見つけたら、そのマスに絵文字を入れる。

  • EC班の表示のコード（商品1つにつき、商品名と価格が左右に並ぶカードを作る）

    const shop = document.getElementById("shop");

for (let i = 0; i < products.length; i++) {
  const item = document.createElement("div");
  item.className = "item";

  const row = document.createElement("div");
  row.className = "row";

  const name = document.createElement("span");
  name.textContent = products[i].name;

  const price = document.createElement("span");
  price.textContent = `${products[i].price}円`;

  row.appendChild(name);
  row.appendChild(price);
  item.appendChild(row);
  shop.appendChild(item);
}

    priceの行は、第2回のテンプレートリテラル（バッククォートで囲み、${ }で値を埋め込む書き方）。rowは、display: flexで名前と価格を左右に離すための部品（骨組みの<style>に.item .rowとして入っている）。

  • 保存して、Simple Browserを再読み込みする。ゲーム班は6マスの盤面に絵文字が2つ、EC班は商品カードが5枚並べば成功

③ データを増やして、画面が変わるのを確かめる（15分）

  • ゲーム班: キャラクターを1体足す（例: { name: "ねこ", icon: "🐱", position: 5 }）。前の行の末尾にカンマを付けるのを忘れない。保存・再読み込みで、絵文字が3つになる。次に、positionの数を変えて、マスの場所が動くことも確かめる
  • EC班: 商品を1つ足す（例: { name: "えんぴつ", price: 100 }）。前の行の末尾にカンマを付けるのを忘れない。保存・再読み込みで、カードが6枚になる。priceを書き換えて、価格の表示が変わることも確かめる
  • ここで見てほしいのは、HTMLもコードの後半も1文字も変えていないのに、画面が変わったこと。これが「データと表示を分ける」の意味で、第9回の土台になる
  • うまく表示されないときの確認
    • F12でConsoleタブを開き、赤い文字の行番号から見る（第7回の道具1）
    • Cannot set properties of nullやCannot read properties of nullが出たら、getElementById("board")（EC班は"shop"）の名前が、HTMLのidと1文字も違わないかを確かめる
    • Cannot access 'characters' before initialization（productsも同じ）は、データを書いた行が、表示のコードより下にある
    • characters is not definedやproducts is not definedは、スペルが違う
    • Unexpected tokenは、配列のカンマの付け忘れ・付けすぎが多い。要素と要素の間にだけカンマがあり、最後の要素の後ろは付けても付けなくてもよい
    • エラーは出ないのに何も出ないときは、表示のコードの前後にconsole.log(characters.length);（EC班はproducts.length）を書いて、Consoleに件数が出るかを見る（第7回の道具2）

自分の企画に合わせて、データの項目と表示を広げる

plan.mdの「4. 持つデータ」を、配列の項目にする（15分）

  • plan.mdの「4. 持つデータ」と「3. 必要な機能」を見て、自分の作品に必要な項目を1〜2つ選び、配列の各オブジェクトに足す。まだ画面には出さなくてよい。まずデータだけを増やす
  • ジャンル足す項目の例使いみち（次回以降）
    ゲーム班hp: 3（体力）／point: 10（倒したときの点）／color: "pink"当たり判定やスコア計算
    EC班category: "文具"／stock: 5（在庫）／icon: "☕"カート追加、絞り込み
  • これは例で、自分のplan.mdに書いた項目が優先。項目の数も1つで足りる。キャラクターや商品の数も、企画に合わせて増やしてよい

足した項目を、画面にも出す（25分）

  • 足したデータのうち、画面に見えたほうがよいものを1つ選び、表示のコードに反映する。1回に1つだけ変更して、変えるたびに保存・再読み込みで確かめる
  • 考え方の例:
    • ゲーム班: マスの背景色をcolorで変える（cell.style.background = characters[j].color;を、cell.textContentの行の下に足す）。盤面のマス数を6から9に増やす（外側のforの6を9に。ただし.holesは3列なので、3×3になる）
    • EC班: カードにcategoryを出す（spanを1つ作り、textContentに入れて、item.appendChild(...)で足す）。商品の絵文字を名前の前に付ける
  • 書き方が分からないときは、自分で書いた表示のコードの似た行をまねる。createElement → textContent → appendChildの3点セットは、どの部品でも同じ
  • 色や余白など、見た目のCSSは、第6回で書いた<style>の中を直せばよい。今日の主役はデータと表示なので、見た目の細かい調整は後回しでよい
任意: 素材サイトの画像を使って、作品を広げる（早く終わった人向け）
  • 絵文字のかわりに、Webで配られている無料の素材（画像）を使ってよい。必須ではない。先に今日の必須（データを足して画面に出す）を終えてから取り組む

  • 使ってよいサイトは、次の3つ（確認日 2026-11-09。各サイトの説明から要点だけを書いた。規約は変わることがあるので、使う前に自分でも読む）

    サイト公式に書かれている要点使いどころ
    Assets · Kenneyゲーム用の素材がパブリックドメイン（CC0）。クレジット表記は必須ではなく、商用でも使える（Support · Kenney）。迷ったらここゲーム班のキャラクター・マス
    かわいいフリー素材集 いらすとや規約の範囲で、個人・商用を問わず無料。素材を主体にしたコンテンツや商品の再配布・販売は禁止。著作権は放棄されていない（ご利用について | いらすとや）EC班の商品イラスト

  • 守ること
    • 画像はダウンロードして、自分のリポジトリのimagesフォルダに保存する。ほかのサイトの画像のURLを、そのままsrcに貼らない（相手の都合で消えたり、見られた記録が相手に残ったりする）
    • ファイル名は、半角の英数字と-だけにする（例: mogura.png）。日本語や空白があると、公開したときに表示されないことがある
    • 人の顔が写った写真、ロゴ、ブランド名の入った素材は使わない
    • 自分のリポジトリは公開される。素材のファイルそのものを配るための置き場にならないよう、作品の一部として使う

  • 出典メモ: 使った素材ごとに、リポジトリのNOTES.mdへ1行ずつ書く（「どこから持ってきたか」を、あとで言えるようにする）

    ## 使った素材
- images/mogura.png / サイト: Kenney / ライセンス: CC0 / URL: （ダウンロードしたページのURL） / 確認日: （今日の日付）

  • データにimageの項目を足す（ファイル名は自分の画像に合わせる）

    • EC班: { name: "マグ", price: 800, image: "images/mug.png" }

  • ゲーム班の表示: if (characters[j].position === i) { … }の中の2行（cell.textContentとcell.title）を、次の5行に置き換える

          const pic = document.createElement("img");
      pic.src = characters[j].image;
      pic.alt = characters[j].name;
      pic.className = "pic";
      cell.appendChild(pic);

  • EC班の表示: item.className = "item";の次の行に、次の5行を足す（カードの一番上に画像が出る）

      const pic = document.createElement("img");
  pic.src = products[i].image;
  pic.alt = products[i].name;
  pic.className = "pic";

  • <style>の中に、画像がはみ出さないための1行を足す

    .pic { display: block; max-width: 100%; max-height: 100%; }
  • 画像が出ないときは、ファイル名の綴りとフォルダ名（images）、Console（第7回の道具1）のエラーを見る。altは、画像が表示できないときに出る代わりの文で、見えない人にも内容を伝える
  • 画像の保存の操作（Codespacesのエクスプローラーへ画像を入れる方法）は、教員が授業前に実機で確認する。分からないときは、講師に声をかける
