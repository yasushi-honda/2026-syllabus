シラバス一覧 / プログラム基礎 II / 第5回

後期テーマ選択＆企画

Week 5 火曜 1・2限
テーマ
後期に作る作品のジャンル（ゲーム制作かECサイト制作）を選び、企画シート（画面構成・必要な機能の洗い出し）を作る
キーワード
ジャンル選択 / 企画シート / 画面構成 / 機能の洗い出し / 必須とできれば
必要な準備
前期から使っているGitHubリポジトリとCodespaces。予習は必須ではないが、好きなゲームや、よく見るネットショップの画面を思い浮かべておくと選びやすい

この回のゴール

  • ゲーム制作かECサイト制作のどちらかを選び、選んだ理由を自分の言葉で言える
  • 作品の画面構成を、画面ごとに「何を表示するか」として書き出せる
  • 必要な機能を洗い出し、「必須」と「できれば」に分けられる
  • 企画シートをplan.mdとしてリポジトリに保存し、commit・pushできる
  • 企画をAIに見てもらい、指摘ごとに採用・不採用とその理由を記録できる

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

後期のゴールを確認し、2つのジャンルを比べて選ぶ

ここまでの4回と、これからの流れを確認する（10分）

  • 第1回で示した後期のゴールを思い出す——ゲーム制作かECサイト制作を選んで、1つの作品を完成させる
  • 第2〜4回で学んだオブジェクトと配列、フォーム入力、localStorageでの保存は、この作品を作るための部品だったことを確認する
  • 今日は企画の回で、本格的な制作は第8回から始まる。今日決めた企画が、第8・9・11回の「何を作るか」になる

2つのジャンルを比べる（15分）

  • ゲーム制作——ルールを決めて、動かして遊べるものを作る。第8〜11回の流れは次のとおり
    • 第8回: 盤面・キャラクター表示
    • 第9回: 当たり判定・スコア計算
    • 第11回: レベルアップ・タイマー
  • ECサイト制作——商品のデータを並べて見せ、選んだ商品を計算する。第8〜11回の流れは次のとおり
    • 第8回: 商品一覧表示
    • 第9回: カート追加・合計金額計算
    • 第11回: 検索・絞り込み
  • どちらも、第2〜4回の部品を使う。オブジェクトの配列は「キャラクターや商品のデータ」に、フォームは「名前の入力や検索欄」に、localStorageは「ハイスコアやカートの保存」に使える

自分のジャンルを選ぶ（15分）

  • 次の3つの問いに、自分の答えをメモする
    • 作っている途中で、どちらのほうが「続けたい」と思えそうか
    • どちらのほうが、最後まで完成させるイメージが持てるか
    • 完成したら、誰に見せたいか
  • メモをもとに、ジャンルを1つ選ぶ。迷ったら講師に相談する（親ページの履修上の注意点のとおり）
  • 選んだジャンルを、隣の人に「どちらを選んだか」「その理由」の2点だけ伝える
1限 後半 約50分

作品のアイデアを出し、画面構成と必要な機能を書き出す

作りたい作品を出して、1つに絞る（15分）

  • 選んだジャンルで、作りたい作品のアイデアを3つ書き出し、その中から1つ選ぶ
  • 絞るときの基準は「1行で説明できるか」と「第8・9・11回の3回の授業で作れそうな大きさか」の2つ。大きすぎるアイデアは、いちばん面白い部分だけに小さくする
  • 例（ゲーム）: もぐらたたき——穴からもぐらが出てきて、クリックするとスコアが増える
  • 例（ECサイト）: 架空の雑貨店——商品を一覧で見て、カートに入れると合計金額が出る
ECサイトは架空のお店にする: 作品はGitHub Pagesで公開されます。実在のお店やブランドの名前、商品の写真をそのまま使わず、お店の名前も商品も自分で考えたものにしてください。商品の画像は、絵文字や色つきの四角で代用してかまいません。

画面構成を書く（20分）

  • 作品に出てくる画面ごとに「何が表示されるか」と「何を押せるか」を書く。画面が1つだけの作品なら、1つでよい
  • 文字で書く簡単な図でよい。きれいな絵は不要で、どこに何があるかが分かればよい。紙に描いてもよいが、最終的には次の時間のplan.mdに文字で写す
  • 文字で書く図の例（もぐらたたき）: 
    [ もぐらたたき ]
スコア: 3
[穴1] [穴2] [穴3]
[穴4] [穴5] [穴6]
[ はじめる ]
  • 文字で書く図の例（架空の雑貨店）: 
    [ ミニ雑貨店 ]
[ 検索欄 ]
[商品カード] [商品カード] [商品カード]
  名前 / 価格 / [カートに入れる]
カート: 2点  合計 1,200円
  • この図は、第6回（CSS発展：レイアウトを整える）でGrid/Flexboxを使って実際に組む画面の設計図になる

必要な機能を洗い出し、「必須」と「できれば」に分ける（15分）

  • 機能は「ユーザーが何をすると、何が起きるか」の形で書く
    • ゲームの例: 穴をクリックするとモグラが消えて、スコアが1増える
    • ECサイトの例: 「カートに入れる」を押すと、カートの点数と合計金額が増える
  • 書き出した機能を、次の2つに分ける
    • 必須: これがないと作品として成り立たないもの
    • できれば: 時間が余ったら足すもの
  • 分けるときは、第8回で作る部分（ゲームなら盤面・キャラクター表示、ECサイトなら商品一覧表示）が必須の先頭に入っているかを確認する
休憩 10分
2限 前半 約50分

企画シートplan.mdを作り、制作の予定まで書く

Codespacesでplan.mdを作る（10分）

  • 前期から使っているリポジトリをCodespacesで開く（再開でよい）

  • リポジトリの一番上のフォルダに、新規ファイルplan.mdを作り、下の雛形を貼り付けて保存する

    # 後期作品 企画シート

- ジャンル: ゲーム / ECサイト（どちらかを残す）

- このジャンルを選んだ理由:

## 2. 画面構成

| AIの指摘 | 採用 / 不採用 | 理由 |
| --- | --- | --- |
|  |  |  |
  • plan.mdはMarkdownという書き方のメモ用ファイル。見出しは#、箇条書きは-で書く。今日は形式を気にせず、雛形の空欄を埋めればよい

雛形の空欄を埋める（30分）

  • 1限で考えた内容を、上の項目から順に書き写す。足りない部分はここで考えて足す
  • 「4. 持つデータ」は第2回で学んだオブジェクトで考える
    • ゲームの例: キャラクターは{ name: "もぐら", point: 1 }のようにまとめる。あわせて、盤面（例: 6つの穴の並び）やスコアのように、第8・9回で必要になるデータも書く
    • ECサイトの例: 商品は{ name: "マグカップ", price: 600 }のようにまとめる
  • localStorageに保存するものは、第4回で学んだ「保存できる作品」の考え方で決める（例: ハイスコア、カートの中身）。保存するものがなければ「なし」でよい
  • 「5. 制作の予定」は、1限で分けた機能を第8・9・11回に振り分ける。親ページの予定（第8回は基礎機能、第9回はインタラクション、第11回は仕上げ機能）に合わせる

自分でチェックする（10分）

  • 「第8回に最初に作る部分」が、具体的に書けているか
  • 「必須」の機能が、第8・9・11回の授業で作れる量に収まっているか。多すぎると感じたら、いくつかを「できれば」に移す
  • 画面構成に書いたボタンや入力欄が、機能の一覧に1つ以上対応しているか
2限 後半 約30分

AIに企画を見てもらい、指摘を採用・不採用に分けて記録する

AIに企画のレビューを頼む（10分）

  • 前期から使っているAIチャット（Copilot Chatなど）が使える人は、plan.mdの内容を貼り付けて、下の依頼文で見てもらう。先に自分で書いてからAIに見せるのがこの回のルール

    次の企画シートを読んで、次の3点を教えてください。コードは書かないでください。
1. 授業3回分（各180分）で作るには大きすぎる点
2. 抜けている画面や機能
3. 分かりにくい書き方

（ここに plan.md の内容を貼り付ける）
  • AIが使えない人は、隣の人にplan.mdを読んでもらい、同じ3点を口頭で指摘してもらう

指摘を採用するか決めて、理由を記録する（15分）

  • 指摘を1つずつ読み、plan.mdの「6. AIメモ」の表に「採用」か「不採用」と、その理由を書く。不採用でも理由を書く
  • AIは、自分の技術や授業の残り時間を知らない。そのため指摘をそのまま受け入れず、「自分の作品に本当に必要か」「授業で作れるか」で判断する
  • 採用した指摘は、plan.mdの該当する項目も書き直す
  • この記録は、評価の「AIの批判的活用」（採用・不採用の理由が記録されているか）にそのままつながる

commit・pushする（5分）

  • 前期第4回と同じ手順で、plan.mdをcommit・pushする（コミットメッセージ例: 後期作品の企画シートを追加）
  • リポジトリがPublicなら、plan.mdはGitHub上で誰でも読める。名前や連絡先など、公開したくないことは書かない
まとめ 約10分

次回予告と今日の振り返り

  • 次回（第6回）: CSS発展：レイアウトを整える——CSS Grid/Flexboxでゲーム画面や商品一覧など複雑なレイアウトを組む練習。今日書いた画面構成を見ながら進める
  • 今日のキーワード「ジャンル選択」「企画シート」「必須とできれば」を口に出して言えるか確認して退出

課題・次回までにやること

必須
plan.mdを仕上げて、pushする

授業内で書ききれなかった項目は家で埋める。「第8回に最初に作る部分」が具体的に書けている状態にして、push後にGitHub上でplan.mdが見えることを確認する。

推奨
好きなゲーム画面やネットショップの画面を観察する

ボタンや商品カードが「どう並んでいるか」を見ておくと、第6回のレイアウトの練習で組みたい形のイメージを持ちやすい。
