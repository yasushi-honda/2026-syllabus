GitHubの続き＋Codespacesを自分で起動＋agyを導入しよう

Week 3 木曜 1・2限
テーマ
GitHubアカウント登録を完了させ、自分のリポジトリを新規作成してGitHub Codespacesを自分で起動し、Antigravity CLI（agy）を導入して簡単なゲームを作ってもらう
キーワード
GitHub / 新規リポジトリ作成 / GitHub Codespaces / Antigravity CLI（agy）/ 認証 / AIエージェント
必要な準備
第2回で準備したGitHubアカウント（ログインできる状態）。まだ登録・確認が終わっていない人は、今日の1限前半で個別にフォローするのでそのまま来てください。

この回のゴール

  • 前回終わらなかったGitHubアカウント登録を完了し、全員がログインできる状態にする
  • 自分のGitHubアカウントに新しいリポジトリを作成する
  • GitHub Codespacesを自分の手で起動する
  • Codespaces上にAntigravity CLI（agy）をインストール・認証する
  • agyに自然言語で簡単なゲームを作ってもらい、「指示したら形になった」を体験する
今日の優先順位: agyはGoogleアカウントでの認証まで済ませて初めて使えるようになりますが、この認証がGitHub登録と同じくらいつまずきやすいポイントです。今日は/modelや/usageといった細かい使い方は扱いません。「認証を突破して、まず1回動かしてみる」ことを最優先にします。

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

前回の続き——GitHubアカウントを全員そろえる

前回の振り返り

  • Git（バージョン管理・コミット・ブランチ）とGitHub（Gitをホスティングするプラットフォーム）の関係を1分で振り返る
  • AIエージェントが指示を受けてファイルに変更を加える存在であり、その変更をGitが記録する——という前回の要点を再確認する

アカウントの状態ごとに個別フォローする

  • ログインできる人：待たずに次の「1限後半」のリポジトリ作成へ進んでよい
  • 登録したがメール確認（verify）が済んでいない人：受信箱を確認し、確認メール内のリンクを開く
  • まだ登録していない人：github.com/signup から新規登録する。教員が個別にサポートする
早く終わった人へ: 全員がそろうのを待つ必要はありません。ログインできることを確認できたら、そのまま1限後半のリポジトリ作成作業を先に始めてください。
1限 後半 約50分

自分のリポジトリを新規作成し、Codespaces上でagyをインストールする

今日は一斉ガイド形式で進める（参考）

教員の画面を見ながら全員で同じ手順を一斉に進める。詰まったら手を挙げてその場で確認する。

新しいリポジトリを作る

  • GitHub右上の「+」アイコン→「New repository」を選択する（公式: Creating a new repository）
  • Repository name に好きな名前を入力する（例: agy-practice）
  • Public のままにする——第5回でGitHub Pagesに公開する予定があり、GitHub FreeプランではPrivateリポジトリをGitHub Pagesで公開できないため
  • 「Add a README file」に必ずチェックを入れる——チェックを入れないと最初のコミットが無く、Codespacesを起動できない
  • 「Create repository」をクリックする

Codespacesを起動する

  • 作成した自分のリポジトリを開き、「Code」ボタン→「Codespaces」タブ→「Create codespace on ◯◯」（◯◯には自分のリポジトリのブランチ名が入る。通常はmain）をクリックする（公式: Creating a codespace for a repository）
  • ブラウザ上にVS Codeの画面が立ち上がることを確認する
  • 左のファイルツリー、真ん中のエディタ、下のターミナル——第2回の教員デモで見た画面と同じ位置構成になっていることを確認する

「コーディングAIエージェント」とは

  • 第2回で比べた「チャット型AI」と「AIエージェント」のうち、コードを書く作業に特化したAIエージェントを「コーディングAIエージェント」と呼ぶ
  • 指示を受けて自分でコードを書き、ファイルを作り、実行して結果を確かめるところまで自律的に行う。人間は「何を作りたいか」を自然言語で伝え、細かい書き方までは指定しなくてよい
  • 同じ種類のツールは他にも複数あるが、今日はAntigravity CLI（agy）——第1回の教員デモで紹介したもの——を使う

agyをインストールする

  • 今日は自分のCodespaces上にagyを入れる。agyはターミナルで自然言語の指示を受け取り、実際にファイルへ変更を加える

Codespacesのターミナルに、次のコマンドをそのまま貼り付けてEnter（公式: Antigravity CLI — Installation & auth）。

curl -fsSL https://antigravity.google/cli/install.sh | bash
  • インストールが終わったらagy --versionと入力してEnter——バージョン番号が表示されればインストール成功（この時点ではまだ認証しない。認証は休憩後の2限前半で行う）
インストールがうまくいかない時: コマンドを貼り付けてもエラーが出る場合は、コピーした内容が1行そのままになっているか確認してください（改行や余分なスペースが入るとエラーになります）。それでも動かない場合は手を挙げて教員に相談してください。
使い終わったら停止する習慣を: GitHub Codespacesの無料枠には月ごとの上限があります（プランによって条件が異なるため、都度公式情報で確認してください）。今日の授業が終わったら、Codespacesの一覧画面から今日使った環境を停止しておきましょう。次回は「Create codespace」で新規作成せず、同じ環境を再開（resume）します——停止・再開（rebuildしない限り）は環境ごと保持されます（公式: Understanding the codespace lifecycle「Any saved changes in your codespace will still be available when you next start it.」）。
休憩 10分
2限 前半 約50分

agyを認証して使えるようにする

今日は個別フォロー優先で進める

認証はGitHubアカウント登録と同じくらいつまずきやすい工程です。教員は机間巡視で認証に詰まっている学生を優先的に回ります。焦らず、詰まったら手を挙げてください。

なぜ認証が必要か

  • agyは自分のGoogleアカウントと紐づけて使う。1限で入れたのはあくまで「プログラム本体」で、認証して初めて指示を出せるようになる

認証する

  1. ターミナルでagyと入力してEnter
  2. 認可URLが表示されるので、URLにマウスを乗せてCtrlキー（Macの場合はCmdキー）を押しながらクリックしてブラウザの新しいタブで開く（VS Codeのターミナルは通常のクリックだけではリンクが開かない仕様）
  3. Googleアカウントでサインインする
  4. 表示された英数字のコードをコピーし、ターミナルに戻って貼り付けてEnter
  5. ヘッダーにメールアドレスが表示されれば認証完了
よくあるつまずきと対処:
  • 認可URLが表示されない → もう一度agyと入力してみる
  • Ctrl（Cmd）+クリックしても新しいタブが開かない → URLをドラッグして選択・コピーし、手動で新しいタブに貼り付けて開く
  • Googleアカウントの選択画面でどれを使うか迷う → 学校用・個人用どちらでもよい（本科目ではアカウントの種類は問わない）
  • コードを貼り付けてもエラーになる → コードの前後に余分な空白や改行が入っていないか確認し、コピーし直す
  • 認証に時間がかかりすぎる・エラーが出て止まってしまう → Ctrl+Cで一度中断し、もう一度agyから最初からやり直す
  • それでも動かない → 手を挙げて教員に相談。早く終わった人は、隣で詰まっている人を手伝ってもらってもOK
2限 後半 約30分

agyに簡単なゲームを作ってもらう

まずは話しかけてみる

  • 自然言語で話しかけてみる。例: あなたが何をできるか、自己紹介してください

ゲームを1つ作ってもらう

  • 例: ブラウザで遊べる簡単なテトリスを作ってください / ブラウザで動くシンプルなボンバーマン風のゲームを作ってください——テトリス・ボンバーマン・じゃんけん等、好きなお題を選んでよい
  • 完成度は気にしない。「指示したら形になった」という体験が今日のゴール
  • agyがファイルを作り、コードを書き進める様子をそのまま見守る

分からないことはagyに聞く

  • 表示の仕方が分からない・エラーが出た・次に何をすればいいか分からない——そんな時はこれはどういう意味ですか？動かないので直してくださいのように、agy自身に聞いてよい

変更をGitHubに記録する

  • 例: ここまでの変更をコミットして、GitHubにプッシュしてください
  • 第2回で学んだ「コミット＝変更の記録」「プッシュ＝GitHubへ送る」を、agyへの指示で実践する
  • ここでプッシュしておかないと、Codespaces内だけの変更のままでGitHubには残らない——次回以降も同じ手順で必ずプッシュする
まとめ 約10分

次回予告＆今日の振り返り

  • 次回（第4回）：agyと一緒につくる①——今日作ったゲームに、agyへの自然言語の指示で小さな機能を1つ追加する
  • 今日作成したリポジトリは、第6回にGoogle AI Studio Build modeから読み込み直します。名前を覚えておいてください
  • 「GitHub・Codespaces・agyについて分かったこと・まだよく分からないこと」を一言メモして退出

課題・次回までにやること

必須
今日作ったゲームの変更がGitHubにプッシュされていることを確認しておく

今日作成した自分のリポジトリをGitHub上で開き、agyが作ったファイル一式が反映されているか確認する。プッシュできていない場合は、次回授業の冒頭で完了させる。第6回にGoogle AI Studio Build modeから同じリポジトリを読み込み直すため、リポジトリ名も控えておく。Codespace自体は停止したままでよい（次回resumeで再開する）。

推奨
agyに他の指示も試してみる

時間のあるときに、ゲームのルールを変えてみる・見た目の色を変えてみる等、簡単な指示を追加で試しておくと次回スムーズです。
