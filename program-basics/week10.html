Week 10 火曜 1・2限
テーマ
第9回までに、サイコロを for 文で 10 回振る・配列をリスト表示する、と同じような処理を何度も書く場面が増えてきた。今日は「処理に名前を付けてまとめる」仕組み——function（関数）を導入する。引数なし → 引数あり → 戻り値あり、と段階的に手で書き、サイコロを振る処理を rollDice() という関数にまとめる。さらに AI（Copilot/Gemini）に「バグ入り関数」を生成させて読み解いて直すバグ修正ワーク③で、関数の「定義」と「呼び出し」の境目を体に入れる

必要な準備

この回のゴール

  • 関数が「処理に名前を付けて、何度でも呼び出せるようにまとめたもの」であることを自分の言葉で説明できる
  • function 名前() { ... } の構文で関数を定義し、名前() で呼び出すを 1 度は手で書く
  • 引数（カッコの中で受け取る値）と戻り値（return で返す値）の役割を区別できる
  • 第9回の「サイコロ 10 回」を rollDice() 関数を使って書き直し、同じ機能のまま行数が減ることを体感する
  • AI が生成した「バグ入り関数」を読み解き、エラーメッセージと自分の予想を頼りに直せる

1限 前半 約40分

「同じ処理を何度も書く面倒さ」を体感する → 関数の必要性を理解する

前回の振り返り（10分）

  • 第9回で作った list.html を Codespaces で開く（python3 -m http.server 8000 → 第1回と同じ手順で Simple Browser）
  • favorites 配列の中身を増やしたり減らしたりして、for 文の本体を直さなくても <li> が増減することを再確認
  • 家でやった「サイコロ 10 回の結果を画面に表示する」推奨課題ができた人は、簡単に画面共有（強制ではない）

「同じ処理が 3 か所に出てきた」場面を作る（15分）

  • game.html を Codespaces で開き、<script> ブロックに次のような状況を作ってみる: 
    // サイコロを 1 回振る（第8回・第9回で書いた）
const dice1 = Math.floor(Math.random() * 6) + 1;
console.log("1 回目:", dice1);

// もう 1 回振りたい
const dice2 = Math.floor(Math.random() * 6) + 1;
console.log("2 回目:", dice2);

// さらにもう 1 回（合計 3 回）
const dice3 = Math.floor(Math.random() * 6) + 1;
console.log("3 回目:", dice3);
  • 保存して Simple Browser を開き、F12 → Console タブで 3 行のログが出ることを確認
  • 気づくこと:
    • 「Math.floor(Math.random() * 6) + 1」が3 回まったく同じ形で出てくる
    • 第9回の for 文を使えばまとめられるが、3 か所が離れたところにある場合は for でまとめにくい
    • 「サイコロを振る処理に名前を付けて、必要な場所でその名前を呼び出せたら楽」——これが関数

「関数 = 処理に名前を付ける」を予告（15分）

  • 関数を使うとさっきの 3 か所はこうなる（1 限後半で実際に書く、ここは予告だけ）: 
    function rollDice() {
  return Math.floor(Math.random() * 6) + 1;
}

console.log("1 回目:", rollDice());
console.log("2 回目:", rollDice());
console.log("3 回目:", rollDice());
  • 2 つの新しいキーワード:
    • 定義: function rollDice() { ... } で「rollDice という名前の処理」を一度だけ書く
    • 呼び出し: rollDice() で「その処理を実行」する。何回でも呼び出せる
  • 関数のご利益 3 つ:
    • 同じ処理を 1 か所にまとめられる——直すときも 1 か所だけ直せばよい
    • 名前で意味がわかる——rollDice() と書いてあれば「サイコロを振っている」とすぐわかる
    • 他のファイル・他の人にも使ってもらえる——名前と引数だけ伝えれば中身を知らなくても使える
「関数 = 1 回書いて何度も呼ぶ」: 第9回の for 文は「同じ処理を同じ場所で繰り返す」仕組みでした。関数は「同じ処理を別の場所で何度も使う」仕組みです。両方とも「同じことを何度も書くのは面倒」という感覚から生まれた書き方、という共通点があります。今日学ぶ関数は、後でfor 文と組み合わせると「サイコロを 100 回振って結果を画面に表示する」のような処理が、たった 5〜6 行で書けるようになります。
1限 後半 約50分

関数を手で書く → サイコロ関数とリスト表示関数を作る

関数の基本構文（10分）

  • もっとも単純な関数（引数なし・戻り値なし）から書く: 
    function sayHello() {
  console.log("こんにちは！");
}

sayHello();   // → "こんにちは！" と表示される
sayHello();   // もう 1 回呼べばまた表示される
  • 注意する 3 点:
    • 定義と呼び出しの2 つで 1 セット——function sayHello() { ... } だけ書いて呼ばないと何も起きない
    • カッコ () を忘れない——sayHello; と書くと関数を呼ばずに「関数そのもの」を指してしまう（エラーは出ないが何も実行されない）
    • 中身は波カッコ { }——インデント（半角スペース 2 個）で見やすく

引数を受け取る関数（10分）

  • 「名前を変えて挨拶する」関数: 
    function greet(name) {
  console.log("こんにちは、" + name + "さん！");
}

greet("田中");   // → "こんにちは、田中さん！"
greet("山田");   // → "こんにちは、山田さん！"
  • 引数のしくみ:
    • function greet(name) の name が仮引数（parameter）——「ここに値が入ってくる箱」
    • greet("田中") の "田中" が実引数（argument）——「実際に入れる値」
    • 呼び出すときに渡した値が、関数の中で name として使える
  • よくあるミス: greet() と引数なしで呼ぶと、name が undefined になって "こんにちは、undefinedさん！" と表示される

戻り値のある関数（10分）

  • 計算した結果を呼び出し元に返す関数。return を使う: 
    function add(a, b) {
  return a + b;
}

const result = add(3, 5);
console.log(result);   // → 8
  • return の意味:
    • 「計算結果を呼び出し元に返す」キーワード
    • return に出会った瞬間に関数は終わる——その後の行は実行されない
    • 関数の呼び出し（add(3, 5)）が「その結果の値」として扱えるようになる（const result = ... で受け取れる）
  • 引数なし・戻り値なし（sayHello()）/ 引数あり・戻り値なし（greet(name)）/ 引数あり・戻り値あり（add(a, b)）の 3 パターンを、関数を読むときの目印にする

サイコロを rollDice() 関数にまとめる（20分）

  • game.html の <script> を次のように書き直す: 
    function rollDice() {
  return Math.floor(Math.random() * 6) + 1;
}

console.log("1 回目:", rollDice());
console.log("2 回目:", rollDice());
console.log("3 回目:", rollDice());
  • 保存して Simple Browser を更新。F12 の Console に 3 行のログが出ることを確認
  • 第9回の for 文と組み合わせる——10 回振るのを次のように書く: 
    const results = [];
for (let i = 0; i < 10; i++) {
  results.push(rollDice());
}
console.log(results);
  • 第9回では Math.floor(Math.random() * 6) + 1 を for 文の中に直接書いた——今日は rollDice() という名前で呼ぶだけになった点を比較する
  • 「100 回振りたい」「サイコロを2 個振りたい」「20 面ダイスにしたい」など、要件が変わったときに直す場所が 1 か所で済むのが関数のご利益
休憩 10分
2限 前半 約50分

バグ修正ワーク③：AI に「バグ入り関数」を生成させて読み解く

ワークの目的を共有（5分）

  • 第5回（バグ修正ワーク①：スマホ対応 CSS）・第7回（バグ修正ワーク②：if 文）に続く、3 回目のバグ修正ワーク
  • 狙い: 「AI が書いた関数を読んで、何が起きているかを自分で予想する」感覚を作る。Copilot が普段提案するコードを「採用するか・しないか」自分で判断する練習（第3回の延長線）
  • 今日のバグは関数まわり特有のもの——引数の渡し忘れ、return の書き忘れ、呼び出し時のカッコ抜け、など

AI にバグ入り関数を生成させる（15分）

  • Codespaces のCopilot Chat（または Gemini）に次のプロンプトを投げる: 
    JavaScript の初学者向けの練習問題として、わざと 1 か所だけバグを入れた関数のコードを 3 つ書いてください。
- どの関数も 5 行以内
- バグは「return の書き忘れ」「引数名の typo」「呼び出し時のカッコ忘れ」のどれか
- バグの場所と原因は答えを別欄に書いてください（コード本体には書かないこと）
  • AI が出した 3 つの関数を game.html の <script>（または新規ファイル bug-quiz.html）にコピペする
  • 同じプロンプトでも応答は毎回違う——隣の人と内容が違っても OK。それぞれが自分の問題に取り組む

バグを読み解く（25分）

  • AI が出した「バグの場所と原因」の答え合わせ部分は隠して、まず自分で読む
  • 読み方の手順:
    • ① 関数の定義を読む——名前・引数・return の有無を確認
    • ② 呼び出し方を読む——引数の数は合っているか、結果を受け取っているか
    • ③ 実行してみる——保存して Simple Browser を更新、F12 の Console でエラーを見る
    • ④ エラーメッセージから原因を予想——undefined が出る、NaN（数値ではない）が出る、何も表示されない、など
  • 3 つとも直せたら、AI の答え合わせを見て自分の予想と比較する
  • 「自分は return 抜けだと思ったが、本当は引数名の typo だった」のようなズレこそ学びの素材。NOTES.md に「ズレた箇所」を 1 行メモしておくと、次のバグに会ったときの引き出しが増える

同じ AI にもう 1 回出させる（5分）

  • 時間が余った人は、AI に「もう 1 セット、今度は引数を 2 つ使う関数で」などと条件を変えて再生成させる
  • AI の出し方の癖（よくやる typo / よく忘れる構文）が見えてくると、普段 Copilot が提案するコードのチェックも速くなる
「エラーが出る = 失敗」ではない: エラーメッセージはJavaScript が「ここがおかしいよ」と教えてくれる手紙です。F12 の Console に出るエラーは赤字で目立つので「失敗した」と感じがちですが、本当の失敗は「エラーが出ないのに動きがおかしい」ケース（よくあるのは return 抜けで結果が undefined になるパターン）。エラーが出てくれるのはむしろ親切、と覚えておきましょう。
2限 後半 約30分

第9回の list.html を関数で整理する → コード整理を体感する

整理の方針を確認（5分）

  • 第9回の list.html では「配列を for 文で <li> として並べる」処理を直接書いた
  • 今日はこの処理を showList(items) という関数にまとめる——同じ機能のまま、別の配列にも使い回せる形にする
  • これが「リファクタリング（コード整理）」の最初の一歩——機能を変えずに、形だけ整える

showList(items) 関数を作る（15分）

  • list.html の <script> ブロックを次のように書き直す: 
    function showList(items) {
  const ul = document.getElementById("favorite-list");
  for (let i = 0; i < items.length; i++) {
    const li = document.createElement("li");
    li.textContent = items[i];
    ul.appendChild(li);
  }
}

const favorites = [
  "好きな食べ物：カレー",
  "好きな色：青",
  "好きな音楽：J-POP",
  "好きな場所：図書館"
];

showList(favorites);
  • 保存して Simple Browser を更新——第9回と同じリストが表示されることを確認（機能は変わっていない）
  • 確認ポイント:
    • showList(items) の items は仮引数——呼び出すときに何の配列を渡してもよい
    • showList(favorites) でも showList(["a", "b", "c"]) でも動く（直接配列を渡しても OK）
    • 関数の中の items.length は、渡された配列の長さを自動的に見てくれる（第9回の length のご利益が関数と組み合わさる）

「もう 1 つリストを増やす」と楽になる（10分）

  • list.html に2 つ目の <ul> を追加するシナリオを試す（時間がなければ概念の確認だけで OK）: 
    // HTML 側に追加
<h2>最近見つけた良いもの</h2>
<ul id="recent-list"></ul>
  • このとき、関数を使っていない場合は for 文の塊をもう 1 セットコピペする必要があるが、関数があればshowList の中の getElementById を引数で受け取る形に拡張するだけで済む（実装は推奨課題に残す）
  • 「2 か所目を作ろうとした瞬間に、整理しておいてよかったと感じる」——これがリファクタリングの効用
まとめ 約10分
