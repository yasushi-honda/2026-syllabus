1限 前半 約40分

「小ゲーム」とは何かを整理 → 設計図を紙またはメモに書く

前回（第7回）の振り返り（10分）

  • 第7回で完成させた気分スコア診断を Codespaces で開き直す（python3 -m http.server 8000 → 第1回と同じ手順で Simple Browser）
  • mood の値を変えて、4 つの枝（絶好調・いい感じ・ぼちぼち・お疲れさま）が想定通りに動くか確認
  • 第6回のおみくじのコード（Math.random + 配列）も同じページ内に残っているはず——今日はこの 2 つを統合して、ひとつの小ゲームにする

「小ゲーム」のミニマル定義（10分）

  • このシラバスでいう「小ゲーム」とは、次の 3 つを満たすもの:
    • ① 入力（または毎回変わる要素）がある: 第6回の Math.random、第7回の mood 変数のような「実行ごとに違う値」
    • ② 判断（分岐）がある: 第7回の if / else if / else
    • ③ 結果が画面に表示される: 第6回・第7回と同じ document.getElementById(...).textContent = ...
  • 難しい言葉で言うと「入力 → 処理 → 出力」の 3 ステップが揃っているだけで「ゲーム」と呼べる。クリックや入力欄は第11回（DOM 操作）で扱うので、今日は「ページを開いた瞬間にランダムに 1 回プレイされる」形でよい

今日作る小ゲームの設計を決める（20分）

  • 選択肢として 2 つの方向を提示。どちらか自分の好きな方を選ぶ:
    • 案A: 運勢アドバイスゲーム——サイコロ（1〜6）をランダムに振って、出目に応じて「今日のおすすめ行動」を返す
    • 案B: 拡張気分スコア診断——気分スコアをランダムに決定（毎回違う値）し、結果に応じてアドバイスを返す。さらに「ラッキー絵文字」もランダムに 1 つ添える
  • どちらの案でも、NOTES.md または紙に設計図を書いてから手を動かす:
    • 変数名（例: dice / moodScore）
    • 分岐の条件と結果（例: 5以上 → "机を片付ける" ／ 3以上 → "水を1杯飲む" ／ それ以外 → "深呼吸を3回"）
    • 表示する要素の id（例: id="game-result"）
  • 設計図を 5 分以内に描けたら、すぐにコードを書き始めてよい。迷う人は案Aで進めるのが時間切れリスクが低い
「全部入りを狙わない」: ミニ完成回は「動くものを公開する」のが最優先。あれもこれもと盛り込むと 2 限後半までに公開が間に合わなくなります。1 つの分岐 × 1 つのランダム要素で十分に「小ゲーム」と呼べます。装飾や追加機能は家でゆっくり足してください。
1限 後半 約50分

新規ファイル game.html を作って、ロジックを統合する

新規ファイル game.html を作る（10分）

  • Codespaces のファイル一覧で右クリック →「New File」を選び、game.html という名前で作成（リポジトリのルート、index.html と同じ階層に置く）
  • 第1回と同じ最小 HTML テンプレを書く。今日の小ゲーム用の要素を 2 つ追加: 
    <!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>運勢アドバイスゲーム</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>今日の運勢アドバイス</h1>
  <p>ページを更新するたびにサイコロが振られます</p>
  <p id="game-result">ここに結果が出ます</p>
  <p><a href="index.html">トップに戻る</a></p>

  <script>
    // ここに統合ロジックを書く（次の手順で）
  </script>
</body>
</html>
  • game.html を保存（この時点ではまだ <script> は空で OK）
  • index.html 側にも 1 行だけ追加: <p><a href="game.html">運勢アドバイスゲームで遊ぶ</a></p> ——トップから遊べる動線を作る。保存して、Simple Browser で index.html を更新するとリンクが出るはず
  • Simple Browser に表示された 「運勢アドバイスゲームで遊ぶ」リンクをクリック → game.html に移動して、見出しと段落が表示されることを確認（この時点では結果文言はまだ出ない、次の手順で <script> を書いて動かす）

ロジックを統合して書く（30分）：案Aの例

  • <script> ブロックの中に、第6回の Math.random と第7回の if 分岐を組み合わせて書く: 
    // 1〜6 のサイコロを 1 回だけ振る
const dice = Math.floor(Math.random() * 6) + 1;

// 出目で「今日のおすすめ行動」を分岐
let advice;
if (dice >= 5) {
  advice = "机を片付けて気持ちをリセット";
} else if (dice >= 3) {
  advice = "コップ1杯の水を飲んでひと息";
} else {
  advice = "深呼吸を3回してから次の作業へ";
}

// 結果を画面に表示
const message = `🎲 ${dice} が出ました！→ ${advice}`;
document.getElementById("game-result").textContent = message;
console.log(message);
  • 保存 → Simple Browser を何度か更新。サイコロの目と、それに応じたアドバイスが切り替わることを確認
  • うまく動かないときは F12 → Console タブを開く。第7回のバグ修正ワーク②と同じ手順——赤い行があれば 1 行目をそのまま読む
  • 案Bを選んだ人は、上の例の dice を moodScore に、Math.floor(Math.random() * 6) + 1 を Math.floor(Math.random() * 11)（0〜10 の整数）に置き換え、第7回の 4 段階の if 文をそのまま貼り込む

動いたらやってほしいこと（10分）

  • 分岐のメッセージを自分らしい言葉に書き換える（テンプレのままだとつまらない）
  • 余裕があれば、style.css の既存ルールが game.html にも適用されているか確認。見出しの色や余白が共通になっていたら成功
  • 絵文字は1〜2 個まで。入れすぎると公開時に見づらくなる
休憩 10分
2限 前半 約50分

commit & push して GitHub Pages に追加公開する

commit & push で再デプロイ（15分）

  • Codespaces 左側の「ソース管理」（Source Control）タブを開く
  • 変更ファイルとして game.html（新規）と index.html（リンク追記）が一覧に出ているはず
  • コミットメッセージ例: 運勢アドバイスゲームを追加
  • 「Commit」→「Sync Changes」（または「Push」）で GitHub に反映
  • Week 4 で GitHub Pages はすでに有効化済みなので、Settings の操作は不要。push しただけで自動的に再デプロイされる
  • GitHub.com のリポジトリページ →「Actions」タブで pages build and deployment ワークフローの進行状況を確認

追加された公開URLを確認（15分）

  • 第4回で取得した公開URLは https://<ユーザー名>.github.io/<リポジトリ名>/
  • 今回追加した小ゲームの URL は、その末尾に game.html を付けるだけ:
    https://<ユーザー名>.github.io/<リポジトリ名>/game.html
  • ブラウザの別タブで開いて、Simple Browser と同じ表示・同じ動作（更新ごとにサイコロが変わる）が再現できるか確認
  • 反映待ち時間: 公式に最大10分（通常は1〜3分）。すぐ反映されない時は Mac: Cmd + Shift + R / Windows: Ctrl + Shift + R でキャッシュをクリア

スマホ実機で開く（20分）

  • 新しい公開URLを LINE などで自分宛に送るか、手で打ち込んでスマホで開く（QR コードは第5回で扱った方法を使ってよい）
  • スマホで開いて2〜3回更新して、サイコロの目が変わることを確認
  • 第5回で書いたレスポンシブ（メディアクエリ）のスタイルが効いていれば、スマホでも崩れずに表示されるはず
  • 表示が崩れていた場合は、スクリーンショットを撮って NOTES.md に貼っておく（家で家族・友達に遊んでもらうときの素材にもなる）
「公開URLは2つ持っている」と覚える: 今あなたの公開URLは少なくとも 2 本あります——プロフィール (/) と小ゲーム (/game.html)。これからの回でページが増えるたびに公開URLも増えていくのが GitHub Pages の自然な使い方です。第12回（ミニ完成③ インタラクティブ作品公開）でもこの仕組みを使います。
2限 後半 約30分

クラスメイトに遊んでもらって反応を集める → 自己レビュー

公開URLを共有する（10分）

  • 授業内の連絡手段（Google Classroom やチャット）で、自分の/game.html の URLをクラスメイトに共有
  • 共有するときは「更新するたびにサイコロが振られます」のような遊び方の一言を添えるとよい
  • 受け取った側は、相手のゲームを3 回以上更新して動かしてみる

他人に遊んでもらった反応をメモする（10分）

  • クラスメイトから「面白かった点」「分かりにくかった点」を 1 つずつでよいので聞く（口頭・チャットどちらでも）
  • NOTES.md の末尾に「公開後フィードバック」という見出しで記録:
    • 誰の反応か（名前は伏せて「クラスメイトA」でよい）
    • 面白かった点
    • 改善したいと思った点
  • このメモは第14回（自由制作）の素材になる——「他人がどう感じたか」の記録は教科書には載っていない自分だけのデータ

自分の作品を1分だけ眺める（10分）

  • スマホで自分の公開URLを開き、更新ボタンを 10 回くらい押す
  • 同じメッセージが連続で出ることがあれば、それは Math.random の自然な挙動（偏ることがある）
  • 「自分が作ったものが、家でもスマホで動く」——この感覚を一度味わって退出する。これが2 作目の公開体験として、第4回（プロフィールサイト公開）に続くミニ完成回の本当のゴール
まとめ 約10分

次回予告と今日の振り返り

  • 次回（第9回）: 繰り返しと配列——for 文と配列の基本を手で書く。たとえば1 回だけ振っていたサイコロを「10 回振って全部表示する」ような、複数のデータを扱う考え方を学ぶ
  • 今日のキーワード 「ロジックの統合」「Math.random + if」「追加ページ」「commit & push で自動再デプロイ」「スマホ実機での確認」を口に出して言えるか確認して退出
  • 家で公開URLを家族・友人に見せて、第三者から見たときの第一印象を聞いてみるだけでも復習になる

課題・次回までにやること

必須
小ゲームを公開URLで遊べる状態にして push する

授業内で公開が間に合わなかった人は家で完成させ、必ずスマホでも動作確認してから push する。公開URL（/game.html）を授業内連絡手段で共有しておくと、次回までにクラスメイトからフィードバックが集まる。

必須
NOTES.md に「公開後フィードバック」と「自己レビュー」を書く

クラスメイトから聞いた反応を最低 1 件、自分で見直したときに「ここを直したい」と思った点を最低 1 件、それぞれ 2〜3 行で記録。直すかどうかは第14回まで保留してよい。

推奨
分岐の枝を 1 つ増やす or メッセージを書き換える

3 段階の分岐を 4 段階に増やす、または分岐の中身を自分の趣味や日常に合わせて書き換える。「自分のための小ゲーム」として育てると、第14回（自由制作）の起点になる。コード変更後は再度 commit & push して公開URLにも反映する。
