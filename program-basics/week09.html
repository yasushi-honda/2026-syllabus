繰り返しと配列

Week 9 火曜 1・2限
テーマ
第8回の小ゲームではサイコロを 1 回だけ振った。今日は同じことを 10 回繰り返すのに、コピペで 10 行書くのではなく for 文で 1 度だけ書く方法を学ぶ。あわせて複数のデータをひとつの変数にまとめる「配列」を導入し、for 文と組み合わせてリスト表示アプリを作る。新規ファイル list.html を作って GitHub Pages に追加公開する
キーワード
繰り返し / for 文（初期化・条件・更新の 3 点セット） / 配列 / インデックス（0 から始まる） / length / push / 配列と for 文の組み合わせ / リスト表示アプリ / document.createElement + appendChild / 追加ページ（list.html） / 再デプロイ
必要な準備
第8回までに作った GitHub Pages 公開済みリポジトリ・Codespaces が起動できる状態・第6回のおみくじ（Math.random）と第7回の if 文を一度書いた経験

この回のゴール

  • 配列が「複数の値をひとつの変数にまとめて入れる入れ物」であることを自分の言葉で説明できる
  • const items = ["a", "b", "c"]; のように配列を宣言し、items[0] でインデックス指定して値を取り出せる
  • for 文の初期化・条件・更新の 3 点セットを 1 度は手で書く
  • for 文と配列を組み合わせて、配列の全要素を順番に表示できる
  • 新規ファイル list.html を作り、commit & push で自動再デプロイされる流れを再体験する

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

「10 回振りたい」を素朴に書いてみる → 繰り返しの必要性を体感する

前回の振り返り（10分）

  • 第8回で作ったgame.html を Codespaces で開き直す（python3 -m http.server 8000 → 第1回と同じ手順で Simple Browser）
  • ページを何度か更新して、サイコロが毎回 1 回だけ振られて結果が 1 つだけ出ることを確認
  • 「毎回更新しないと次の目が出ない」のがやや不便。今日は1 回ページを開いただけで 10 回分の結果が並ぶ形を目指す

素朴に「10 回」書いてみる（15分）

  • game.html の <script> ブロックを開き、ためしにサイコロのコードを 10 個コピペしてみる: 
    const dice1 = Math.floor(Math.random() * 6) + 1;
console.log(dice1);
const dice2 = Math.floor(Math.random() * 6) + 1;
console.log(dice2);
const dice3 = Math.floor(Math.random() * 6) + 1;
console.log(dice3);
// ... これを 10 個まで書く
  • 保存して Simple Browser で game.html を開き、F12 → Console タブで 10 個の数字が並ぶことを確認
  • 書いていて気づくはず: 「同じことを 10 回書くのは面倒」「変数名 dice1 〜 dice10 を全部覚えていられない」「100 回にしたくなったら破綻する」
  • この「面倒」「破綻する」の感覚が、今日学ぶ for 文と配列が登場する理由

「同じことを繰り返す」を 1 文で書く方法を予告（15分）

  • 同じコードを 10 回書くかわりに、JavaScript には「これを 10 回繰り返してね」と頼める書き方がある——それが for 文
  • そして 10 個の結果を dice1 〜 dice10 という別々の変数に入れるかわりに、1 個の入れ物に並べて入れる書き方がある——それが配列
  • for 文と配列の2 つを組み合わせることで、「サイコロを 10 回振って結果を順番に表示する」が、たった 4〜5 行のコードで書けるようになる
  • 先に 10 個コピペした <script> は、1 限後半で書き直すので消さずに残しておく（書き直しのとき、新旧で見比べて違いを実感するため）
「面倒だな」と感じる感覚を大切に: プログラミングの便利な書き方の多くは、「同じことを何度も書くのが面倒」という人間側の感覚から生まれています。for 文・配列・関数（次回）も全部その仲間です。「楽したい」と感じた瞬間が、新しい書き方を学ぶ準備ができたサインと覚えておいてください。
1限 後半 約50分

配列と for 文を手で書く → サイコロ 10 回を 4 行で書き直す

配列の基本（15分）

  • 配列は角括弧 [ ] で複数の値を並べて書く: 
    const fruits = ["りんご", "みかん", "ぶどう"];
console.log(fruits[0]);    // "りんご"
console.log(fruits[1]);    // "みかん"
console.log(fruits[2]);    // "ぶどう"
console.log(fruits.length); // 3
  • 注意点 3 つ:
    • インデックスは 0 から始まる——fruits[1] は 2 番目（みかん）になる
    • .length で要素数が取れる——3 個なら 3 が返る
    • 後から要素を追加するときは push——fruits.push("メロン"); で末尾にメロンが入る
  • F12 の Console に直接打ち込んで、上の 4 行を実行して結果を確認

for 文の基本（15分）

  • for 文は初期化・条件・更新の 3 点セットで書く: 
    for (let i = 0; i < 3; i++) {
  console.log(i);
}
  • 3 点セットの意味:
    • 初期化 let i = 0: ループの最初に 1 回だけ実行。i という変数を 0 で開始
    • 条件 i < 3: ループのたびにチェック。true なら中身を実行、false なら終わり
    • 更新 i++: 中身を 1 回実行した後に i を 1 増やす（i = i + 1 の短縮形）
  • 上の例は i が 0 → 1 → 2 と変わって 3 回ログが出る（3 回で止まるのは条件 i < 3 が false になるから）
  • よくあるミス: 条件を i <= 3 にすると 4 回回ってしまう。length と組み合わせるときは i < fruits.length が定型句

サイコロ 10 回を 4 行に書き直す（20分）

  • 1 限前半で 10 個コピペしたコードの下に、新しく次のコードを書く（古いコードは消さずに残す、見比べたいので）: 
    const diceResults = [];
for (let i = 0; i < 10; i++) {
  diceResults.push(Math.floor(Math.random() * 6) + 1);
}
console.log(diceResults);
  • 保存して Simple Browser を更新。F12 の Console に 10 個の数字が並んだ配列が出ることを確認
  • 確認ポイント:
    • 10 個コピペした旧コードと比べて、4 行で同じことをしている
    • 「100 回にしたい」と思ったら、10 を 100 に書き換えるだけ
    • diceResults[0] や diceResults[9] で個別の値も取り出せる
  • 動いたことを確認したら、旧コード（dice1 〜 の 10 行コピペ）は消してよい。for 文を残す

新規ファイル list.html を作る → 配列の中身を画面にリスト表示する

新規ファイル list.html を作る（10分）

  • 第8回と同じ手順——ファイル一覧で右クリック → New File、list.html をリポジトリのルートに作成（index.html と同じ階層）
  • 最小 HTML テンプレ: 
    <!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>お気に入りリスト</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>私のお気に入り</h1>
  <p>配列に入れたものを <code>for</code> 文で全部表示します</p>
  <ul id="favorite-list"></ul>
  <p><a href="index.html">トップに戻る</a></p>

  <script>
    // ここに配列と for 文を書く（次の手順で）
  </script>
</body>
</html>
  • index.html 側にもリンクを 1 行追加: <p><a href="list.html">お気に入りリストを見る</a></p>（第8回の game.html リンクの下に並べる）
  • Simple Browser で index.html を更新 → 新しいリンクをクリックして list.html に移動できることを確認

配列の中身を <li> として並べる（25分）

  • <script> ブロックの中に、次のコードを書く: 
    const favorites = [
  "好きな食べ物：カレー",
  "好きな色：青",
  "好きな音楽：J-POP",
  "好きな場所：図書館"
];

const ul = document.getElementById("favorite-list");

for (let i = 0; i < favorites.length; i++) {
  const li = document.createElement("li");
  li.textContent = favorites[i];
  ul.appendChild(li);
}
  • 新しく出てきた 3 つの書き方:
    • document.createElement("li"): 新しい <li> 要素を JavaScript で作る
    • li.textContent = ...: 作った <li> の中身（テキスト）を設定（第6回・第7回でも textContent を使った）
    • ul.appendChild(li): 作った <li> を <ul> の子として末尾に追加
  • 保存して Simple Browser を更新——4 つの項目が箇条書きで表示されたら成功
  • うまく動かないときは F12 → Console タブ。よくあるエラー:
    • Cannot read properties of null: HTML 側の id="favorite-list" のスペルミス、または <script> が <ul> より上にある（第6回と同じパターン）
    • 表示が出ない: li.textContent ではなく li.textcontent など大文字小文字のミスがないか

「自分のお気に入り」に書き換える（15分）

  • テンプレの 4 項目を、自分自身のお気に入りに書き換える（4〜6 項目くらい）
  • 項目の数を変えても for 文の favorites.length が自動的に追従するので、for 文側を直す必要はない——これが .length を使うご利益
  • 個人情報（本名・住所・学校名・電話番号）は書かない原則は授業共通。「クラスメイトに見せても OK な範囲」で書く
「画面に出す = HTML を JS で作って差し込む」: 第6回・第7回では textContent ですでにある要素の中身を書き換えました。今日は createElement + appendChild で新しい要素を JavaScript 側で作って差し込む書き方を覚えました。第11回（DOM 操作とイベント）で本格的に扱いますが、今日はその予告編として「JS で HTML を組み立てることができる」と知っておけば十分です。
