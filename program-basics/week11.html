DOM操作とイベント

Week 11 火曜 1・2限
テーマ
第9回・第10回で document.getElementById や document.createElement を使い、HTMLの要素をJavaScriptから触る体験はすでにしている。今日はこれを正式にDOM（Document Object Model）という名前で捉え直し、textContent での書き換えと addEventListener によるクリックイベントを組み合わせる。第10回で作った rollDice() 関数をボタンクリックに接続し、押すたびにサイコロが振られて結果が画面に表示される「サイコロクリックゲーム」を完成させる
キーワード
DOM（Document Object Model） / document.getElementById / textContent による書き換え / addEventListener("click", 関数) / イベントハンドラ / クリックカウンター / 関数を呼び出さずに渡す（関数名 と 関数名() の違い、第10回の続き） / サイコロクリックゲーム
必要な準備
第10回までに作った GitHub Pages 公開済みリポジトリ（index.html / game.html / list.html）・Codespaces が起動できる状態・第10回の rollDice() 関数、第7回の if 文を一度は手で書いた経験

この回のゴール

  • DOMが「ブラウザに読み込まれたHTMLをJavaScriptから触れるようにした木構造」であることを自分の言葉で説明できる
  • document.getElementById("id").textContent = "新しい文字" の形で、既存の要素の中身を1行で書き換えられる
  • addEventListener("click", 関数名) の構文で、ボタンを押したときに関数が呼ばれる仕組みを手で書ける
  • 「関数名()（呼び出す）」と「関数名（呼び出さずに渡す）」の違いを、addEventListener の中で正しく使い分けられる
  • 第10回の rollDice() を クリックイベントと if 文と組み合わせて、押すたびに結果とスコアが更新される小さなゲームを1つ完成させる

「HTMLをJavaScriptから触る」を DOM という名前で捉え直す

前回の振り返り（10分）

すでに DOM を触っていたことに気づく（15分）

  • list.html の showList(items) 関数を見直す: 
    function showList(items) {
  const ul = document.getElementById("favorite-list");
  for (let i = 0; i < items.length; i++) {
    const li = document.createElement("li");
    li.textContent = items[i];
    ul.appendChild(li);
  }
}
  • 気づくこと: document.getElementById（要素を探す）・document.createElement（要素を作る）・li.textContent（中身を書く）・ul.appendChild（つなげる）——すでに4つのDOM操作を第9回・第10回で使っていた。特に createElement で <li> を作っただけではまだ画面に何も現れず、最後に ul.appendChild(li) で ul（親）につなげて初めて表示される点に注意——「作る」と「つなげる」は別の操作
  • 今日名前を付ける: この「HTMLがブラウザの中でJavaScriptから触れる木の形」を DOM（Document Object Model）と呼ぶ。document という単語は「この木の根っこ」を指している

textContent だけで書き換える実験（15分）

  • 新規ファイル click-game.html を作る。第9回の list.html と同じく、<!DOCTYPE html> から書く骨組みを省略しない（<head> 内の <meta charset="UTF-8"> を忘れると日本語が文字化けするので必ず入れる）: 
    <!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>クリックゲーム</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1 id="message">まだ何もしていません</h1>

  <script>
    // ここに JavaScript を書く（1限後半で書き足していく）
  </script>
</body>
</html>
  • 保存して開く: game.html を表示している Simple Browser のタブのアドレスバーの末尾だけ /click-game.html に書き換えて Enter（サーバーは前半の振り返りで起動済みなのでポート番号はそのまま）。まだ index.html にリンクはないので、この方法で直接開く
  • 開けたら F12 → Console タブを開いて次の1行を打ち込んでみる: 
    document.getElementById("message").textContent = "書き換わった！";
  • コピー＆ペーストで貼り付けると、初めて Console を使う場合はブラウザの自己防衛機能（self-XSS対策）が働き、貼り付けがブロックされて「allow pasting と入力してください」という警告が出ることがある。その場合は入力欄に半角で allow pasting と打ち込んで Enter を押すと、以降は普通に貼り付けできるようになる
  • Enter を押した瞬間、ページの見出しがコードを保存し直さなくても変わることを確認——これが「JavaScriptからHTMLを直接操作する」体験そのもの
  • id="message" の要素を document.getElementById("message") で掴んで、.textContent = "..." で中身を差し替える、の2ステップだけで書き換えが起きている
「DOM」は新しい概念ではなく「呼び方」: 第9回の for 文、第10回の関数、そして今日の DOM は、難易度が急に上がる新技術ではありません。今日の最初の実験でやったことは、実は第9回・第10回の list.html ですでにやっていた操作と同じです。「知らないうちに DOM を触っていた」と気づくのが、今日いちばん大事な発見です。

addEventListener でクリックに反応する → クリックカウンターを作る

addEventListener の基本構文（15分）

  • click-game.html の <h1> の下にボタンを1つ追加する。ボタンにも id="my-button" を付けておく——id="message" と同じで、後で JavaScript から掴むための目印になる: 
    <h1 id="message">まだ何もしていません</h1>
<button id="my-button">押してみる</button>
  • テンプレートに用意しておいた <script> の中身（コメント行）を、次のコードに置き換える: 
    function handleClick() {
  document.getElementById("message").textContent = "押されました！";
}

const button = document.getElementById("my-button");
button.addEventListener("click", handleClick);
    上から順に3つの部品でできている:
    1. function handleClick() { ... } — ボタンが押されたときにやってほしい処理をひとまとめにした関数。中身は今日の最初にやった textContent の書き換えと同じ
    2. const button = document.getElementById("my-button"); — id="my-button" の要素を掴んで button という変数に入れておく。今日の前半で message を掴んだのと同じやり方
    3. button.addEventListener("click", handleClick); — 掴んだ button に「click（クリック）されたら handleClick を呼んでください」と予約する。1つ目の引数がイベントの種類（文字列 "click"）、2つ目の引数が呼び出したい関数そのもの
  • 保存して Simple Browser を更新し、ボタンを押すたびに見出しが変わることを確認

よくあるミス：カッコを付けて渡してしまう（10分）

  • 第10回の「sayHello; と sayHello(); の違い」がここでも罠になる: 
    // NG: ページを開いた瞬間に1回だけ実行され、クリックしても何も起きない
button.addEventListener("click", handleClick());

// OK: クリックされるたびに実行される
button.addEventListener("click", handleClick);
  • コードの実行順で理由を追う: JavaScript は () を見た瞬間にその場で関数を実行する。handleClick() と書くと、ページが読み込まれた瞬間に handleClick が1回実行され、その戻り値（handleClick は return していないので undefined）が addEventListener の2つ目の引数として渡ってしまう。addEventListener が本当に必要としているのは「クリックされた瞬間に呼び出す関数そのもの」であって「関数を1回実行した結果」ではない——だからカッコを付けると壊れる
  • 実際に handleClick() と書き換えて動かし、「1回だけ実行されてクリックしても反応しない」を自分の目で確認してから正しい形に戻す

クリックカウンターを作る（25分）

  • 「押した回数」を数える変数を用意し、押すたびに増やす: 
    let count = 0;

function handleClick() {
  count = count + 1;
  document.getElementById("message").textContent = "押した回数: " + count + " 回";
}

const button = document.getElementById("my-button");
button.addEventListener("click", handleClick);
    コードの読み方:
    • let count = 0; を function の外側で宣言している点に注意——関数の中で宣言すると、クリックのたびに count が 0 に戻ってしまい数えられない。また const ではなく let を使うのは、count はクリックのたびに値を書き換える（再代入する）変数だから（button は書き換えないので const のまま）
    • count = count + 1; — 「今の count の値に 1 を足して、その結果をもう一度 count に入れ直す」という意味。右辺（古い値 + 1）を先に計算してから、左辺の count に代入し直している
    • "押した回数: " + count + " 回" — 文字列と数値を + でつなげると、数値が自動的に文字列に変換されて1つの文字列になる（count が 3 なら "押した回数: 3 回"）
  • 保存して Simple Browser を更新。ボタンを連打して回数が増えていくことを確認
  • 時間が余った人は、count が 10 の倍数になったら message の文字を変える（if 文の復習、第7回参照）などアレンジしてよい

rollDice() をボタンに接続する → サイコロクリックゲームの土台を作る

サイコロボタンを作る（20分）

  • click-game.html に第10回の rollDice() 関数を追加し、ボタンと接続する: 
    function rollDice() {
  return Math.floor(Math.random() * 6) + 1;
}

function handleRoll() {
  const result = rollDice();
  document.getElementById("message").textContent = "出た目: " + result;
}

const rollButton = document.getElementById("my-button");
rollButton.addEventListener("click", handleRoll);
    コードの読み方（第10回からの変化点）:
    • function rollDice() { ... } — 第10回でそのまま作った関数。Math.floor(Math.random() * 6) + 1 で 1〜6 のランダムな整数を1つ戻り値として返すだけで、画面には何も表示しない
    • function handleRoll() { ... } — クリックされたときに実行する新しい関数。中は2ステップ: ① const result = rollDice(); で rollDice() を呼び出し、戻ってきた数字を result という変数に保存する。② その result を "出た目: " + result という文字列に組み立てて textContent で画面に書き込む
    • const rollButton = ... / rollButton.addEventListener(...) — 1限後半と同じ「掴んで→予約する」の2ステップ。関数名とボタンの変数名が変わっただけで構造は同じ
  • ボタンの表示も <button id="my-button">サイコロを振る</button> に変更
  • 保存して Simple Browser を更新。押すたびに 1〜6 のランダムな目が表示されることを確認
  • 第10回は console.log で結果を確認していたが、今日は結果を画面（DOM）に表示している点が進化ポイント——rollDice() 自体は1文字も変えていないことに注目（関数は呼び出し方を変えるだけで別の場所でも再利用できる）

if 文と組み合わせてスコアを付ける（30分）

  • 「6 が出たら得点」というルールを追加し、試行回数と得点も画面に表示する: 
    let tries = 0;
let score = 0;

function rollDice() {
  return Math.floor(Math.random() * 6) + 1;
}

function handleRoll() {
  const result = rollDice();
  tries = tries + 1;

  if (result === 6) {
    score = score + 1;
  }

  document.getElementById("message").textContent =
    "出た目: " + result + "（" + tries + "回目、得点: " + score + "）";
}

const rollButton = document.getElementById("my-button");
rollButton.addEventListener("click", handleRoll);
    handleRoll の中身を上から順に追う:
    1. const result = rollDice(); — まずサイコロを振って結果を確定させる。この result を以降の判定と表示の両方で使い回す（rollDice() をもう一度呼ぶと別の目になってしまうので、1回だけ呼んで変数に保存するのがポイント）
    2. tries = tries + 1; — クリックカウンターと同じ加算代入。6が出ても出なくても、クリックされたら必ず1増える
    3. if (result === 6) { score = score + 1; } — result がちょうど 6 のときだけ、中の score = score + 1; が実行される。6以外なら if の中はスキップされ、score は変わらない
    4. "出た目: " + result + "（" + tries + "回目、得点: " + score + "）" — クリックカウンターの文字列連結と同じ仕組みを、変数3つ分に拡張しただけ
  • 保存して Simple Browser を更新。何度もクリックして、6 が出たときだけ得点が増えることを確認
  • 確認ポイント:
    • tries・score はどちらも handleRoll の外側で宣言——クリックカウンターと同じ理由（関数の中で宣言すると毎回リセットされてしまう）
    • if (result === 6) は第7回で書いた条件分岐そのもの——DOM操作の中でも普通に使える
    • 「関数（rollDice）」「条件分岐（if）」「DOM操作（textContent）」「イベント（addEventListener）」——第6〜11回の要素が1つの画面に全部つながった
