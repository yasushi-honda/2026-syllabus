デバッグ集中回（AIなしで直す）

Week 13 火曜 1・2限
テーマ
第12回で NOTES.md に書いた「直したいことリスト」を教材に、今日はAI（GitHub Copilot）を使わずに自力でバグを直す。これまでのバグ修正ワーク①〜③はAIが生成したバグ入りコードを読み解く練習だったが、今日は自分の3作品に残る"生きたバグ"を、仮説を立てる→console.logで確かめる→直すというサイクルで自分の力だけで直す
キーワード
エラーメッセージを読む / 仮説→検証→修正 / console.logでの原因特定 / AIなしで直す / 修正記録
必要な準備
第4・8・12回で公開済みの3作品（プロフィールサイト・小ゲーム・クリックゲーム）・第12回のNOTES.md「直したいことリスト」・Codespaces が起動できる状態

この回のゴール

  • エラーメッセージを読み、「どこで」「何が」起きているかを自分の言葉で言える
  • AIに頼らず、自分で原因を推測して修正を試せる
  • console.log で値を確認しながら、原因を絞り込める
  • 直せたバグ・直せなかったバグの両方を NOTES.md に記録できる
  • エラーは怖いものではなく手がかりだと感じられる

大事な前提（毎回投影しておく）

今日はAIを使わない宣言: GitHub Copilot の自動補完・チャットをオフにする——これまでのバグ修正ワーク①〜③（AIにバグ入りコードを書かせて直す練習）とは逆に、今日はAIにコードを書かせない。検索して MDN 等のリファレンスを読むのは OK。目的は「AIに頼らなくても自分で直せる」という自信と、エラーメッセージを読む基礎力を育てることにある。

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

今日のルールを知る → エラーメッセージの読み方を学ぶ

今日のルールを共有する（10分）

  • 講師から、今日はCopilotをオフにして自力で直す集中回であることを共有。第10回までのバグ修正ワークとの違い（AIが作ったバグ→自分の本物のバグ）を確認

「直したいことリスト」を見直す（10分）

  • Codespaces で NOTES.md を開き直し、第12回に書いた「直したいことリスト」とクラスメイトからのフィードバックを読み返す
  • 今日直す候補を3つ選ぶ（簡単そうなもの→難しそうなものの順に並べる）

エラーメッセージの読み方（20分）

  • python3 -m http.server 8000 → 第1回と同じ手順で Simple Browser を開く
  • ブラウザの開発者ツール（コンソール）を開き、エラーメッセージの構成（赤字のメッセージ・ファイル名・行番号）を確認する
  • わざと存在しない変数を呼ぶなど簡単なミスを書いてエラーを1つ出し、読み方を練習する
1限 後半 約50分

1つ目のバグを自力で直す

仮説を立てる（15分）

  • 選んだバグについて「たぶんここが原因では」という仮説を NOTES.md に1行書いてから着手する（第10回までの「読み解く」練習の応用）

console.log で確かめる（20分）

  • 怪しい箇所の前後に console.log(...) を挟み、実際の値を確認しながら仮説が合っているか検証する

直す（15分）

  • 原因が分かったら修正。直ったら Simple Browser で動作を再確認する
休憩 10分
2限 前半 約50分

2〜3つ目のバグに挑戦する

続けて挑戦する（30分）

  • 残りのバグにも同じ手順（仮説→console.log→直す）で取り組む

詰まった時の作法（20分）

  • AIに答えを聞く代わりに、「今どこで、何が分からないか」を NOTES.md に言語化してから、講師またはクラスメイトに相談する
  • 人に説明しようとするだけで気づくこともある——声に出して自分のコードを説明してみる
2限 後半 約30分

修正記録をまとめる

修正記録を書く（20分）

  • NOTES.md に「デバッグ集中回の記録」という見出しを作り、直したバグは原因と直し方を、直せなかったバグは今分かっていることを書く

3作品の最終チェック（10分）

  • 3つの公開URLを開き直し、直した修正が本番（GitHub Pages）にも反映されているか確認する（commit & push を忘れていないか）
まとめ 約10分

次回予告と今日の振り返り

  • 次回（第14回・前期最終回）: 自由制作＆振り返り——これまで学んだ技術を自由に組み合わせて最終作品を作り、公開後は前期の学びを記録形式で振り返る（発表なし）
  • 今日のキーワード 「エラーメッセージを読む」「仮説→検証→修正」「console.logでの原因特定」「AIなしで直す」「修正記録」を口に出して言えるか確認して退出
  • 直せなかったバグは、次回はAIを使ってよいのでそこで再挑戦してもよいと伝える

課題・次回までにやること

必須
「直したいことリスト」から最低2件を自力で修正し、原因と直し方を NOTES.md に記録する

授業内で終わらなかった人は家で続けてよいが、AIを使わず自力でという条件は変えない。

必須
直せなかったバグがあれば、今分かっていることを NOTES.md に書き残す

「どこまで分かったか」「何を試したか」を記録しておくと、次回以降の再挑戦がしやすくなる。

推奨
開発者ツールのコンソールで console.warn ・console.error も試してみる

console.log との表示の違いを見比べ、使い分けを体感する。
