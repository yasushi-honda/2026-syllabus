Week 12 火曜 1・2限
テーマ
第11回でDOM操作を統合して作った click-game.html（サイコロクリックゲーム）を index.html からリンクし、GitHub Pages に公開する。第4回（プロフィールサイト）・第8回（小ゲーム）に続く3作目の公開体験。スマホ実機で動作確認し、クラスメイトからのフィードバックをもとに自己レビューを行う
キーワード
3作目の公開体験 / index.html へのリンク追加 / commit & push による自動再デプロイ / スマホ実機でのタップ動作確認 / クラスメイトへの共有とフィードバック / 3作品の自己レビュー
必要な準備
第11回で push 済みのclick-game.html（サイコロクリックゲーム、スコア機能付き）・第4回で有効化済みのGitHub Pages・Codespaces が起動できる状態・スマホ（公開URLを開くため）

この回のゴール

  • click-game.html を index.html からリンクし、自分のサイトから遊べる動線を作れる
  • commit & push で GitHub Pages に自動的に再デプロイされる流れを、3回目の実践で自分の手順として定着させる
  • 公開した click-game.html をスマホ実機で開き、タップ操作でも正しく動くことを確認できる
  • クラスメイトに自分の作品を共有し、フィードバックをもとに自己レビューができる
  • プロフィールサイト・小ゲーム・クリックゲームの3作品を振り返り、次回（デバッグ集中回）に向けて直したい点を言葉にできる

授業の流れ

2コマ連続（90分 + 90分 = 計180分）。途中休憩あり。

1限 前半 約40分

前回の宿題を確認する → 見た目を仕上げる

前回の振り返り（10分）

  • click-game.html を Codespaces で開き直す（python3 -m http.server 8000 → 第1回と同じ手順で Simple Browser）
  • 第11回の必須課題——スコア付きバージョンの pushとルールアレンジ（難易度変更・連続記録・リセットボタンのいずれか）ができているかを自分で確認。できていなかった人はここで仕上げる

「3作目」の位置づけを確認する（10分）

  • 第4回のプロフィールサイト、第8回の小ゲームに続き、今日 click-game.html を公開すると公開URLが3本になる（第8回のtip「公開URLは2つ持っている」の続き）
  • 今日のゴールは「動くものをもう1つ世界に公開する」こと——盛り込みすぎず、まず公開を最優先にする

見た目を仕上げる（20分）

  • 第3回のCSSを思い出し、ボタン・見出し・得点表示に色・余白・フォントサイズを付けてゲームらしく見せる（推奨、必須ではない）
  • 第11回のルールアレンジでリセットボタンを選ばなかった人は、時間が余ればここで追加してもよい（tries・score を 0 に戻す handleReset 関数を addEventListener で接続する、第11回参照）
1限 後半 約50分

index.html にリンクを足す → commit & push で公開する

index.html にリンクを足す（15分）

  • 第8回で game.html へのリンクを足したのと同じ手順で、index.html に1行追加する: 
    <p><a href="click-game.html">サイコロクリックゲームで遊ぶ</a></p>
  • 保存して Simple Browser で index.html を更新し、リンクが表示されることを確認 → クリックして click-game.html に正しく飛ぶか確認

commit & push で再デプロイ（15分）

  • Codespaces 左側の「ソース管理」（Source Control）タブを開く
  • 変更ファイルとして index.html（リンク追記）と click-game.html（未pushの修正があれば）が一覧に出ているはず
  • コミットメッセージ例: サイコロクリックゲームをトップページからリンク
  • 「Commit」→「Sync Changes」（または「Push」）で GitHub に反映。第4回で GitHub Pages はすでに有効化済みなので、Settings の操作は不要
  • GitHub.com のリポジトリページ →「Actions」タブで pages build and deployment ワークフローの進行状況を確認

公開URLを確認（20分）

  • 公開URL https://<ユーザー名>.github.io/<リポジトリ名>/ をブラウザの別タブで開き、追加したリンクから click-game.html に飛べるか確認
  • 直接 /click-game.html を開いて、Simple Browser と同じ動作（クリックで出た目・得点が更新される）を再現できるか確認
  • 反映待ち時間: 公式に最大10分（通常は1〜3分）。すぐ反映されない時は Mac: Cmd + Shift + R / Windows: Ctrl + Shift + R でキャッシュをクリア
休憩 10分
2限 前半 約50分

スマホ実機で確認する → クラスメイトに共有してフィードバックをもらう

スマホ実機で開く（20分）

  • 公開URLをQRコードに変換してスマホで読み取る（第5回と同じ方法）、または LINE などで自分宛に送って開く
  • ボタンをタップして、出た目・試行回数・得点が正しく更新されるか確認——addEventListener("click", ...) はスマホのタップでもクリックと同じように反応する（モバイルブラウザがタップを click イベントとして扱う標準的な挙動、参考リンクのMDN解説を参照）ことを実機で体感する
  • 第5回で書いたレスポンシブ（メディアクエリ）のスタイルが効いていれば、スマホでも崩れずに表示されるはず。崩れていた場合はスクリーンショットを撮って NOTES.md に貼っておく

クラスメイトに共有する（15分）

  • 授業内の連絡手段（Google Classroom やチャット）で、自分の公開URL（トップページ、または /click-game.html）をクラスメイトに共有
  • 共有するときは「ボタンを押すとサイコロが振られます」のような遊び方の一言を添えるとよい
  • 受け取った側は、相手のゲームを3回以上タップして動かしてみる

フィードバックをメモする（15分）

  • クラスメイトから「面白かった点」「分かりにくかった点」を1つずつでよいので聞く（口頭・チャットどちらでも）
  • NOTES.md の末尾に「公開後フィードバック」という見出しで記録: 誰の反応か（名前は伏せて「クラスメイトA」でよい）・面白かった点・改善したいと思った点
2限 後半 約30分

3作品を並べる → 自己レビューする

3作品を並べて振り返る（15分）

  • 自分の公開URL配下の3ページ——プロフィールサイト（第4回・/）・小ゲーム（第8回・/game.html）・クリックゲーム（第12回・/click-game.html）——を順に開く
  • それぞれについて「何を学んだ回に作ったか」「今見て一番気に入っている部分」を1行ずつ NOTES.md に書く

次回に向けて直したい点をリストアップする（15分）

  • 3作品の中で気になるバグ・直したい見た目・動きが変な箇所を思いつく限りリストアップし、NOTES.md の「直したいことリスト」にまとめる
  • クラスメイトからのフィードバックで挙がった「分かりにくかった点」もこのリストに合流させる
  • このリストが第13回（デバッグ集中回）でそのまま使う教材になる
まとめ 約10分

次回予告と今日の振り返り

  • 次回（第13回）: デバッグ集中回（AIなしで直す）——エラーメッセージを読む練習。あえてAI（Copilot）を使わずに自力でバグを修正する体験。今日作った「直したいことリスト」がそのまま教材になる
  • 今日のキーワード 「3作目の公開体験」「index.htmlへのリンク追加」「commit & pushで自動再デプロイ」「スマホでのタップ動作確認」「自己レビュー」を口に出して言えるか確認して退出
  • 家では自分の3つの公開URLを家族・友人に見せて、率直な感想をもう1つもらっておくと次回の教材が増える

課題・次回までにやること

必須
click-game.html を index.html からリンクして公開する

授業内で公開が間に合わなかった人は家で完成させ、必ずスマホでも動作確認してから push する。

必須
NOTES.md に「公開後フィードバック」と「3作品の自己レビュー」を書く

クラスメイトから聞いた反応を最低1件、3作品を見直して気づいた「直したいことリスト」を最低3件、それぞれ記録する。直すかどうかは第13回・第14回で判断してよい。

推奨
見た目やルールをもう1つ改善する

「直したいことリスト」から1つ選んで先に直してみる。次回のデバッグ集中回ではあえてAIを使わずに直す体験をするので、簡単なものは今のうちに片付けておくと次回に集中しやすい。
