if 文の基本構文を手で書く → 真偽値の感覚をつかむ

前回の振り返り（10分）

  • 第6回で作ったおみくじページを Codespaces で開き直す（ターミナルで python3 -m http.server 8000 → 第1回と同じ手順で Simple Browser）
  • 更新ボタンを何度か押して、配列からランダムに選ばれる動きを思い出す
  • ただし今のおみくじは 「どんな結果でも同じ動き」——「大吉だったらお祝い、凶だったら励まし」のように結果ごとに違う処理はできない。今日はそれを可能にする

はじめての if 文（15分）

  • <script> ブロックの中に、新しい行を追加して試す: 
    const score = 80;

if (score >= 60) {
  console.log("合格です");
}
  • if (条件) { 処理 } という形——カッコの中が true なら、波カッコの中身が実行される
  • 保存 → Simple Browser を更新 → Console を確認:
    • "合格です" が表示されたら成功
    • score を 40 に変えてもう一度 → 今度は何も表示されない（条件が false なので中身がスキップされる）
  • これが「判断して、必要な時だけ動く」プログラムの第一歩——MDN「コードでの意思決定 — 条件文」でも最初に出てくる構文

真偽値（true / false）を Console で観察（15分）

  • 第6回で「真偽値（Boolean）」という型の名前は出たが、実際にどんなときに true / false になるかを、いま Console で確かめる: 
    console.log(80 >= 60);   // true
console.log(40 >= 60);   // false
console.log(80 === 80);  // true
console.log(80 === "80"); // false  ← 型が違うと false
console.log("はい" === "はい"); // true
  • 比較演算子の一覧（MDN「式と演算子」より、よく使うもの）:
    • === 等しい（型もチェック）／ !== 等しくない
    • < 小さい／ > 大きい／ <= 以下／ >= 以上
  • if のカッコの中身は、必ず最終的に true か false になる式を書く——これが今日いちばん大事なルール
「= と == と === は別物」: = は「箱に値を入れる」（代入）、=== は「2 つを比べる」（厳密な等価比較）。MDN の ==（等価演算子）の解説では「型変換を試みる」と明記されており、思わぬ落とし穴が生まれます。一方 ===（厳密な等価演算子）は「型変換を一切試みない」ので事故が少ない——今日からは === と !== を使うと覚える。バグ修正ワーク②でもこの取り違えが頻出します。
1限 後半 約50分

else if / else と論理演算子で3分岐を組む

else で「それ以外」を書く（10分）

  • さっきの if は「合格のときだけ表示」だった。今度は「合格 / 不合格」を両方表示する: 
    const score = 40;

if (score >= 60) {
  console.log("合格です");
} else {
  console.log("もう少し！");
}
  • score を 80 と 40 で交互に切り替えて Console の出力が変わることを確認
  • 「もしAなら○○、そうじゃなければ△△」を 1 セットで書けるのが if / else——日本語の構造とほぼ同じ

else if で「3 段階以上」を書く（15分）

  • 合格・条件付き合格・不合格の 3 段階に振り分けたい: 
    const score = 75;

if (score >= 80) {
  console.log("優秀");
} else if (score >= 60) {
  console.log("合格");
} else {
  console.log("もう少し！");
}
  • 上から順番にチェックして、最初に true になった枝だけが実行される
  • そのため if の条件は厳しいほうから順番に書くのがコツ。score >= 60 を score >= 80 より先に書くと、80 点でも「合格」止まりになってしまう（バグ修正ワーク②の予習）
  • score を 85 / 70 / 50 と変えて、それぞれの枝が動くことを確認

論理演算子で複数条件を組み合わせる（15分）

  • 「A かつ B」「A または B」を書きたいときは論理演算子を使う: 
    const age      = 17;
const hasTicket = true;

// A かつ B（両方 true のときだけ true）
if (age >= 13 && hasTicket === true) {
  console.log("入場できます");
}

// A または B（どちらか一つでも true なら true）
if (age < 13 || hasTicket === false) {
  console.log("受付に来てください");
}
  • &&: かつ（and）／ ||: または（or）
  • 真偽値そのものを比較に使うときは === true を省略して if (hasTicket) とも書けるが、最初は明示的に書く方が読みやすい

診断ゲームの設計を考える（10分）

  • 2限前半で完成させる「気分スコア診断」の設計を立てる:
    • 入力: mood という数値（0〜10）
    • 分岐: 9以上 → 「絶好調！」／ 6以上 → 「いい感じ」／ 3以上 → 「ぼちぼち」／ それ以下 → 「お疲れさま」
    • 出力: 第6回と同じく id="result" の要素に textContent で表示
  • このように「入力 → 分岐 → 出力」と分けて設計図を頭に描いてから書くと、コードを書く順番が決まる

2限 前半 約50分

気分スコア診断を手で完成させ、ページに表示する

HTML 側を整える（10分）

  • 第6回のおみくじページに、新しいセクションを追加（おみくじは残したまま）: 
    <h2>気分スコア診断</h2>
<p>今日の気分を 0〜10 の数値で mood 変数に書いて更新してください</p>
<p id="result">ここに診断結果が出ます</p>
  • この時点で Simple Browser を更新して、見出しと段落が表示されることだけ確認

JavaScript 側を手で書く（25分）

  • おみくじの <script> ブロックの後ろに、新しいブロックを追加してもよいし、同じブロックの下に書き足してもよい: 
    // 気分スコア診断
const mood = 7;  // 0〜10 で気分を表す数値

let message;

if (mood >= 9) {
  message = "絶好調！その勢いを大切に";
} else if (mood >= 6) {
  message = "いい感じ。今日もがんばろう";
} else if (mood >= 3) {
  message = "ぼちぼち。無理せずいこう";
} else {
  message = "お疲れさま。今日はゆっくり休もう";
}

console.log(message);
document.getElementById("result").textContent = message;
  • ポイント:
    • message は最初は中身を入れずに let で宣言し、各 if の枝で代入する——「あとから値が決まる箱」
    • 条件は厳しい順（>= 9 → >= 6 → >= 3）に書く。順番を逆にすると常に >= 3 の枝に落ちる
    • すべての枝に message = "..." を書くのを忘れない——書き忘れた枝に入ると message が undefined のまま表示される
  • 保存 → Simple Browser を更新 → 結果が表示されたら成功
  • mood の値を 10 / 7 / 4 / 1 と変えて、毎回違う結果が出ることを確認

論理演算子で 1 段階「条件付き」を足してみる（15分）

  • たとえば「気分が低い (mood < 3) かつ 平日（isWeekday === true）のときだけ別メッセージを返す」を組み込んでみる: 
    const mood      = 2;
const isWeekday = true;

let message;

if (mood < 3 && isWeekday === true) {
  message = "平日のお疲れさま。早めに切り上げて";
} else if (mood >= 9) {
  message = "絶好調！その勢いを大切に";
} else if (mood >= 6) {
  message = "いい感じ。今日もがんばろう";
} else if (mood >= 3) {
  message = "ぼちぼち。無理せずいこう";
} else {
  message = "お疲れさま。今日はゆっくり休もう";
}
  • より厳しい条件（&& で AND を取った条件）は前に持ってくると、欲しい枝に正しく落ちる
  • 余裕があれば isWeekday の値を切り替えて、結果が変わることを観察

バグ入りコードを生成させる（10分）

  • 新規ファイル bugfix02.html を作り、第1回と同じ最小 HTML テンプレに <script> ブロックだけ用意
  • AI に以下のように依頼: 
    JavaScript の初心者向けに、わざとバグが 3 つ入った if 文のコードを書いてください。
お題は「年齢で入場区分を判定するプログラム」。
12 歳未満は「子ども」、12 歳以上 18 歳未満は「学生」、18 歳以上は「大人」と返す。
バグの種類は次の中から 3 つ選んで混ぜてください：
- 代入と等価比較の取り違え（= と ===）
- 条件を厳しい順に書いていない
- 比較演算子の向きが逆（< と >）
- else if の書き間違い
バグの場所は教えないでください。私が自分で見つけて直します。
  • AI が出したコードを bugfix02.html の <script> 内に貼り付ける

自分で読み解いて直す（15分）

  • まず動かしてみる（Simple Browser で表示 → Console 確認）。エラーメッセージが出る場合と、エラーは出ないけど結果がおかしい場合がある
  • 確認のしかた:
    • age を 5 / 15 / 30 の 3 通りで試して、それぞれ「子ども」「学生」「大人」が返るか
    • 返らない場合、どの値で何が返ったかを NOTES.md に記録（バグの再現条件）
  • 1 つずつ直して、その都度動かし直す——一気に全部直さないのがコツ。直したつもりが別のバグを生む
  • 「ここを直した理由」を NOTES.md に 1〜2 行ずつメモ。AI に質問して答え合わせするのは自分で全部直し終わったあと
「動かなかったらまず Console」: 真っ白な画面が出たり、結果が表示されない時は、必ず F12 → Console タブを開く。赤い行があれば、その1 行目をそのままコピーして読むのが第一歩。MDN「よくある JavaScript の問題の解決」にも代表的なエラーメッセージの読み方が載っています。
