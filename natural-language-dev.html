自然言語開発

新設科目 木曜 1・2限 IT・情報処理専攻(システム) 3年次

担当教員

本田 康志

非常勤講師 / ヤススシステム代表

「3年次のみなさん、ようこそ。この授業では、2026年現在の最前線——自然言語でソフトウェアを開発する技術を学びます。プロンプトエンジニアリングを超えた『コンテキストエンジニアリング』、AIエージェントを制御する『ハーネスエンジニアリング』、そして仕様を起点にした『Spec-Driven Development（SDD）』。これらは、AIと協働する開発者に求められる新しい専門スキルです。同時に大切にしたいのが 『責任あるコード』 という考え方。AIが高速にコードを生成できる時代だからこそ、何を作るか・なぜ作るか・どう検証するかを自分で判断できる開発者が求められています。まずは進級制作のレビューから始めましょう。みなさんの作品を一緒に振り返り、そこから新しい開発手法の旅を始めます。」

授業概要

  • GitHub Codespaces × Gemini CLI による完全クラウドベースの開発環境で、自然言語による本格的なソフトウェア開発手法を学ぶ、実践中心の専門科目です。ブラウザだけで受講でき、ローカルPCへのインストールは一切不要です。
  • 個人の Google アカウントだけで Gemini CLI の無料枠（60 リクエスト/分・1,000 リクエスト/日、Gemini 3 モデル、1M トークンのコンテキスト）を使って学習を始めます。第8回以降の Antigravity CLI 無料枠条件は Antigravity 公式を執筆時点で確認のうえ進めます。追加課金は不要です。
  • 「Vibe Coding（直感的AI開発）」から始まり、Spec-Driven Development（SDD：仕様駆動開発）へと段階的にレベルアップ。プロトタイプ段階ではAIと自由に対話しながら素早く形にし、プロダクション段階では仕様書を起点に品質を担保する——この使い分けを体得します。
  • AI CLI の主要機能（GEMINI.md（プロジェクト別コンテキスト）、Plan mode、MCP（Model Context Protocol）、Hook（agent のツール実行に割り込む仕組み・Antigravity CLI では plugin 内 hooks.json で定義）、Agent Skills、サンドボックス、カスタムコマンド）を触りながら、AI エージェントの仕組みと制御方法を学びます。※ 本科目は CLI 移行期にあり、Hook 周辺の詳細実装は概念紹介＋発展課題として扱います。
  • コンテキストエンジニアリング（プロンプトを超えた全体的な情報設計）、ハーネスエンジニアリング（テスト・lint・レビューによるAI出力の制御基盤）など、2026年現在のAI開発の最前線を学びます。
  • 前年度（2年次）の進級制作を通年の素材として振り返り、自分が当時書いたコードに新しい技術を積み上げていきます。学期末には「4月の自分のコード」と「前期末のコード」を比較でき、自分自身の成長が可視化されます。
  • 「責任あるコード」を貫くテーマとし、AIが生成するコードに対する検証・品質管理・倫理的判断の重要性を学びます。
  • PRD（製品要求仕様書）、ADR（アーキテクチャ決定記録）、TDD（テスト駆動開発）など、ソフトウェアエンジニアリングの基礎的なセオリーも実践の中で身につけます。
  • ※ 2026-05-19 Google I/O 2026 で発表された通り、Gemini CLI は Antigravity CLI（コマンド agy）に引き継がれ、個人ユーザー向けの Gemini CLI は 2026-06-18 で停止します。本授業では第7回までの内容は当初設計通り Gemini CLIで進めますが、第8回以降は Antigravity CLI（agy）に切り替え、移行体験そのものを教材に組み込みます（詳細は 第8回ページ参照）。GEMINI.md や .geminiignore 等の主要な周辺ファイルは引き続き互換維持される設計です。※ 6/18 以降に第3〜7回を実施する場合は gemini を agy に読み替えて進めます（サブコマンド・スラッシュコマンドは大半が互換）。一次出典: Google Developers Blog / Antigravity CLI 移行ガイド。

到達目標

知識・理解

  1. プロンプトエンジニアリング、コンテキストエンジニアリング、ハーネスエンジニアリングの違いと関係を説明できる。
  2. Spec-Driven Development（SDD）の概念と、TDD・PRD・ADRとの関係を理解している。
  3. AIコーディングエージェント（Gemini CLI 等）の仕組みと、ガイド（GEMINI.md 等の事前制御）・センサー（自動テスト等の事後検証）の概念を説明できる。
  4. 「責任あるコード」の原則（検証可能性、説明責任、倫理的配慮）を理解している。
  5. Git/GitHub Flowを用いたチーム開発プロセス（Issue, Branch, PR, Review, Merge）を説明できる。

思考・判断

  1. Vibe Codingが適切な場面とSDDが必要な場面を判断できる。
  2. AIが生成したコードの品質・安全性・保守性を批判的に評価できる。
  3. 仕様の曖昧さや矛盾を検出し、明確化するための質問を構築できる。
  4. テスト観点（正常系・異常系・境界値）を自ら設計できる。

スキル・表現

  1. AIエージェントを活用して、仕様に基づいたWebアプリケーションを開発できる。
  2. PRD・ADRを作成し、設計判断を文書化できる。
  3. テストを先に書き、実装を後から行うTDDの基本サイクルを実践できる。
  4. GitHub Flow（Issue→Branch→PR→Review→Merge）で開発を進められる。
  5. コードレビューにおいて、建設的なフィードバックを提供できる。
  6. 自身の設計判断とAI活用プロセスをプレゼンテーションで説明できる。

関心・意欲・態度

  1. AI開発の最前線の手法に興味を持ち、自ら調査・試行する姿勢を持つ。
  2. コードの品質と責任に対する意識を持ち、「動けばいい」で終わらせない姿勢を持つ。
  3. チーム開発において、他のメンバーのコードや意見を尊重し協力できる。
  4. 技術の急速な変化に対して、継続的に学び続ける意欲を持つ。

授業計画（全16回）

週 テーマ 主な内容・活動
1オリエンテーション＆前年度の進級制作を振り返る授業の目的・進め方・評価方法。前年度（2年次）の進級制作を通年の素材として振り返りながら使うことの説明。Codespacesで自分の進級制作リポジトリを開き直し、コードを久しぶりに読み返す。Gemini CLI を npx @google/gemini-cli で起動・OAuth認証。「当時の自分は何を考えてこう書いたか」「前期末までにこれをどう育てたいか」を自分の言葉でメモ。「責任あるコード」の導入。
2コンテキストエンジニアリング入門プロンプト→コンテキストへの進化。コンテキストウィンドウの仕組み、U字型精度カーブ、情報配置の戦略。自分の進級制作を題材に「AIに自分のコードをどう説明すれば正しく理解してもらえるか」を実験。
3Gemini CLI / GitHub Copilot CLI を使い分ける2つのAI CLIをCodespacesに導入し、それぞれの動作原理を比較（Gemini CLI の AIエージェント + Built-in Tools（ファイル操作・シェル実行・Web Search・MCP など）で作業するループ、Copilot CLI の AIモデルが custom agents (Explore / Task / General-purpose / Code-review) に subagent として委譲しながら作業する仕組みと、別軸の Plan mode）。GEMINI.md と Copilot CLI の設定ファイルの違い、無料枠・モデル選択の違いを理解。自分の進級制作を題材に、どのタスクをどちらのCLIに任せるか使い分けの方針を立てる。Vibe Coding体験：自然言語だけで進級制作に小さな改善を加える。
4Vibe Codingの限界とGEMINI.mdで落ち着かせる進級制作に Vibe Coding で小さな機能を1つ追加し、Gemini CLI の出力のブレ（使用言語の混在・スタイル逸脱・関係ないファイルの変更 等）を体感。続けて GEMINI.md にプロジェクトの目的・使用言語・好みの書き方を 3〜5 行で書き、同じ依頼を再実行して Before/After を比較。「AI に毎回同じ説明をしなくて済む状態を作る」最小一歩。
5PRDとADRで「なぜそうしたか」をAIに渡す第4回 GEMINI.md の振り返りから、PRD（要求の意図）/ ADR（設計判断）へ。進級制作の小機能 1 つを題材に PRD/ADR を AI と協働で書き、GEMINI.md の @file Memory Import で AI に取り込ませる。仕上げに Plan Mode（/plan または Shift+Tab）で PRD を起点とした実装計画を立てさせ、計画 markdown を人間がレビュー。「指示／意図／判断／計画」の4階層が揃う体験。
6Spec-Driven Development入門SDDの概念：仕様が実行可能な成果物になる。SDDライフサイクル（定義→計画→分解→実行→デバッグ）。Gemini CLI の Plan mode と GitHub Copilot CLI の Plan mode を比較しながら、「実行前に計画を立てる」サイクルを体験。進級制作にSDDで新機能を追加する小演習。
7テスト駆動開発（TDD）基礎TDDの基本サイクル：Red → Green → Refactor。テスト観点の設計（正常系・異常系・境界値）。進級制作にテストを追加していく演習。AIにテストを書かせ、人間がテスト観点を検証する。
8ハーネスエンジニアリング入門（Antigravity CLI への移行を含む）進級制作リポジトリにハーネスを構築する実践。同時に、2026-05-19 Google I/O 2026 で発表された Gemini CLI → Antigravity CLI（コマンド agy）への移行（agy plugin import gemini）を体験する（個人ユーザーの Gemini CLI は 2026-06-18 に停止）。ガイド（.geminiignore、GEMINI.md、ブランチ保護等の事前制御）とセンサー（GitHub Actions によるテスト・lint・ビルド、PR レビュー等の事後検証）。Hook（plugin 内 hooks.json で定義し /hooks で確認できる第3の層）の存在を知り、家での発展に繋ぐ。
9進級制作で Map を使う：Leaflet × ジオコード × 天気 API学生リクエストを起点に、進級制作の具体機能としてマップを組み込む実装回。Leaflet + OpenStreetMap で地図を描画、Open-Meteo Geocoding API で住所→緯度経度を取得、Open-Meteo Forecast API で天気を地図ピンの popup に表示する最小機能を Antigravity CLI（agy）と協働で組み立てる。Mapbox / Google Maps Platform の判断軸（料金体系・API キー・利用規約・OSS / 商用の違い）と、AI コーディングへの効果的なプロンプトの 4 作法（完成イメージ先出し／公式 API 仕様の貼り付け／失敗ケースの再現手順／1 ステップずつ）を並行して学ぶ。第10回以降の SDD 実践プロジェクトに向けた「進級制作の具体機能を 1 回分で完成させる」型の実装回。
10SDD実践プロジェクト①：設計進級制作を素材に、より大きな機能追加のSDDプロジェクトを開始。仕様書の作成（AIと協働）。テスト計画の策定。アーキテクチャの決定とADR作成。Issue分解とGitHub Project活用。
11SDD実践プロジェクト②：実装第10回で固めた spec.md / plan.md / ADR / GitHub Project を起点に、/speckit.analyze → /speckit.implement と TDDサイクル（第7回）を組み合わせて 1 タスクずつ Green に変えていく実装回。MCP（Model Context Protocol）サーバー連携（Antigravity CLI agy の /mcp と ~/.gemini/config/mcp_config.json）で外部ツール（GitHub・Filesystem・Fetch のいずれか 1 つを講師事前検証済み構成で配布）と接続する体験。ハーネスによる品質チェック（事前制御 + 事後制御の両輪）と、GitHub Flow（Branch → Commit → PR → Review → Merge）を 1 タスク分で 1 周完走する演習を含む。
12SDD実践プロジェクト③：検証と改善テスト結果に基づく品質評価。仕様と実装の差異分析。リファクタリングと技術的負債の管理。セキュリティ観点でのコードチェック。
13責任あるAI開発進級制作で生成されたAIコードを倫理的観点で見直す。Anthropic Claude Constitution（CC0公開文書）を教材にした倫理ディスカッション。EU AI Act等の規制動向。AI生成コードの著作権・ライセンス問題。
14プロジェクト最終仕上げ①：最終調整・テスト第12回で棚卸しした技術的負債と第13回の責任あるAI開発チェックリストの先送り事項を優先度順に解消。テストカバレッジの再計測とBefore/After比較。GitHub Project・Securityタブの最終確認。
15プロジェクト最終仕上げ②：ドキュメント整備・発表準備README整備、ADRの棚卸しと振り返り、「4月の進級制作」と「前期末の進級制作」を比較する成果発表の骨子作成。
16成果発表＆総括「4月の進級制作」と「前期末の進級制作」を比較する成果発表（技術選択の根拠、AI活用プロセス、品質管理の工夫、自分の成長を含む）。前期の振り返り：「プロンプト→コンテキスト→ハーネス」の進化を実感。後期への接続。

※授業計画は、学生の理解度や興味、AI技術の進展に応じて柔軟に変更する可能性があります。

評価方法・基準

AIエージェントを効果的に活用しつつ、コードの品質と設計判断に責任を持てるかを重視します。

25%仕様・設計の品質 — PRD/ADR/仕様書の明確さ、テスト設計の網羅性、設計判断の妥当性。
25%実装・コードの品質 — コードの動作、可読性、保守性、セキュリティ配慮。テストの充実度。
20%AI活用の高度さ — コンテキスト設計の工夫、ハーネスの構築、AIへの効果的な指示、出力の検証プロセス。
15%開発プロセス — GitHub Flowの実践（Issue/PR/Review）、継続的な進捗管理、チームでの協働。
15%「責任あるコード」の実践 — AI生成コードの検証姿勢、倫理的配慮、設計判断の説明責任。

  • 体調やメンタル面で不安がある場合は、無理せず担当教員または学校の相談窓口に相談してください。
  • この授業で学ぶスキルは、現在のIT業界で急速に需要が高まっている分野です。授業外でも積極的に実践し、ポートフォリオとして活用してください。
